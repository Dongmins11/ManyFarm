# 도착 후 Teacher 순차 수확 적용 검토

> **후속 승인 반영:** 아래는 초기 검토 이력이다. 최신 사용자는 대부분을 sim에 두고 공통은 도착 후 팔 작업 연결만 추가하는 좁은 범위를 승인했다. 새 `farm_interfaces` 타입·공통 Window 실행기를 제안한 아래 안은 채택하지 않았다. 현재 구현·실행·검증 상태와 부분 실패의 Result 의미는 [Teacher 수확 실행 문서](TEACHER_HARVEST_RUNTIME_20261006.md)를 따른다. 아래의 “승인 대기/미구현”은 작성 당시 상태다.

2026-10-06. 기준 `main/1666a23bf47dc7f0e8a6f2dfafbc1d41e190f6cd`와 동적 물리 미커밋 구현.
상태: **개발 가능, 정책 CPU 로딩/추론 확인 완료. 공통 변경·부분 성과의 최종 상태 의미는 승인 대기.**
이번 검토로 실제 농장 팔 수확을 구현하거나 검증했다고 해석하지 않는다.

## 사용자 요청과 확정 범위

수확 장소에 도착·정지 → 주변 과실 물리 활성화 및 Teacher 상태 제공 → 과실별 수확 시도 →
바닥 낙하/박스 안착 등에 따른 성공·실패 Feedback → 대상 처리 후 최종 Result.

사용자 추가 선택: **현재 정차 위치에서 오른팔이 도달 가능한 빨강·노랑을 각각1회 시도한다.
실패하면 다음 과실로 넘어가고, 녹색은 제외하며 차체 추가 이동은 하지 않는다.**
물리적으로 제어를 계속할 수 없는 고장·복귀 실패·취소는 일반 과실 실패와 구분해야 한다.

이번 요청은 시뮬 과실 좌표를 Teacher에 제공하라는 명시적 지시다. 기존 정답 입력 제한의
예외를 **이번 sim Teacher 검증 경로**에 적용하며, 예찰 비전·Nav2·실물 제어에는 주입하지 않는다.
이를 실물 카메라 인식이나 Student 정책을 검증한 결과로 사용하지 않는다.

## 결론: 파일은 충분하지만 실행 어댑터가 필요하다

정책4개·정규화 상태·run.json·실행 코드·자산·환경 설정은 이미 받았다.
원본 정책 파일을 더 받아야 개발을 시작할 수 있는 상태는 아니다.
그러나 현재 농장에 좌표 하나를 보내면 팔이 바로 실행되는 ROS 서버는 없다.
`arm_sim.py`는 미구현이며 기존 수확 서버는 도착 후 SUCCESS/수확0을 반환한다.

전달 Teacher는82차원 관측과 별도의 접촉/진행 상태를 사용한다. 원본 `HarvestEnv`는
새 장면 생성과 물리 진행까지 맡으므로 기존 `run_fleet` 안에서 그대로 실행할 수 없다.
농장 World는 하나로 유지하고 다음 접점을 구현해야 한다.

| 개발 항목 | 필요한 작업 |
|---|---|
| 실제 목표·상태 공급 | prim의 지속 ID, 현재 root pose/자세/속도, 관절6축, TCP, 줄기 anchor·힘·timer, 박스 정보를 원본 순서의82차원으로 구성 |
| 좌표 변환 | 위치뿐 아니라 TCP·과실 자세·속도·anchor·인장축·박스를 같은 정책 프레임으로 변환. 매20Hz 현재 상태를 갱신 |
| 접촉·파지 판정 | 목표 과실에 대한 양손가락 contact와 힘 방향, 파지·유효 분리·보유·놓기 승인 상태 구성 |
| 정책·관절 출력 | 원본 정규화/4단계 routing,20Hz 증가 명령과 gripper 보정/관절 한도 적용. World.step은 기존 물리 루프만 호출 |
| 실제 완료 판정 | 분리만으로 성공 처리하지 않고 지정 박스 안착·낙하·놓침·미분리·시간초과를 관측 |
| 실패 후 다음 과실 | 실패 완료 ID를 보존하고 실제 팔 복귀·정지 후 다음 대상을 시작. 월드 reset·재부착·과실 삭제로 해결하지 않음 |
| 공통 수확 연결 | 도착 후 후보조회/과실별 Action, Feedback 수량, 취소·실패 부분 결과, 모든 대상 처리 후 Result |

최초에는 하나의 수확로봇/한 과실 동작을 검증한 뒤 같은 정차 위치의 여러 과실로 확장한다.
분리된 과실과 이전 적재 상태를 매 시도마다 초기화하지 않는다.

## 좌표·수확 가능 범위에서 주의할 점

정책 월드의 오른팔 장착점은 `(0.235,-0.19,0.713)m`다. 오른팔 장착 좌표와 정책
월드 좌표는 같은 것이 아니다. 변환은 다음과 같다.

`T_policy_from_world = T_policy_from_arm2 × inverse(T_world_from_arm2)`

과실 JSON은 asset root이고 파지 중심은 `root + R × [0,0,-0.006]m`다.
RGB-D 표면 좌표를 root로 간주하지 않는다. 물리를 켜면 과실이 처지거나 흔들리므로
시작 때 받은 좌표 하나를 고정해서 쓰지 않고 Teacher 제어 시각마다 현재 상태를 공급한다.

0.8m는 주변 물리 활성화 반경이며 팔 도달 인증 범위가 아니다. 원본 근거리 평가의
18개 후보, HOME TCP에서9~18cm 거리, 작업영역을 참고해 후보를 선별하되, 단순 범위
통과를 IK·접근·복귀 경로의 충돌 없음으로 간주하지 않는다. 현재 audit 작업상자 안에
있는 과실 모두를 Teacher로 수확할 수 있다는 근거도 없다.

현재 planner 기하에288개 정답 root를 **오프라인 분석용으로만** 넣어 만든174개 정지
후보에서는 작업상자에288개가 배정되지만, 위 연속 근거리 조건을 통과한 고유 root는53개
(빨강18·노랑20·녹색15)였다. 실제 센서 기반 Window/실제 Nav2 정지/성공 가능 개수가 아니다.
이 결과는 “수확 작업상자에 포함”과 “현재 Teacher의 검증 조건에 가까움”의 차이를 보여준다.
범위를 통과한53개도 전달18개 이산 후보와 정확히 일치하지 않으므로 성공을 보장하지 않는다.

반면 팔과 박스의 기본 기하는 이식 가능한 것으로 확인했다. 전달 legacy URDF와 농장
mobile URDF는 HOME+bank8자세,9개 팔/박스 link 비교에서 강체 좌표 변환 후 최대 행렬오차
`2.22e-16`이다. 실제 농장 로봇 USD의8개 link 정적 FK 오차도 `5.96e-7` 이하다.
박스 벽 내부XY는 Teacher 판정영역과 일치하고, 바닥 표면5mm 차이는 원본 바닥10mm 허용값
안에 있다. 이는 기하 확인이며 실제 접촉·적재 시험을 대체하지 않는다.

농장의 위치·회전·색·ID를 그대로 보존한 정적 분석에서 원본 평가와 다른 배치가
확인됐다. root 최소 간격은 약132.77mm이며18cm 미만 이웃34쌍/고유66개다.
전달 single/pair 평가는 identity root 자세·18cm 이상 이격이다. 농장 과실 local Z의
수직 대비 기울기는 중앙 약23.76°, 최대41.17°다. 이는 초기 배치 비교이며 Teacher의
가로파지 오차25°와 같은 판정이 아니고, 학습이 이 자세를 전혀 다루지 않았다는 뜻도 아니다.

원본 `selected_teacher_observation()`은 다른 과실 슬롯을0으로 만들어 선택 목표만
정책에 제공한다. 주변 과실은 실제 충돌에는 존재하지만 정책이 주변 장애물을
인식한다고 볼 수 없다. 초기 단일 대상과 이웃 접촉을 별도로 검증해야 한다.

## 성공·실패와 종료 제안

- **시도 성공:** 실제 줄기 분리, 집게 해제, collider 전체가 지정 박스 내부에 포함되고 속도 조건을 만족한 채0.6초 유지. 원본의 박스 경계/바닥 허용 오차를 좌표 검증 후 사용한다.
- **시도 실패:** 바닥/박스 밖 낙하·놓침, 분리 실패·시간초과 등. 바닥은 농장의 실제 바닥 기하/접촉으로 판정하며 원본의 정책 월드 `z<0.48`을 그대로 월드 높이에 적용하지 않는다.
- **기록 분리:** 원본 RL의 유효 파지·분리·보유 성공 조건은 단계 제어에 유지한다. 정책 상태와 실제 최종 도착지 결과는 각각 남기고 사용자 Feedback은 실제 안착 성과를 사용한다.
- **일반 실패 후 진행:** 해당 과실을 이번 작업에서 완료된 실패로 표시하고 물리 상태를 보존한다. 팔이 다음 목표를 받을 수 있는 자세/정지 상태가 확인되면 다음 대상에 진행한다.
- **작업 중단:** 취소, 제어/관측 상실, 심한 충돌·복귀 실패처럼 다음 시도가 성립하지 않는 경우 새 목표를 보내지 않는다. 이미 확정된 수량을 Result에 보존한다.
- **대상 소진:** 시작 시 최신 후보목록을 확정해 각각1회 처리한다. 후보 수는 expected_count와 다를 수 있고 차이를 가짜 성공/실패 수량으로 채우지 않는다. 정상 빈 목록과 관측 불가를 구분한다.

권장 부분 성과 의미는 `SUCCESS = 확정 후보의 처리가 정상 종료됨`이다.
예:2개 성공/1개 실패 후 종료 → SUCCESS, harvested_count=2, failed_count=1.
작업 미완료 중단은 FAILED, 취소 확인은 CANCELED다. 이는 아직 사용자 확인 전 제안이다.
관제가 SUCCESS를 전량 적재로 읽으면 안 되므로 수량을 함께 해석해야 한다.

현재 전달 실행기는 첫 FAILED/TIMED_OUT에서 batch를 중단하고, 실패 후 assign_target을
거절하며, 미수집 분리 과실이 있으면 HOME 복귀도 실패한다. 이 세 부분은 요청한
“실패 후 다음 과실”과 달라 보완이 필요하다. 복귀 코드의 실제 물리25ms/계산50ms
불일치도 현재 농장 시간 루프에 맞춰 해결해야 한다.

## 공통 변경의 구체적인 승인 범위

[공통 변경 제안서와 내부 메시지 초안](proposals/HARVEST_ARM_COMMON_CONTRACT_20261006.md)을 작성했다.

- `harvest_robot`의 `node.py`, `mission.py`, `communication.py`, `contract.py` 수정 및 `window_executor.py`, `arm_client.py` 추가.
- `farm_interfaces`에 `HarvestCandidate.msg`, `GetHarvestCandidates.srv`, `PickFruit.action` 및 타입 생성/의존성 추가.
- 기존 외부 `HarvestTask.action`/`HarvestTask.msg` 필드는 유지한다. 공통 Nav2 알고리즘과 실물 설정은 바꾸지 않는다.
- 공통 Window 실행기가 대상 순서·시도·누적 수량·취소·종료를 관리한다. sim에 공통 업무 FSM 복사본을 만들지 않는다.
- sim은 후보 발견, 단일 과실 Teacher 제어, 접촉·물리 결과와 정지 ACK를 제공한다. 실물 backend가 없으면 sim으로 대체하거나 성공 처리하지 않는다.

공통 코드에는 아직 적용하지 않았다. [AGENTS.md](../../AGENTS.md)의 공통 변경 사전 확인
절차에 따라 이 대상·영향·검증안을 확인받은 후 진행한다. 사용자가 확정한 sim 정답 입력과
빨강/노랑1회 기준을 다시 승인받으려는 것이 아니다.

## 직접 확인한 것과 다음 검증

이번 직접 확인:

- 정책4개와 각 run.json SHA256 일치.
- 현재 `torch2.7.0+cu128 / rsl-rl-lib3.1.2 / isaaclab0.54.2`에서 공식 ActorCritic 구조로 strict load.
- 정규화 상태를 포함한 각 정책의 합성82차원 입력5개에 대해 유한한6차원 출력·결정적 추론 확인. **물리 수확 성공 시험이 아니다.**
- 전달 실행·관측·제어·판정 코드와 현재 공통 Action/농장 물리 접점 대조.
- 농장 USD·URDF FK·기존 planner 기하의 정적 좌표/간격 대조. 실행 중 실제 Nav2 도착 검증과 구분한다.
- 제안 메시지/Service/Action3종을 ROS Jazzy rosidl parser로 문법 검사했다. 실제 타입 등록·빌드·통신 시험은 아직 아니다.

원본 근거: `sim/runs/robotarm/policy_integration_review_20261006/`의
`checkpoint_inspection.json`, `policy_inference.json`, `geometry_analysis.json` 및 검사 스크립트.
받은 과거9g 성적은3/6이며 이번 PC 농장 성적으로 바꾸어 말하지 않는다.

승인 후 검증 순서:

1. 독립9g 기준 평가 재현 및 원본과 관측·action·판정 수치 대조.
2. 농장 단일 과실: 실제 파지/분리/안착, root↔파지점/정책 프레임·박스 기하 확인.
3. 복수 과실: 성공→성공, 바닥 실패→다음 시도, 미분리·시간초과·복귀 실패, 상태 reset 없음.
4. 공통 Service/Action: 과실별 Feedback·최종 수량·빈 후보·거절·중복/늦은 응답·취소·정지 미확인.
5. 실제 도착 후 실행과 예찰 동시 주행,60/480Hz 전환의 Nav2 추종·도착 오차. 이전 개방루프 약2.6cm 차이는 해결 완료로 보지 않는다.

## 로봇팔 담당자에게 확인하면 도움이 되는 항목

추가 정책/소스 수령은 필수 선행조건이 아니다. 아래가 별도로 있다면 이식과 실패 복구를
줄일 수 있으므로 제공을 요청할 수 있다. 이 문구를 실제로 전송한 것은 아니다.

> 전달된 정책4개와 실행 소스는 확인했고, 농장 도착 후 지정 과실을 순차 수확하도록 연결하려고 합니다.
> (1) 후보18개 밖 연속 좌표와 기울어진 과실 자세에 대해 확인된 허용 범위/성공 로그,
