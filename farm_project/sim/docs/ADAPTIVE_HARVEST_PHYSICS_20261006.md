# 수확 활동에 따른 물리 주기·과실 활성화

2026-10-06 / 기준 `main/1666a23bf47dc7f0e8a6f2dfafbc1d41e190f6cd` 이후 미커밋 변경.
사용자 승인: “물리주기도 동적으로 바꾸고 … 수확중 수확로봇 인근에있는 과실만 적용”.
공통 로봇 업무·메시지·실물 설정은 수정하지 않았다.

## 1. 같은 장면에서 여러 로봇이 움직일 때

현재 농장은 하나의 PhysicsScene을 공유한다. 수확로봇만 480Hz, 같은 장면의
예찰·운송로봇만 60Hz로 독립 적분하는 구조는 아니다. 장면 물리 주기는 모든
수확 활동을 모아서 결정하고, 다른 로봇의 시간과 제어·센서 주기는 유지한다.

| 상태 | 장면 물리 | 과실 처리 |
|---|---:|---|
| 수확 활동 없음 | 60Hz | 붙어 있는 과실 고정, 줄기 계산 생략 |
| 하나 이상의 로봇이 팔 작업 중 | 480Hz | 각 오른팔 장착점 주변 영역의 합집합만 활성화 |
| 작업 종료, 아직 움직이거나 분리 판정 중인 부착 과실 | 480Hz | 정지할 때까지 활성 상태 유지 |
| 분리된 과실 낙하·충돌 중 | 480Hz | 위치와 관계없이 동적 물리 유지 |
| 분리된 과실이 충분히 정지 | 60Hz | 동적 상태 보존, PhysX sleep 허용; 다시 움직이면 480Hz |

한 로봇의 작업이 끝나도 다른 로봇의 활동을 끄지 않는다. 여러 활동이 같은
과실을 포함해도 한 번만 계산한다. 전역 주기는 프레임 경계에서 전환하며,
`world.reset()`이나 시간 초기화·로봇 pose 재설정을 하지 않는다.

외부 루프는 시뮬 시간 기준 60Hz다. 한 프레임에서 물리를 1회(60Hz) 또는
8회(480Hz) 진행한 다음 한 번 렌더한다. 줄기 외력은 매 물리 tick 전에 계산한다.
`/clock` 60Hz, 상태 30Hz, 라이다 10Hz, RGB-D 15Hz는 물리 tick 수와 분리했다.
명령 목표는 내부 tick 동안 유지하고 odom은 실제 경과한 시뮬 초로 계산한다.
향후 Teacher 정책 20Hz도 이 시뮬 시간을 기준으로 연결해야 하며, 아직 정책은 실행하지 않는다.

이는 주기 변경 때문에 로봇이 8배 빨라지거나 시간이 역행하는 문제를 방지한다.
접촉·바퀴 미끄러짐 등의 수치 결과까지 완전히 동일하다는 뜻은 아니다.
또한 고주기 동안 다른 로봇의 물리 계산 비용도 늘어난다. 여러 시험 세트가 서로
독립적인 물리 주기를 가져야 한다면 별도 Isaac 프로세스/인스턴스로 나눠야 한다.
현재 운송로봇 및 여러 수확로봇 실기 구성을 새로 구현한 것은 아니다.

## 2. 설정과 과실 보존

설정: `sim/ros_ws/src/farm_sim_config/config/robotarm_physics.json`의 `adaptive`.

- `enabled: true`, `idle_hz: 60`, `harvest_hz: 480`.
- 실제 오른팔 `arm_2_base_link`의 월드 위치에서 3차원 거리 `activation_radius_m: 0.8` 이내 과실 활성화.
- 이미 활성화된 과실은 `retention_radius_m: 1.0`까지 유지해 경계에서 반복 전환을 줄인다.
- 분리 과실의 선속도 `0.01m/s`, 각속도 `0.1rad/s` 이하가 시뮬 `0.6초` 지속되면 저주기로 복귀한다.
- 붙어 있는 과실을 고정할 때도 속도 `0.01m/s`·`0.1rad/s`를 넘거나 분리 타이머가 진행 중이면 유예한다. 이 고정 보호값은 어댑터 상수이며, 위 분리 과실의 정지 설정과 별개다.

9g·크기·접촉·줄기 계수·힘/변위/40ms 분리 조건은 이전 적용을 유지한다.
비활성 과실은 kinematic으로 고정하며 충돌체는 남는다. “물리 API와 충돌을 모두
제거”하는 방식은 아니다. 매 tick의 줄기/pose 조회는 작은 활성 view에 한정한다.
고정 시 현재 pose를 유지하고, 다시 켜도 최초 앵커·기준 자세·분리 상태를 바꾸지 않는다.
PhysX의 kinematic+CCD 비호환을 피하도록 고정 중 body CCD를 끄고 활성화 때 원래 값을 복원한다.
scene CCD 설정은 기존 그대로다. 변경은 세션 레이어에만 적용하며 원본 USD는 저장하지 않는다.

분리 과실은 영역 밖이어도 고정하지 않는다. 바구니 적재 성공 판정과 바구니에
대한 상대 고정은 후속 과제다. 현재는 정지 후 저주기/자연 sleep을 사용하므로,
바구니가 이동해 과실도 움직이면 다시 고주기가 필요할 수 있다. 물리 분리를 수확 성공으로 보내지 않는다.

프로파일 최상위와 장치의 `physics_hz: 480`은 초기화·기준 물리 주기다.
초기 reset은 이를 유지하고 실제 운용 주기는 `adaptive`가 정한다.
480Hz는 전달 9g 환경을 보존하기 위한 수확 중 기본값이며, 낮은 주기에서
학습 정책 성공률을 비교한 결과가 아니다. 허용 주기는 60/120/240/480Hz지만
수확 주기를 낮추기 전 파지·분리·적재 성능을 별도로 시험해야 한다.

## 3. 팔 작업 시작/종료 입력

현재 공통 수확 서버는 이동 완료 후 수확 0개를 반환하며 실제 팔 동작이 없다.
따라서 Window 도착이나 Action SUCCESS를 팔 작업으로 간주하지 않는다.
이번에 실제 팔 제어기가 연결할 다음 시뮬 전용 입력을 준비했다.

- Isaac 내부: `HarvestPhysics.set_activity(robot_id, True/False)`.
- ROS fleet: 로봇 namespace의 `sim/harvest_activity`, 형식 `std_msgs/msg/Bool`.
- `harvest.json`의 `runtime.harvest_activity`가 bridge를 켜며 기본 유효기간은 벽시계 2초다.
- ROS 활동은 heartbeat로 갱신한다. false, 전송 중단 후 유효기간 만료로 종료한다. bridge가 이전 true를 자동 재전송하지 않는다.
- UDP에서는 로봇 ID·실행 세션·순번·전송시각을 검사한다. 속도 명령과 순번 검사를 분리했다.

기존 [실행 가이드](RUN_GUIDE_20261006.md)의 `harvest:=true` fleet 실행 후,
수확로봇이 과실 가까이에 있는 상태에서 다음 명령으로 활동만 확인할 수 있다.
이 명령은 팔을 움직이지 않는다. 주행 시작 station은 과실에서 멀 수 있다.

```bash
cd ~/main/farm_project
source scripts/env.sh sim
ros2 topic pub -r 10 /harvest_01/sim/harvest_activity std_msgs/msg/Bool '{data: true}'
```

위 publisher를 Ctrl+C로 종료하고 다음을 실행한다. publisher가 계속 true를
발행하는 상태에서는 false가 다시 덮일 수 있으므로 먼저 종료한다.

```bash
ros2 topic pub --once /harvest_01/sim/harvest_activity std_msgs/msg/Bool '{data: false}'
```

`sim/runs/robotarm/physics/<session>/activity.jsonl`에서 `physics_hz`,
`active_robot_ids`, `active_fruit_count/paths`를 확인한다.
`detach_events.jsonl`은 실제 물리 분리, `summary.json`은 종료 상태와 주기별 프레임 수다.
단독 예찰 runner는 수확로봇 전용 ROS 장치 채널을 실행하지 않으므로 이 수동 활동 시험은 fleet으로 한다.

## 4. 직접 실행한 검증

환경: Isaac Sim 5.1.0, RTX 4070 SUPER, CPU PhysX/NumPy, 현재 농장 USD.
원본 USD SHA256은 전후 `1d9887539611d65ec9c284a810bcd0b8015493db0158147c7188b414f95395e7`로 동일하다.

- 관련 단위·USD 검사 107개, skip 0 통과. 영역 합집합/겹침·한 로봇 종료 후 다른 활동 유지·분리 과실 재가동·시간 연속성·CCD 복원 포함.
- `farm_sim_config`, `farm_sim_devices`, `farm_sim_runtime` 3개 colcon 빌드 통과.
- 실제 GPU 자동 검사 19항목 통과: 초기 288개 고정 → 주변 3개 활성 → 고정/재활성 → 선택 과실 3N 실제 분리 → 약 0.20714m 하강 → 정지 후 60Hz. 분리 조건 누적 41.667ms, 종료 시 287개 고정+분리 과실 1개 동적 유지. 앵커/기준 자세/멀리 있는 과실 보존.
- 기존 전체288개·고정480Hz 기준 검사도 15항목/종료코드0으로 통과했다. 0.1N 유지와 3N 분리를 재검증했다.
- 실제 fleet 6초: 예찰 주행 중 60→480→60Hz, 360프레임/1,200물리 tick. 주변 과실 3개만 활성, 자연 분리 0개. `/clock` 360개, 상태 로봇별 180개, RGB-D 89프레임. 라이다 10Hz 및 카메라 시각/pose 대응 검사 통과.
- 실제 ROS Jazzy `Bool`→장치 어댑터→UDP 13항목 통과. true/false 전달, 세션/로봇/순번, 이전 true 자동 재전송 없음, telemetry 만료 후 활동 차단을 확인했다.

**동시 주행의 수치 응답 차이는 남아 있다.** 동일한 0.08m/s 개방루프 명령으로
6초 시험을 비교했다. 두 실행은 전환 전 1초까지 odom과 바퀴 위치가 동일했다.
전환 후 60Hz의 바퀴 odom 속도는 약 0.0673m/s, 480Hz 구간은 약 0.0793m/s였다.
최종 odom 이동량은 0.29516m와 0.31944m, 실제 월드 위치 차이는 약 0.02587m다.
시계/센서가 정상이라는 결과를 주행 궤적 동일성으로 확대하면 안 된다.
Nav2 폐루프 도착 오차·속도 추종 시험은 아직 하지 않았으며 이 차이를 감추기 위해
바퀴 drive나 속도 명령을 임의 보정하지 않았다.

같은 6초 시험의 측정 구간에서 고정60Hz 실시간 배율은 약 0.725,
60→480→60Hz는 약 0.483이었다. 각각 약 43.5/29.0 렌더 프레임/벽시계 초에 해당한다.
짧은 headless fleet+센서 조건이며 GUI 평균 FPS나 장시간 성능 보장이 아니다.
여러 로봇의 궤적을 엄밀히 비교하는 시험은 정책이 동작하는 최소 고정 주기를 먼저
선정해 `idle_hz`와 `harvest_hz`를 같게 두는 선택도 가능하다. 이때 영역 선택은 유지된다.
정책 미연결 상태에서 60/120/240Hz의 수확 성능이 충분하다고 결론내리지는 않는다.

로그는 `sim/runs/robotarm/adaptive_20261006/`, 주기/분리 기록은 각 결과 JSON의
`physics_log_directory`에 있다. [버전 관리 검증 요약](changes/ADAPTIVE_PHYSICS_VALIDATION_20261006.json)에
직접 실행 결과와 주행 차이를 보존했다. 최초 과실 배치가 반경 밖이었던 시험 실패는
`initial_placement_failure.*`로 보존했다. 실제 오른팔 장착점 기준으로 초기 시험
배치를 수정한 뒤 통과했으며 운영 반경이나 물성을 바꾸지 않았다. 초기 kinematic+CCD
경고는 호환 순서의 flag 전환으로 수정하고 재시험했다. 원본 USD visual 참조 경고와
Kit 종료 UI 경고는 별개이며 최종 검사 결과와 프로세스 종료코드를 확인했다.

미실행: 학습 정책 추론/적재 성공률, 실제 Nav2 전체 경로·정밀 정지, 여러 수확로봇
동시 GPU 실행, 운송로봇, 전체 예찰→관제→수확 E2E, 실물 동작. 기존 4개 GUI 성능
비교와 이번 headless 센서 시험은 조건이 달라 직접 FPS 향상 비율로 비교하지 않는다.

## 5. 재현과 되돌리기

동적 처리 검사는 자동으로 종료되는 유한 검사다. 아래 GUI에서는 시험 시작 시만
로봇을 과실 옆에 배치하고 활동/외력을 자동으로 적용한다.

```bash
cd ~/main/farm_project
~/isaac/env_isaaclab/bin/python sim/tools/check_adaptive_harvest.py \
  --gui --output sim/runs/robotarm/adaptive_20261006/manual_adaptive_check.json
```

기존 `check_harvest_physics.py --expected-fruits 288 --pull`은 전체 과실 480Hz
기준 물성 검사로 남겼다. 이 도구의 낮은 FPS를 동적 운용 경로의 성능으로 해석하지 않는다.

프로파일 `adaptive.enabled: false`는 전체 과실·고정 480Hz 기준 동작으로 복귀한다.
활동 입력은 물리 활성화에 영향이 없어진다. 전체 코드 복원 시에는 이번 sim 소스·설정과
이 문서 변경만 비교 복원하고, 기존 사용자 AGENTS/README·인수 원본·이전 변경을 보존한다.
이번 변경은 아직 커밋·푸시하지 않았다.
