# 인계 겹침 기준과 실물 도킹 허용오차 — 사용자 승인 후 적용

기준: main ea25693 + D-067~069 미커밋 통합. 실제 시험 ROS Domain13/SUBNET, CPU 물리60Hz.

## 확인한 사실

- 실물 원본 9686aca의 최종 도킹은 전방 라이다 `0.200 ± 0.005m`, 정지 확인 후 성공한다. 이 수치와 공통 판정은 변경하지 않았다.
- 사용자 승인에 따라 시뮬에는 바구니 겹침 **72% 이상**, 양의 높이 차이, 정지0.8초 유지 조건을 적용했다. USD 바구니 형상·장착은 그대로다.
- pickup3: 실제42 접근→수확 회전/벽정렬→실제41 도킹 성공. 임시42 마커 횡방향 배치 탓에 약7.8cm 측방 오차, 겹침 최대66.57%, 덮개 열기 거절.
- pickup4: 42 마커를 기존 접근 통로에 맞춤. 횡방향 오차 약2.25cm, 겹침72.058%에서 열기와 가상 배출 성공, 실제 `TRANSFER_COMPLETE` 피드백. 이후71.913%로 미세 변화하여 닫기 거절. 닫기는 배출의 재판정이 아니므로 시뮬 가상 장치만 현재 세션/정지/연결 확인으로 수정했다. 열기와 배출72% 조건은 유지한다.
- pickup5: 같은 제어값/배치 재실행. 실제41 도킹 성공, 라이다 약20.4cm로 원본 허용범위 안. 겹침 최대71.591%, 열기 시71.508%로 **열기 거절**. 따라서 닫기 수정만으로 반복 인계 성공을 보장할 수 없다.
- 승인 적용 뒤 pickup7에서 열기71.9349%→가상배출→운송이격→수확 원호복원까지 양쪽 Action SUCCESS를 확인했다. 이후 수확을 먼저 복귀시키는 시험 순서 때문에 정지 운송로봇과 간섭해 복귀105 발생. 운송을 먼저 내보내도록 시험 도구만 수정했다. 전체 보고는 HANDOFF_CYCLE_20261028.md. 수확 표본은 기존 SEC01 한 윈도우이며 실제 harvested=0이다.

## 왜 수치를 임의 변경하지 않는가

현재72%는 과거 단일 정지 자세의 근사값에 매우 가깝다. 실물은 목표거리에서 최대5mm 오차를 허용한다. 수확 바구니 구경190mm 기준, 한 방향5mm 차이는 겹침률 약2.63%p 차이에 해당한다. 따라서 실물 도킹 성공과 엄격한72% 인계 하한이 매번 동시에 성립하지 않는다. 바퀴를 일부러 과속시키거나 바구니/정지거리/공통 성공조건을 바꿔 통과시키지 않는다.

## 승인 및 적용

사용자는 2026-10-28 확인 질문에 **“거리 허용오차 반영: 하한 약69.4%”**를 선택했다. 아래 값을 시뮬 평가 설정에 적용했다. 후속 실제 pickup7 인계 성공을 확인했다.

실물 제어와 USD를 유지하고, **시뮬 인계 평가에만** 기존 도킹 거리 허용오차를 반영하는 안을 권장한다. 명목72%, 보수적인 하한 약69.4%로 기록한다. 정확한 적용값은 `0.72 - 0.005 / 0.19 = 0.6936842105263158`이다. 높이와0.8초 정지는 그대로, 실제 겹침률은 원시 로그와 보고서에 계속 남긴다.

변경 지점: `sim/ros_ws/src/farm_sim_config/config/docking/basket_alignment_evaluation.json`의 `minimum_coverage` 및 설명. 실물/공통 도킹 값과 판정, USD는 불변이다. 승인 후 평가 경계 및 가상장치 검사24개를 통과했다. 같은 실제 인계 시험을 다시 실행하며, 배출/이격/복원 모두 성공해야 다음 단계로 진행한다.

72%를 엄격한 하한으로 유지하는 선택도 가능하다. 그 경우 이미 사용자와 논의한 실물 바구니 장착 조정의 확정값을 반영하거나, 별도로 승인된 정밀 위치 보정이 필요하다. 임시 마커 변경만으로 도킹 거리 허용오차까지 없앨 수는 없다.
