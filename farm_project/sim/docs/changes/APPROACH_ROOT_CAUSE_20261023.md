# 작업구간 짧은 이동 실패 원인 조사 (2026-10-23)

## 확인 결과

실패는 베드 최초 진입이 아니라 수확 윈도우 사이 이동을 요청하기 전 `CorridorNavigator.resume_current → _plan_current → straight_plan`에서 발생했다. 아직 Nav2에 다음 이동을 보내지 않은 상태다. 주행 중 105나 팔 동작 오류가 아니다.

1. 서로 다른 관측점에서 같은 실제 과실을 별개 ID로 등록했다. 3D 거리 6.5cm 이내만 같은 ID로 연결하는 규칙에서 SEC12 F0003/F0008은9.405cm, F0004/F0007은9.580cm, SEC16 F0004/F0006은6.923cm로 연결되지 않았다.
2. 기존 창/소속을 유지하고 미할당 새 ID로 창을 추가하는 누적 플래너가 겹치는 별도 창을 생성했다. 최종 목표는 순방향 정렬됐으나 SEC12 W003→W002 간격8.981cm, SEC16 W004→W003 간격4.695cm가 됐다. ID 번호가 역순인 것은 생성 순서이며 실제 목표 진행 순서는 정상이다.
3. 이전 도착에서 허용됐던 횡오차에 대해 다음 짧은 이동은 `atan2(횡오차, 전방거리) ≤3°`를 요구한다. 횡오차 자체5cm 이내/차체yaw3° 이내/목표전방 조건은 통과하고 이 각도 조건만 실패했다. 예: 전방9cm에서는 횡오차 약4.7mm 이하만 허용한다. 이전 도착은 위치5cm를 허용하므로 조건이 양립하지 않을 수 있다.

## 중복 등록의 위치 추정/표면점 기여

동일 RGB-D 점을 촬영시각의 실제 차체 자세로 재변환했다(진단 샘플 간격0.90~0.95시뮬초 사이 보간, 촬영은 정지 상태). SEC12 두 쌍은 각각 같은 실제 과실 Pepper_0012_red/Pepper_0004_red의 AABB 안이며 재변환 후 관측 간 거리는4.061/4.115cm로6.5cm 안이다. 따라서 SEC12는 위치/방향 추정 오차가 기존 연결 실패를 유발한 구체적인 증거다.

SEC16 두 점도 같은 Pepper_0026_red의 AABB 안이지만 실제 자세 재변환 후 간격은8.579cm로 여전히6.5cm를 넘는다. 이 경우 서로 다른 시점의 표면 측정점 차이도 있어, 위치 추정 개선만으로 같은 ID 연결이 보장되지 않는다. 근접 과실/모든 영상의 완전한 물체 식별 검증은 하지 않았다. 세부 좌표는 동명 JSON에 보존했다.

## 1차와 차이

- `parallel_approach.py`, `corridor_navigation.py`는 1차/2차 동결 소스 SHA256 일치. 해당 판정 자체가 새로 생긴 것이 아니다.
- 1차 SEC12는8창, 문제 지점의 별도 중복창 없이 간격약40cm 이상으로 통과했다. 2차 SEC12 재시도2도8창으로 성공했다.
- 1차 SEC16 attempt2는 TASK003 y=−8.1636 다음 TASK004 y=−8.2772를 요청해 역방향11.36cm, `WORK_TARGET_NOT_AHEAD`로 실패했다. 이미 관련 문제가 존재했다.
- 2차 SEC16은 정렬로 역방향 요청을 제거했으나 겹치는 창 자체는 남아 짧은 전방 이동의 각도 제한에 걸렸다. 2차 재시도3은7창으로 성공했다.
- 따라서 ‘1차에는 관련 문제가 없고 2차 주행 코드 변경으로 생겼다’는 결론은 틀리다. 관측/연결 결과가 달라지고, 정렬 이후 실패 지점이 다른 검사로 바뀐 것이다.

## 조치 제안 및 범위

직접적인 정지는 공통 주행의 짧은 구간 경로/허용 조건 불일치다. 횡오차 및 차체 방향 안전 기준을 유지하면서 짧은 전방 이동을 어떻게 구성할지 먼저 명시해야 한다. 단순히3°를 크게 풀거나 가까운 목표를 성공으로 생략하면 실제 팔 작업 위치가 달라질 수 있다. 중복 ID/중첩창은 별도 예찰 품질 문제로 함께 기록하되, 예찰 개선만으로 주행 문제 해결을 선언하지 않는다. 실물에서도 같은 공통 조건과 유사한 목표/오차라면 발생 가능하며 실물 재현 완료는 아니다.
