# 전체 사이클 실패의 발생 경로와 시뮬 수정

기준: main `18d0e000d4c98e3478e0a8510d84948561fc7d5f` 및 기존 미커밋 변경. 2026-10-30 KST. 사용자 원인 규명·해결 요청에 따라 시뮬 설정/진단만 수정했다. 공통 제어, 실물 설정, 성공·실패 허용치는 변경하지 않았다. 커밋·푸시하지 않았다.

## 1. 실패를 만드는 두 조건

기존 실패 원문과 시도별 증거는 [실패 분석](FRESH_CYCLE_FAILURE_ANALYSIS_20261030.md)에 있다. 1~3차는 원호 오차에 따른 Nav2 106, 4차는 회전 완료 후 재진입 각도 1.0543°가 1°를 초과, 5차는 원호 끝점 정지 중 위치 오차였다.

### 지도는 정상인데 수신이 끊겼다고 판단하는 이유

`harvest_robot/handoff_runtime.py`는 costmap의 ROS 시각 나이와 실제 수신 후 경과 시간을 각각 감시한다. 실패 로그는 ROS 나이가 유효한데 실제 수신 간격이 0.5초를 넘은 경우였다. costmap 발행은 시뮬 시계 기준 5Hz여서, 시뮬 1초에 실제 약 5초가 걸리면 실제 발행 간격이 약 1초가 된다. 이때 안전 감시가 정지 명령을 내린다.

실행 중인 6차의 인계 costmap에 발행 주기만 변경해 각 조건을 실제 20초씩 관측했다. 계산 주기는 10Hz로 유지했다.

| 발행 설정 | 수신 메시지 수 | 실제 최대 간격 | 0.5초 초과 간격 수 |
|---|---:|---:|---:|
| 5Hz | 19 | 1.101초 | 18 |
| 10Hz (첫 대조) | 39 | 0.601초 | 24 |
| 10Hz (두 번째 대조) | 40 | 0.699초 | 21 |
| 20Hz | 74 | 0.401초 | 0 |

**적용:** `sim/ros_ws/src/farm_sim_config/config/nav2_harvest.yaml`의 local_costmap 발행을 20Hz로 지정했다. 공통 watchdog 0.5초는 유지한다. 20초 관측의 개선이지 모든 부하에서 단절이 없다는 보장은 아니다. 지도의 실제 장애물 계산 주기는 늘리지 않았다.

### 정지 명령 후 원호에서 벗어나는 이유

차체와 팔은 하나의 articulation(물리 관절 묶음)이다. `teacher_arm_alignment.py`는 고정 베이스 팔 학습의 위치 반복 12회·속도 반복 4회를 이동 차체 전체에도 적용하고 있었다. 바퀴 목표가 0이 되면 추가 PI 보정은 0이고 USD 구동기의 제동에 의존한다. 이때 병진과 회전 감속이 서로 맞지 않으면, 현재 각도에 해당하는 원호상의 점과 차체 위치가 벌어진다. 공통 원호 판정은 원과의 최단거리만 확인하는 판정이 아니다.

원본 수확 모델·질량·바퀴 형상·이득을 유지하고, CPU 60Hz 물리의 독립 평면에서 후진 -0.01m/s 및 회전 +0.1rad/s를 3초 명령한 뒤 정지했다. 카메라·ROS·과실·농장 충돌은 없는 축소 대조이며 실패 궤적 전체 재생은 아니다.

| 위치 반복 / 속도 반복 | 정지 명령 후 이동 | 최대 원호 정합 오차 |
|---|---:|---:|
| 12 / 4 | 22.224mm | 28.914mm |
| 32 / 4 | 9.338mm | 14.403mm |
| **64 / 4** | **3.915mm** | **6.159mm** |
| 12 / 4 재대조 | 22.314mm | 28.429mm |

**적용:** 시뮬 `robotarm_physics.json`에서 `teacher_alignment.solver_position_iterations=64`를 선택하고 `teacher_arm_alignment.py`가 이 값을 적용하도록 했다. 미지정 기본값은 기존 12, 속도 반복은 4다. 전달 USD와 팔 학습 파일은 보존했다. 이번 조건에서는 32회도 원호 10mm 기준을 초과하므로 64회를 선택했다. 이것은 수치 수렴 개선 근거이며 실제 인계 전체 성공의 증명은 아니다.

속도 반복 4→16→32 대조는 정지 후 이동 22.309→23.943→23.027mm로 개선되지 않아 채택하지 않았다. 무조건 반복 수를 올리는 방안으로 결론 내리지 않았다.

## 2. 회전 잔차는 별도 검증이 필요하다

인계의 작은 Spin을 근사해 목표 +0.03rad, 명령 +0.03rad/s, 제어 20Hz, 관측 지연 0.1시뮬초를 적용했다. 실제 ROS Spin 액션 호출은 아니다.

- 위치 12회: 마지막 목표 오차 0.931° / 재대조 0.824°.
- 위치 64회: 0.879° / 재대조 0.879°.
- 위치 128회: 0.673° / 재대조 0.673°.

64회의 회전 잔차는 1° 이내지만 여유가 작다. 128회는 작은 양의 회전에서 더 좋았으나 원호·수확·전체 성능이 확인되지 않아 운영에 추가 적용하지 않았다. 4차의 1.0543° 실패까지 해결됐다고 단정하지 않는다. 다음 실제 복원 로그에서 정지 후 각도와 완료 시점을 확인해야 한다.

## 3. 적용 시점과 시험 보존

- 진행 중 **attempt_006은 중단하지 않았다.** 인계 costmap 발행만 라이브 20Hz 적용·확인했다. 해당 프로세스의 위치 반복은 시작 당시 12회다. 일반 주행 costmap은 다음 실행부터 새 설정을 받는다.
- 다음 자동 재시작부터 일반/인계 costmap 20Hz 및 위치 반복 64회가 적용된다. 준비용 최종 YAML 병합에서 일반/인계 모두 publish=20, update=10을 확인했다.
- `run_single_cycle.py`는 실행 직전 관련 설정과 코드의 본문·SHA256을 `selected_sim_sources.json`에 저장한다. `drive_diagnostics.py`는 articulation의 설정값도 기록한다. 재시도별 서로 다른 적용 상태를 구분한다.
- 현재 시도의 라이브 변경은 `attempt_006/live_adjustments.json`, 다음 실행 설정은 `fixes_20261030/application.json`에 기록했다.
- 태그 인계 보정 미사용, ROS Domain13/SUBNET, CPU60Hz/렌더30Hz 유지. 팔·차체가 같은 articulation이므로 팔 접촉 성능과 계산 비용은 다음 통합 실행에서 확인해야 한다.

- 실제 USD의 관절·질량·충돌·재질 및 적용값 검사 7개 통과. `fixes_20261030/usd_tests_final.log`.
- `test_harvest_transfer_sim.py`, `test_full_cycle_completion.py`: 22개 통과. runtime 패키지 재빌드 성공. 문법 및 대상 diff 검사 통과.
- 별도 Nav2 launch 검사에서 기존 `controller_output` launch configuration 누락으로 1개 실패(13개 통과). 해당 공통 launch나 fixture는 이번에 수정하지 않았다. 이 검사를 전체 통과했다고 보고하지 않는다.
- 물리 독립 진단은 결과 저장 후 SDK 종료 중 일부 실행이 대기하여 해당 진단 프로세스만 종료했다. 원본 전체 시험 프로세스는 유지했다. 마지막 128회 대조 진단은 6개 결과 저장 후 종료 대기 상태에서 정리했으며 SDK 종료 중 exit139가 기록됐다. 성공적인 SDK 종료로 계산하지 않는다. 최종 도구 소스는 `fixes_20261030/final_sources.json`에 별도 보존했다.
- 원시 근거: `sim/runs/fresh_full_cycle_20261030/fixes_20261030/`의 `costmap_live_ab.json`, `costmap_live_10_20.json`, `merged_parameters.json`, `selected_sources.json`, 빌드·진단 로그.
- 물리 표본: `sim/runs/wheel_arc_stop_20261030/`, `wheel_arc_position_20261030/`, `wheel_spin_goal_20261030/`, `wheel_spin_goal_high_20261030/`. 각 summary와 매 physics tick JSON을 함께 보존했다.

복원은 시뮬 YAML의 이번 local_costmap override 제거 및 시뮬 teacher_alignment의 위치 반복 키 제거(기본12) 후 다음 실행부터 적용한다. 기존 alpha4=.002 등 이전 수정은 보존한다. 라이브 발행을 되돌릴 경우 해당 인계 costmap publish_frequency만 5.0으로 복구한다.

남은 검증은 새 물리 설정을 읽은 전체 실행의 인계·복원 및 모든 로봇 복귀·전량 선별이다. 아직 새로운 전체 사이클 성공 결과는 없다.
