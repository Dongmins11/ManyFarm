## 확인된 통합 누락

선별장 원본 `/World/sorting_station_portable`을 비활성화하고 새 HCR 모델·위치를 적용했지만, 운송의 `map_yaml`은 여전히 `count_test_farm_map.yaml`이다. PNG는 ea25693과 byte 동일하며 이전 선별장 장애물 픽셀이 남아 있다. 모델 교체에 맞춘 AMCL 지도 갱신을 누락했다.

- 모델 교체: `sim/ros_ws/src/farm_sim_runtime/farm_sim_runtime/sorter_scene.py:70`.
- 지도 선택: `sim/ros_ws/src/farm_sim_config/config/transport_runtime.yaml:6`; attempt09 최종 runtime에서도 같은 경로.
- 실제 전방 라이다가 맞힌 신규 IntakeSupport686 전면: map Y 약13.60m.
- 그 부근 기존 지도에서 가장 가까운 장애물 중심: Y 약13.75m. X 방향 차이도 있어 근거리351개 ray 표본의 실제 hit→최근접 점유셀 거리는 평균16.17cm.
- 이는 라이다 TF의 값을 임의로 보정해서 맞출 대상이 아니라, 실제 정적 환경과 위치 추정용 지도 데이터의 불일치다.

## 오차가 커진 시점과 odom 분리

attempt09 실제 차체 진단과 RobotStatus(map→base TF 조회 결과)를 비교했다. wheel odom은 시험에 설정된 시작 위치/방향으로 map 좌표에 정렬하여 평가했다. 정답 위치를 제어기에 주입하지 않았다.

25cm가 바퀴 이동량에서 발생한 증거는 없다. 지도 기반 보정이 들어간 추정값에서 오차가 커졌다. 회전 중 관측 방향이 달라질 때 오차가 증가하고, 정지 후에도 유지된다. 단순한 최신 표본 전달 지연만으로 설명하기 어렵다.

## 결론과 남은 확인

**새 선별장과 AMCL 지도 불일치는 확인된 결함이며 이번 오차 증가의 가장 유력한 원인이다.** AMCL이 새 물체의 반사점을 예전 장애물 위치에 맞추려 하면서 로봇 위치를 잘못 보정한 것으로 해석된다. 접근 때 이미25cm 오차였던 것이 아니며, 기존 일반 주행 성능으로 치부하면 안 된다.

원시 map→odom TF, AMCL pose/covariance, 360도 scan은 당시 파일에 모두 저장되어 있지 않다. 따라서 TF 정합 전체가 정상이라고 확정하거나25cm 전부의 원인을 단정하지 않는다. 이동 중 표는 status 수신시각−0.15초에 가까운 진단 샘플과 비교한 근삿값이다. 최종 정지 오차는 시간 정렬 오차 영향이 작다. 전면 ray 비교는 동일 시뮬시각에 가장 가까운 차체 yaw를 사용했으며 미세 pitch/roll은 무시했다.

다음 조치: 새 선별장 정적 형상·배치에 맞는 점유지도를 만들고 기존 지도와 **지도만 바꾼 비교**를 수행한다. 공통 제어·성공 기준·AMCL 파라미터·초기 배치는 유지한다. 동시에 동일 측정시각의 scan/odom/map→odom TF와 평가용 실제 위치를 남겨 map 보정과 TF 시각 문제를 분리한다.
