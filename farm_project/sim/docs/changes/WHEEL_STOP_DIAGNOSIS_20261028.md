# 정지 후 추가 회전 원인 진단 — 2026-10-28

## 결론

실제 실패 로그에서는 **0 속도 명령 뒤에도 바퀴가 미세하게 더 굴렀고 그 회전량으로 차체 방향 변화가 거의 전부 설명된다.** 바퀴와 무관한 차체 미끄러짐이 주원인이라는 증거는 없다. 별도 Isaac 축소 시험에서는 감쇠 10배가 개선하지 못했으나 속도 solver 반복 4→16에서 잔류 회전이 약 59~62% 감소했다. 시뮬 구동·접촉 제약의 수치 계산이 잔류 회전에 기여한다는 증거다. 특정 타이어 접촉면, 팔 하중, solver 옵션 중 단일 원인까지 확정한 것은 아니다.

실패로 이어지는 경로는 기존 비교 결과와 같다: 벽 정렬 완료 후 제어 종료 → 0 target 아래 미세 바퀴 회전 → 나중에 수행하는 공통 인계 validator에서 0.5° 초과 → 재보정 없이 실패. 물리 잔류 움직임과 공통 완료 처리 구조를 구분해야 한다. 실물에서 동일 현상이 재현됐다는 뜻은 아니다.

## 별도 Isaac 물리 비교

도구: `sim/tools/check_wheel_stop_diagnostic.py`. 현재 농장 USD, 수확 차체·팔 이동 자세, 실제 BaseSim을 사용했다. CPU 60Hz/MBP, 렌더 30Hz. 각 조건은 reset 뒤 3초 정지 → 3초 0.03rad/s 회전 명령 → 6초 정지이며, 정지 명령 후 0.5~3초 구간을 비교한다. gain/iteration 변경은 메모리·세션에서만 이루어지고 파일에 저장하지 않는다.

| 조건 | 속도 solver 반복 | 바퀴 damping 배율 | 바퀴 기준 추가 회전 | 실제 차체 추가 회전 |
|---|---:|---:|---:|---:|
| 기준 | 4 | 1 | −0.08319° | −0.08303° |
| 감쇠 증가 | 4 | 10 | −0.08817° | −0.08975° |

- 감쇠 증가를 해결책으로 채택할 근거가 없다. solver 반복 증가는 해당 축소 시험에서 개선했으나 잔류 회전을 없애지는 않았다.
- 더 늦은 정지 3~6초 구간에는 방향이 반대로 변하기도 했다. 단순히 직전 회전의 관성이 같은 방향으로 남는 것만으로 설명하기 어렵다.
- ROS·카메라·운송차·과실 runtime 없는 축소 시험이며 실제 실패 궤적/팔 하중의 정확한 재생이 아니다. 표의 개선률을 실제 인계 실패율 개선으로 해석하지 않는다. 기준 재확인에서도 수치 산포가 있다.
- 물리 비교 4개 및 결과 저장 완료. 종료 확장 unload 후 프로세스가 남아 진단 PID에 SIGTERM으로 정리했다. 실행 중 액션 실패가 아니며 이 종료 현상은 별도다.
