## 바구니 이동안은 폐기·원복

중심 오차를 없애려고 시뮬 전용 바구니/지지대와 종속 링크10개를 전방10cm 이동하는 시험을 한 번 했다. 관절16개 연결점은 맞았지만, 질량 중심 X가 바퀴축 뒤 -3.67cm에서 앞 +2.74cm로 이동했고 실제 Isaac에서 차체가 앞으로 기울었다. 이 접근은 잘못됐으므로 채택하지 않았다.

원본 URDF/USD는 수정하지 않았고, 시험용 파생 `transport_robot.sim.usda`도 **이번 작업 직전 파일로 바이트 단위 복구**했다. 생성 도구의 이동 코드·임시 장착 설정 역시 제거했다. 실패 시험용 생성 코드/설정/로그만 `41/attempt1_unstable_mount/`에 보존한다. 사용자 후속 지시대로 바구니 형상·질량·장착 위치를 바꾸지 않는다.

## 실제 시험

모든 실행: ROS Domain13, discovery SUBNET, headless Isaac, CPU PhysX/MBP. 공통 PrecisionMotion + MotionGate로 실제 가상 카메라·라이다·바퀴 odom을 사용. 실제 USD 위치는 별도 파일 평가에만 사용했다. 아래 표는 최종 집계 후 생성한 `summary.json`과 함께 읽는다.

- 10cm 이동 시험: 차체 전방 기울어짐, Action 카메라 입력 실패. 채택하지 않고 원복.
- 원복+TF50ms 대기만 적용: 카메라 수신은 계속됐으나 공통의 유효 영상 수신 timeout으로 실패. 영상에도 시계 대기를 적용했다.
- TF/영상50ms: 마커41 최종 도킹 2회 성공·정지, fresh 거절0/0. 마커42 접근 성공·정지했으나 fresh 미래 시각 거절1회. 50ms를 최종 설정으로 확정하지 않았다.
- 100ms 첫 시험: 단일 대기 프레임을 새 프레임으로 교체하던 구현에서 발행 고갈이 발생해 카메라 timeout. 최대4장 큐로 수정하고 촬영주기=대기시간 회귀검사를 추가했다. 이 실패도 보존했다.
- 최종100ms 결과: 공유 `summary.json` 및 문서 하단에 별도 기록.

공통 `farm_docking` Python27파일이 인수 커밋과 바이트 동일. 도킹 프로파일/마커 목표의 숫자·bool 변경0. 프레임 namespace·sim 파일 경로만 환경에 맞췄다. USD 복구 hash 및 비교는 `preservation.json`.

## 남은 바구니 정렬 문제 — 성공 처리하지 않음

원본 모델의 도킹 결과에서 중심 오차 약10.5cm, 명목 배출 개구부 겹침 약72%가 남았다. 양 로봇이 멈춰도 전체 개구부 포함 조건을 만족하지 않아 정렬 유지 실패다. 평가 기준이나 원본 도킹 거리20cm를 낮춰 통과시키지 않았다.

정렬 평가의 치수는 URDF 명목 개구부(수확19cm, 운송29.4cm), 위치/자세는 실제 USD 프레임이다. USD visual mesh의 일부 스케일과 collision bound의 오프라인 해석에도 주의가 필요하므로 이것을 실물 치수 검증 완료라고 보지 않는다. 평가 기준·물리 충돌·실제 배출 성공은 서로 구분한다.

정면·평면 근사에서:

- 운송 라이다 X=-0.064m, 운송 입구 중심 X=0.086-0.15=-0.064m: 둘의 전후 위치가 같다.
- 수확 차체의 관측 면 Y≈-0.25m, 배출부 중심 Y≈-0.35m: 배출부는 면보다10cm 앞으로 나온다.
- raw 라이다20cm에서 멈추면 두 바구니 중심이 약10cm 차이 나는 구조다.
- 단순히10cm 정지로 바꾸면 현행 scan 최소범위12cm 아래이며, 차체 전방 footprint(+7.5cm)와 라이다(-6.4cm)를 이용한 평면 근사에서는 약3.9cm 차체 겹침까지 예상된다. **10cm로 변경하거나 실제 구동을 시도하지 않았다.**

따라서 현재 자료만으로 공통 알고리즘 오류나 실물에서도 같은 기구 불일치가 있다고 단정하지 않는다. USD를 유지하는 조건에서는 실물에서 사용하는 정지 거리의 기준과 실제 장착 위치를 먼저 대조해야 한다.

실물 담당자에게 확인할 값:

1. 프로파일20cm가 raw 라이다→어느 표면의 거리인지, 실제 도킹 완료 시 측정값.
2. 운송 base 기준 라이다와 바구니 수용부 중심·상단 높이, 차체 앞끝.
3. 수확 base 기준 마커41의 면, 라이다 반사 면, 바구니 실제 배출 개구부 중심·크기·높이.
4. 실제 도킹 완료 시 두 로봇의 바구니/차체 상대 위치 사진과 치수. 현재 USD가 그 기구 버전과 같은지.
