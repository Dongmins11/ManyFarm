## 범위와 제한

기존 SEC01 성공 예찰의 첫 윈도우에서 실제 HarvestTask를 수행한 뒤 TransportPickup/DockTransfer를 실행한다. 신규 예찰·전체 SEC01 시험이 아니다. 해당 윈도우는 expected=1, harvested=0이며 팔의 실행가능 대상 없음으로 정상 종료됐다. 실제 과실 인계량을 검증한 시험이 아니다.

수확·운송 초기 배치만 시험용이다. 실행 중 위치 정답이나 가짜 성공을 주입하지 않는다. 실물 제어 수치·공통 성공/실패·취소·타임아웃·바구니 USD는 유지했다. 교통은 비활성이며 공통 코드의 동시 출력 차단을 제거하지 않았다.

- 42번 임시 마커를 회전 전 접근 가능한 면/통로에 맞춘 실행 묶음을 사용한다. 실측 장착값은 아니다. 운영 자산 layout.provisional.json과 USD는 변경하지 않았다.

## 전체 관제 사이클까지 남은 계약

1. Frontend는 선택 Window(-6.015m X)를 staging_pose로 보내지만 운송 원본은 그래프(-5.955m X)로부터2cm 이내만 접수한다. 6cm 차이로 원래 Goal이 거절된다. 현재 시험은 그래프 접근점을 명시적으로 사용하며 운영 관제 해결로 보고하지 않는다. 공통 정책 수정 전 구체안 검토/승인이 필요하다.
2. 인계+교통 동시 출력과 운송 교통 연결은 원본에서 명시적으로 차단한다. 차단 삭제만으로 지원하지 않는다. 실제 관제와 graph_02/zone_02 계약 및 정지 소유권 연결이 필요하다.

4. 모든 연결 뒤 신규 SEC01 예찰→전체 윈도우 수확→운송/선별장/양쪽 복귀를 실제 검증해야 한다.
