- 공통 `scout_new/states/segment_progress_state.py`: 도착 후 정지 상태에서 해당 구간 사용권을 열고 실제 보정3회 적용을 확인한 다음, 사용권을 닫고 확인 완료 이후 시각의 새 capture를 요청한다. 카메라 워커가 예전 프레임을 반환하지 못하도록 after_stamp_ns를 갱신한다. Action 종료/주행 목적지/팔 작업 범위는 변경하지 않는다.
- 대기는 상태 실행 스레드에서만 수행한다. 기존 로그에서 최초 사용권 수신 후 적용1/2/3회까지0.75/1.87/3.08초였고, 보정은 기존 half-step이므로 한 번 반영만으로 잔차가 모두 제거되지 않는다. 3회 확인/벽시계8초 상한을 사용한다. 관측/적용 부재는 timeout, 이벤트 제공 노드가 없으면 unavailable로 사유를 저장하고 기존 촬영을 진행한다. 미적용을 성공으로 기록하지 않고 Action 실패도 만들지 않는다. 이것은 정확도 수렴 보장이 아니라 실제 반영 확인이다.
- 사용권은 finally에서 닫고 취소 시 촬영하지 않는다. 접근 중 반복 ID 사용권은 계속 닫혀 있다. 기존 이동 중 태그 보정 범위/AMCL 보정량/공분산/TF 소유권은 유지한다. 실물의 scan_sync 환경에서도 촬영 전 대기가 추가되며, 적용 이벤트가 없는 initialpose 환경은 대기를 건너뛴다.
- 각 segment 보고서 `tag_capture_sync`에 reason/applied_count/elapsed_wall_s/after_stamp_ns/실제 적용 stamp 목록을 저장한다.
