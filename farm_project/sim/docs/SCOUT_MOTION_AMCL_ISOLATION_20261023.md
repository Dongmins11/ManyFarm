# 예찰 회전 물리·AMCL 잔차 분리 — 2026-10-23

기준: `0832b6f1827d912d827667e4c50aacf3a3f4e549` 및 이전 미커밋 태그/과실/업무·교통 작업. 승인: 사용자 “그것도 진행해”. 공통·실물 코드와 Nav2·AMCL 설정은 수정하지 않았다. 정답은 사후 평가에만 사용했다.

## 1. 확인 및 적용

예찰 로봇 뒤 캐스터는 자유롭게 구르는 관절이 아닌 **고정 상자 충돌체**였고 별도 접촉 재질이 없었다. 이 지지점의 미끄럼 저항이 회전을 방해하는 것이 단일 명령 발행자 시험에서도 재현됐다.

시뮬 캐스터 접촉만 정/동마찰0, 반발0, 마찰 결합=min으로 변경했다. 이는 수동 캐스터의 자유 구름을 마찰 없는 지지 접촉으로 근사하는 것이며 실제 구름저항을 완전하게 재현한 모델은 아니다. 바퀴 형상·간격·반지름·질량·구동 gain·odom 계산은 그대로다.

- 적용 자산: `sim/assets/robots/scout_robot/urdf/scout_robot_camera_fixed.usd`.
- 재현 도구: `sim/tools/configure_scout_caster.py`(USD Python, 기본dry-run, --apply 시 sim 내 백업 필수/기존 백업 덮어쓰기 거부).
- 백업: `sim/runs/localization_motion_20261023/scout_before_caster_fix.usd`.
- Sdf 전체 spec 비교·재개방 PASS: 캐스터 재질 및 해당 충돌체 binding 외 변경 없음(`asset_diff.json`).

## 2. 회전 분리 비교

CPU/headless/Domain13/SUBNET. 기존 Isaac·장치 launch를 조합한 평가 전용 launch에서 Nav2·업무·영상·LiDAR를 끄고 cmd_vel 발행자1개를 확인했다. 각 조건을 전체 재시작해 좌우±0.25rad/s8초, ±0.5rad/s6초 및 전후0.1m/s5초·정지 구간을 실행했다. 측정은 실제 물리 자세와 엔코더를 같은 구간에서 대조했다.

| 조건 | 실제/엔코더 회전 비 | 저속 요청 누적각 추종 | 판단 |
|---|---:|---:|---|
| 기존 | 0.948~0.965 | 약19% | 큰 저항·엔코더 회전 불일치 재현 |
| 캐스터 재질마찰0, 기본 결합 | 0.973~0.988 | 약51~52% | 저항 기여 확인, 결합 마찰 잔류 |
| 바퀴 damping10배만 | 0.956~0.966 | 약15~23% | 개선 없음, 적용 안 함 |
| 캐스터 재질마찰0, min결합 | 0.9950~1.0038 | 약79~80% | 회전량 불일치0.5%이내, 적용 |
| min결합+damping10배 | 0.9962~1.0046 | 약80~81% | 추가 이득 없어 gain 유지 |

캐스터 재질의 마찰만0으로 놓아도 바닥과의 결합 마찰이 남을 수 있어 min결합까지 비교했다. 저속 정상 구간은 요청0.25 대비 실제 약0.200rad/s, 고속 요청0.5 대비 실제 약0.444rad/s였다. **엔코더-실제 회전 불일치 개선과 명령 추종 개선은 별개**이며 명령 추종은 아직100%가 아니다. 구동 gain을 무작정 키우지 않았다.

물리 속도 솔버 반복1→8 추가 시험도 개선되지 않았다(실제/encoder0.991~0.995, 저속 누적 명령 추종74~75%). 기본1을 유지했다. 전체 로봇·과실의 물리Hz나 렌더 설정을 바꾸는 시험은 아니다.

## 4. AMCL — 단순 설정 변경으로 해결되지 않음

### 지도 관측 민감도

실제 scan을 실제 물리 자세에서 지도 거리장에 겹치고 X/Y방향으로5cm씩 이동해 평가했다. 60개가량의 빔에서 지도 점수 감소는 X약3.716%, Y약0.129%였으며, 전체360빔에서도 X3.744%/Y0.144%였다. 길이 방향을 구분하는 정보가 상대적으로 약했다. 이는 보조 점수 진단이며 내부 AMCL 전체 확률의 완전한 재현은 아니다.

### 실제 AMCL 재생

같은 기록 scan·encoder·추정 초기 위치/공분산을 실제 `farm_tag_amcl`에 재생했다. 별도 namespace/frame/map/scan, Domain13/SUBNET, wall clock을 사용해 물리 시험과 ROS입력이 섞이지 않게 했다. **정답 위치는 재생 입력 파일에 없고 평가 파일로 분리했다.**

- 시작 추정 오차 X4.1mm/Y139.1mm, 기록된 추정 표준편차 X200mm/Y544mm.
- 기본 설정, max_beams360, sigma_hit0.05를 각각3회 재현했다. 동일 초기 난수 상태로 수치가 같아 독립 통계 표본3개로 해석하지 않는다.
- 정지 scan10프레임 동안 pose 갱신1회뿐이었다. 기본 update_min_d/a 때문에 정지 관측만 계속 보내도 필터가 계속 갱신되는 것은 아니다.
- 이어서35회 nomotion 갱신 후 Y잔차는 기본약142mm, 360빔약150mm, sigma0.05약204mm였다. 더 기다리기·빔 수 증가·센서 모델 폭 축소는 해결책으로 적용하지 않았다.

근거: `likelihood.json`, `replay_input.json`, `replay_evaluation_truth.json`, `amcl_replay/*/params.yaml/result.json/amcl.log`, `amcl_replay_comparison.json`.

## 5. 공통 개선 후보 — 복수 태그

현재 관측기는 여러 태그를 보더라도 한 태그 packet을 선택한다. 같은 영상의 등록된 여러 태그 간격을 함께 이용한6D PnP를 오프라인 검증했다.

기존 observer가 usable로 판단한 태그만 사용하고 Hamming0/margin80을 유지한 보수적 부분 표본에서, 기하 태그 로그23프레임의 평균 절대 오차는 단일 X14.1/Y21.7mm/yaw0.861° 대비 복수 X7.1/Y12.6mm/yaw0.565°였다. 재투영 RMS≤1px의 동일 프레임 비교이며 전체 프레임/구간 성능은 아니다. 실제 자세의 시간 보간 오차도 남는다.

높이·roll/pitch를 강제로 고정한 평면 해법은 이동 중 차체 기울기를 설명하지 못해 제외했다. 복수 관측도 후보 모호성·공분산·불완전 검출·오등록 태그에 대한 검증이 필요하다. 운영에 시험 알고리즘을 우회 주입하지 않았다.

구체적인 공통 변경 대상·방식·실물 영향·검증 계획: [MULTITAG_LOCALIZATION_PROPOSAL_20261023.md](MULTITAG_LOCALIZATION_PROPOSAL_20261023.md). 공통 소스 변경은 아직 적용하지 않았다.

## 6. 로그·한계·복원

원본은 `sim/runs/localization_motion_20261023`에 조건별 보존했다. 준비 실패는 실제 로봇/Action 실패와 구분했다: 시험 설정 옆 station파일 누락, 상위USD의m·Z메타데이터 누락, 불필요한 수확 audit파일 의존을 확인해 Isaac+예찰장치만 조합하는 전용 launch로 정리했다. 이후6조건 물리시험은 정상 완료했다. Isaac 일부 종료 단계 비정상 종료는 측정 완료 뒤 발생했으며 로그에 남아 있다.

복원은 백업 USD를 원래 자산 경로로 복사한다. 보고서·원본 로그는 보존한다. 다른 작업자의 미커밋 변경은 건드리지 않았고 커밋/푸시는 수행하지 않았다.

재현 주의: 운영 자산을 수정한 뒤에도 비교군이 바뀌지 않도록, 6개 물리 비교 장면은 기존 원본 로봇 백업을 명시 참조하게 고정했다. 실행 당시 상위 레이어는 각 `scene.executed.usda`, 참조 고정 전후 해시는 `replay_stage_pinning.json`에 보존했다.
