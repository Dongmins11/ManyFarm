# 수확로봇 인계 주행 관련 검토 요청 2건

작성일: 2026-10-28 / 시뮬레이션 담당 → 실물 주행·인계 담당

시뮬레이션에서 확인한 두 문제를 공유드립니다. **실물 재현 여부는 미확인**이며, 공통 제어·완료 판정과 인계 중 위치 보정 정책을 검토 부탁드립니다.

시험 기준은 `main ea25693`에 인계 통합 미커밋 변경이 포함된 작업본입니다. ROS Domain 13 / SUBNET, Isaac CPU 물리 60Hz, SEC01 기존 첫 윈도우를 사용했습니다. 전체 SEC01 시험이 아닌 수확 윈도우 이후 도킹·가상 인계·복귀 시험입니다. 실제 과실 배출 대신 바구니 정렬·정지 유지로 인계를 평가했습니다.

## 1. 벽 정렬 완료 후 별도 정지 검사에서 각도 허용치를 넘어 액션 실패

### 현상과 처리 순서

수확로봇이 운송로봇에 인계하기 위한 자세로 회전·벽 정렬하는 단계입니다. 운송로봇이 도킹을 완료한 뒤 발생하는 문제가 아니라, **DOCK_READY를 내보내기 전**에 발생했습니다.

1. 벽 정렬 제어기 측에서 거리·각도 허용범위와 정지 조건을 **0.5초 유지**하면 완료를 반환합니다.
2. 공통 Navigator에서 이후 별도로 **0.8초 정지 유지**를 확인합니다.
3. 최신 관측으로 목표 오차를 다시 검사하고, 허용범위 밖이면 재정렬 없이 액션을 실패 처리합니다.

두 검사 모두 각도 기준은 **±0.5°로 같지만 검사 시점이 다릅니다.** 0.5초부터 0.8초까지의 0.3초 동안만 문제가 발생한다는 의미는 아닙니다. 실제 실패 시험에서 완료 반환부터 최종 검사까지의 비교 구간은 약 2.5초였습니다.

### 확인된 수치

동일 조건 3회 중 1회 성공, 2회 아래 오류로 실패했습니다.

| 항목 | 시험 2 | 시험 3 |
|---|---:|---:|
| 실패 시각(KST) | 10/28 16:41:15 | 10/28 16:43:09 |
| 완료 반환 시점 부근 각도 오차 | 0.346° | 0.435° |
| 최종 검사 시점 부근 각도 오차 | 0.541° | 0.606° |
| 완료 반환 후 실제 차체 방향 변화 | −0.194° | −0.174° |
| 바퀴 실제 회전량으로 계산한 방향 변화 | −0.197° | −0.174° |

해당 구간의 차체 속도 명령과 바퀴 속도 목표는 모두 0이었습니다. 그런데 실제 바퀴가 미세하게 더 굴렀으며, 그 회전량으로 차체 방향 변화가 거의 설명됩니다. 지도 위치 추정만 흔들린 현상은 아닙니다.

시험 2의 실제 액션 결과 필드 발췌:

```json
{
  "result_code": "FAILED",
  "error_code": "DEVICE_FAILED",
  "error_message": "rotate_to_transfer: 정지 후 목표 오차 초과",
  "transfer_complete": false,
  "restore_complete": false,
  "timestamp": "2026-10-28T07:41:15.541142+00:00"
}
```

로그 시각은 UTC이며 본문 표는 KST입니다. 각도 수치는 외부 벽 관측·odom 및 실제 USD 자세를 대조한 재구성입니다. 내부 최종 validator 표본을 직접 캡처한 것은 아닙니다. 최종 결과와 외부 벽 표본 시각 차이는 시험 2 −4.9ms, 시험 3 +4.2ms입니다.

### 현재 판단 및 검토 요청

- 시뮬 구동·접촉 계산에서의 잔류 움직임과, **제어 종료 뒤 다른 시점에 다시 검사하여 실패시키는 공통 처리 구조**가 결합했습니다. 실물에서 같은 잔류 움직임이 발생하는지는 미확인입니다.
- 이전 RPP의 TF 시각 정합 수정이 사라진 사례는 아닙니다. 해당 수정은 유지됐고, 이번에는 인계 경로의 별도 도착 검사에서 거절됐습니다.
- 정렬 제어가 최종 정지·허용범위 유지까지 책임지고 동일 시점의 관측·자세로 완료를 결정하도록 검토 부탁드립니다. 최종 검사 초과 시 제한적인 재정렬 가능 여부도 함께 확인이 필요합니다.
- 현재 시험 진행을 위해 **시뮬 실행 설정만 사용자 승인하에 0.8°로 임시 완화**했습니다. 실물 원본 0.5°는 변경하지 않았습니다. 위 실패 로그는 완화 전 0.5° 시험입니다.

## 2. 인계 후 윈도우 복귀 중 태그 보정 미적용 구간에서 약 7cm 위치추정 오차

### 현상과 시험 조건

수확로봇이 원래 윈도우에서 인계 자세로 이동한 뒤, 운송로봇 도킹·인계·이격을 마치고 원래 윈도우로 복귀하는 과정입니다. **실제 차체는 목표 근처로 돌아왔지만 지도상 추정 위치가 어긋나 복귀 실패**했습니다.

이 결과는 태그 기능을 복원한 뒤 수행한 시험입니다. 이전 시험 실행기에서 태그를 비활성화한 구성 오류가 있었으나 수정했습니다. 이번 시험은 `tag_correction=true`, `farm_tag_amcl`이며 실제 보정 적용도 확인했습니다.

- 수확 윈도우 이동 중: 태그 보정 **3회 적용**.
- 인계 회전·복귀 중: 태그 보정 **0회 적용**.
- 현재 공통 흐름은 윈도우 이동에서 보정 권한을 열고 수확 미션 종료 때 닫으며, 인계 FSM에서는 새 권한을 열지 않습니다.

따라서 이번 문제의 조건은 **태그 기능 전체 OFF가 아니라, 인계·복귀 구간에 추가 태그 보정 없이 AMCL·odom으로 위치를 추정하는 상태**입니다. 운송 도킹에 쓰는 마커 감지와 수확로봇 지도 위치를 보정하는 태그 권한은 구분해야 합니다.

### 확인된 수치와 로그

실패 시각: 2026-10-28 18:08:55 KST.

| 항목 | 측정값 |
|---|---:|
| 실제 차체와 원래 윈도우 목표의 거리 | 2.02cm |
| 지도상 추정 위치와 목표의 거리 | 9.33cm |
| 실제 위치와 지도상 추정 위치의 차이 | **7.34cm** |
| 시험 중 AMCL 위치 오차 최댓값 | 8.49cm |
| 윈도우 복귀 위치 허용치 | 5cm |

실제 액션 결과 필드 발췌:

```json
{
  "result_code": "FAILED",
  "error_code": "DEVICE_FAILED",
  "transfer_complete": true,
  "transport_clear": true,
  "restore_complete": false,
  "error_message": "restore: WINDOW_REALIGN_REQUIRED: 짧은 전진으로 window 완료범위 확보 불가 (전방=-0.0922m, 횡오차=-0.0143m)",
  "timestamp": "2026-10-28T09:08:55.144866+00:00"
}
```

운송로봇 작업은 SUCCESS이며 인계와 이격도 완료됐습니다. 이후 수확로봇 추정 위치 기준으로 목표가 약 9.2cm 뒤에 있다고 판단했습니다. 목표 거리 5cm 범위를 벗어났고 허용된 짧은 전진으로 보정할 수도 없어 `WINDOW_REALIGN_REQUIRED`가 발생했습니다.

실제 좌표는 시뮬 USD 자세를 평가용으로 사용했습니다. 지도상 최종 위치는 결과 약 10.7ms 전의 외부 TF·odom 기록으로 재구성했으며 내부 validator의 정확한 입력 표본은 아닙니다. 시뮬 정답을 주행 제어에 주입하지 않았습니다.

### 현재 판단 및 검토 요청

- 실제 복귀 위치 오차와 위치추정 오차를 구분해야 합니다. 이번에는 차체가 목표에서 9cm 떨어진 것이 아니라, 실제 약 2cm 떨어진 위치를 지도상 약 9cm 떨어진 것으로 추정했습니다.
- 인계·복귀 중 태그 보정 권한을 열지 않는 것이 의도된 정책인지 확인 부탁드립니다. 해당 구간에서 보정을 허용한다면 관측 품질과 적용 시점도 함께 검토해야 합니다.
- 현재 AMCL·odom만으로 복귀 위치 허용치 5cm를 안정적으로 만족할 수 있는지, 복귀 완료 때 어떤 위치 관측을 사용할지 검토가 필요합니다.
- 태그 미적용이 유일한 원인이라고 확정한 것은 아닙니다. 태그 ON 시험 1회만으로 OFF 대비 개선·악화도 판단할 수 없습니다. 실물 동일 증상 및 최근 변경의 기여 여부는 추가 확인이 필요하며, “원래부터 있던 문제”로 단정하지 않습니다.

관련 코드: `harvest_robot/node.py`의 윈도우 이동 태그 권한, `mission.py`의 권한 종료, 인계 FSM, `handoff_window.py::correction_path`의 최종 복귀 판정.

## 첨부 파일 안내

이 문서와 `logs/`를 같은 위치에 두면 상대 링크로 로그를 열 수 있습니다. JSON/JSONL 원본과 기존 분석 결과를 복사했으며, 파일별 원본 경로·SHA-256은 `manifest.json`에 기록했습니다. 경로에 포함된 작업자 PC의 절대 경로는 원본 기록이며, 수신 PC에 해당 경로가 있을 필요는 없습니다.

기존 시험 자료를 정리한 전달본입니다. 이번 문서 작성 중 추가 주행 시험이나 코드·설정 변경은 하지 않았습니다. 위 검토 요청은 제안이며 공통 동작에 적용하지 않았습니다.
