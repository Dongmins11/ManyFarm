## 2. 이번 장면의 핵심

기존06 운송과07 색상 선별을 **하나의 연속 테이크** `06_07_transport_sorting.mp4`로 대체한다.

```text
상부 덮개가 닫힌 운송로봇의 짧은 접근·도킹
→ 배출용 앞문 열기
→ 바구니를 기울여 빨강3개·노랑3개를 쏟기
→ 같은6개가 투입부를 굴러 두 줄/묶음에3개씩 섞여 안착
→ 빈 집게로 시작한 선별 팔이 실제로 내려가 집기
→ 해당 색 분류함으로 옮겨 놓고 구름·안착
→ 안정된 화면2초 유지, 끝부분 페이드아웃
```

- **상부 뚜껑(lid)과 배출용 앞문(gate)을 구분한다.** 운송·선별장 도킹·배출 동안 상부 뚜껑은 닫혀 있다. 앞문만 열고 바구니를 기울여 배출한다.
- 사용자의 “3개3개씩”은 **선별 전 투입부의 두 줄/묶음에 각3개**로 배치하는 의미로 구성한다. 색별 보관함에 처음부터 빨강3/노랑3을 넣는 장면이 아니다.
- 구체 배치의 시작안: 첫 묶음 빨강2+노랑1, 다른 묶음 빨강1+노랑2. 순서와 방향을 엇갈리게 해서 혼합 상태가 보이게 한다.
- 기존 선별장의 실제 투입 레인·경사·팔 도달 영역을 읽고 그 안에 두 묶음을 구성한다. **원래4레인 구조를 임의의2레인 설비로 바꾸지 않는다.** 두 묶음의 간격은 읽기 쉬운 화면 구성을 위한 시작안이며 실제 메시/충돌 범위에 맞춘다.
- 도킹 전부터 과실이 레인에 놓여 있거나, 배출 이후 갑자기 정렬된 과실로 교체되는 연출은 금지한다. 바구니→레인→집게→분류함까지 같은6개 ID를 유지한다.
- 8초 안에서 여섯 번의 집기를 과속시키지 않는다. **편집 기본안은 빨강·노랑 각각1개를 집어 분류하는 동작을 명확하게 보여주는 것**이다. 남은4개는 레인에 그대로 남고, 전량 선별 완료처럼 꾸미지 않는다. 사용자는 이번 메시지에서6개 전량 집기 완료를 명시하지 않았다. 추가 집기는8초와 자연스러움을 함께 지킬 수 있을 때만 넣는다.

## 3. 약8초 동작 설계

다음 시간은 **새 연결 장면의 실제 사용 구간** 기준이다. 애니메이션 키프레임 설계의 시작값이며, 동작이 잘 읽히도록 프레임 단위로 미세 조정한다.

| 사용 구간 | 보이는 동작 | 검수 기준 |
|---|---|---|
| 0.0~0.8초 | 닫힌 덮개 상태로 짧게 접근, 도킹 위치에서 부드럽게 정지 | 바퀴 회전과 이동 일치, 처음부터 설비와 로봇이 한 화면에 보임 |
| 0.8~1.3초 | 앞문 개방 | 앞문의 실제 힌지/축을 사용, 상부 덮개는 닫힘 |
| 1.3~2.3초 | 바구니 기울임, 과실 배출 시작 | 앞문 통로 확보 후 과실 이동, 옆벽/뚜껑 관통 없음 |
| 약2.0~3.6초 | 6개가 엇갈려 빠져나와 경사면을 굴러 두 묶음에3개씩 안착 | 빨강3/노랑3 유지, 각 묶음 색 혼합, 회전과 감쇠 |
| 약3.6~4.6초 | 과실이 모두 빠진 바구니 원위치·앞문 닫기 | 마지막 과실과 간섭 없음, 로봇 차체는 정지 |
| 4.6~8.0초 | 팔이 투입부에서 집기→색별 분류함으로 이동→놓기 | 최소 빨강/노랑 각1개, 집게 닫힘/부착/놓임 연결, 도착 전 과실 교체 없음 |
| 추가8.0~10.0초 | 같은 구도에서 안정 상태 유지 | 마지막1.2초 정착 유지+0.8초 페이드, 새 동작/컷 없음 |

- 앞문 개방 시작0.8초→바구니 복원/앞문 닫기4.6초로 **기구 사이클 약3.8초**. 실제 펌웨어의 약23초를 그대로 기다리지 않는다.
- 과실의 자유 낙하까지 일괄6배속으로 만들지 않는다. 기구와 불필요한 대기 시간을 줄이고, 과실 낙하·접촉·회전은 짧지만 자연스럽게 구성한다.
- 실제 기구 순서인 `gate open → tilt dump(올림/유지/내림) → gate close`를 지킨다. 촬영 시간 압축을 실물 펌웨어나 공통 FSM 설정에 적용하지 않는다.
- 빈 바구니 복원은 레인 과실의 마지막 작은 흔들림과 겹칠 수 있다. 팔은 선택한 과실이 충분히 멈춘 뒤 접근하고, 기구와 간섭하지 않는다.

## 6. 앞 컷05의 최소 연결 수정

V3 05 원본은 보존한다. 새 연결용 `05_handoff_continuity.mp4`만 별도로 만든다.

- 기존 구도, 회색 바닥 슬라이드 개방, 낙하·안착 방식은 유지한다.
- 기존 빨강4/노랑3 대신 **빨강3/노랑3의 같은6개**를 전달한다. 한 개를 컷 사이에서 지우거나 배출 중 숨겨 수량을 맞추지 않는다.
- 인계 때 운송 상부 덮개는 열려 있고, 과실이 모두 들어간 뒤 닫힌 상태로 마무리한다. 닫힘 간섭이 있으면 촬영 배치·바닥 패널 복원 타이밍을 조정해 공간을 확보한다. 운송 상부 덮개 닫힘 완료 후 이격하는 순서를 유지하며 운영 FSM은 변경하지 않는다.
- 닫힘 패널과 과실이 충돌하지 않도록 적재 높이를 점검한다. 06·07의 시작 적재 상태는 이6개 `cargo_box` 상대 pose를 그대로 이어받는다.
- 05용 과실 복제와 새 통합 장면의 ID/색/크기를 같게 기록한다.
- 이번 최소 수정은 05의7개→새 장면6개 불연속 및 열린 뚜껑→닫힌 뚜껑 연결을 해결하기 위한 것이다. 01~04 원본은 그대로 재사용한다.

## 7. 출력 길이·자막·편집

기존 01~05의 각3초는 유지한다. 06·07이 기존5초에서8초로 늘어나므로 마지막2초를 포함한 최종 편집본은 **약25초/750프레임**이다.

| 최종 타임라인 | 사용 영상 |
|---|---|
| 0~3초 | V3 01 전경 |
| 3~6초 | V3 02 예찰 + 기존 검출 이미지 |
| 6~9초 | 원본03 수확 그대로 |
| 9~12초 | V3 04 투입 |
| 12~15초 | 새05 연결용 인계6개/덮개 닫힘 |
| 15~23초 | 새06·07 연속 동작8초 |
| 23~25초 | 같은 화면 정착 유지·마지막0.8초 페이드 |

- 통합 원본은 **12초/360프레임**: 앞 여유1초 + 동작8초 + 안정 상태2초 + 뒤 여유1초. 최종 편집에는 원본 `[1,11)`초10초를 사용한다.
- 원본은1920×1080,30fps,H.264/yuv420p,무음·무자막·무페이드. `ManyFarm_25s_clean.mp4`와 `ManyFarm_25s_captioned.mp4`는 별도 편집 결과다.
- 앞뒤 여유는 전환용이며, 8초 안에 페이드나2초 엔딩을 억지로 끼워 넣지 않는다.
- 05 연결용 원본은 기존처럼5초/150프레임, 사용구간 `[1,4)`초에 인계와 닫힘이 읽히도록 설계한다.
- 통합 장면 내부는 컷/디졸브 없이 이어진다. 05→통합 장면 전환은 여유 프레임을 사용해 최종 길이를 줄이지 않는다.
- 통합 장면 자막은 `운송 · 선별`을 고정 소제목으로 쓰고, 본문을 `선별장 도킹 · 수확물 배출` → `혼합 과실을 색상별로 분류` 정도로 짧게 바꾼다. Noto Sans CJK KR과 기존 민트 포인트를 유지한다.
- 자막은 열린 앞문·과실 이동 경로·집기점·분류함을 가리지 않는 여백에 둔다. 혼합 배치와 실제 집기 순간을 자막 교체로 가리지 않는다.
