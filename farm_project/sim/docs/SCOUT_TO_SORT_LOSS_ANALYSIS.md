# 예찰–수확–선별 수량 손실 원인 분석

> 분석 기준: 첨부 감사 JSON의 dataset_sha256에 해당하는 로컬 데이터 스냅샷. 이후 main의 `570f1a1`에서 6·10번 실제 과실 수가 보완됐다. 아래 두 행의 미확인 표기는 당시 증거 범위를 나타내며 최신 데이터의 값을 취소하지 않는다. 최신 데이터로 도구를 재실행하면 결과가 달라질 수 있다.

## 결론

- **예찰 수량 차이:** 같은 과실을 다른 관측 구간에서 별도 ID로 등록한 사례가 있다. 6.5cm 연계 거리보다 관측 좌표 차이가 커져 중복이 생겼다. 화면 가장자리에서 잘린 검출이 포함된다.
- **수확 수량 차이:** 중복 예찰에 따른 허수와 실제 미수확을 구분해야 한다. 실제 미수확에서는 작업영역 경계 제외, 그리퍼 가림, 집기/분리 실패, 낙하를 확인했다.
- **선별 수량 차이:** 손실 7행 모두 투입은 완료됐으나 과실이 남았다. 좁은 색 검사 ROI에서 `NO_COLOR`가 발생하고 이를 완료 조건으로 사용했다. 저장 영상으로 미검출과 완료 판정을 각각 재현했다.
- 이번 작업은 **분석·오프라인 재현**이다. 운영 코드·ROI·원본 데이터는 바꾸지 않았으며, 실제 물리 재시험으로 개선 효과를 검증한 상태는 아니다.

## 범위와 수량 해석

[원본 데이터](SCOUT_TO_SORT_16_RECORDS_WITH_SYNTHETIC.json)의 실측 11행을 조사했다. 합성 5·13·14·15·16행은 제외했다. 7번과 12번은 같은 예찰·수확 이력을 재사용하고 선별만 별도 실행했으므로, **11회의 독립적인 전체 시험으로 해석하면 안 된다.** 고유 예찰·수확 이력은 10개다.

실제 수는 해당 SEC 작업면의 yellow/red만 집계했다. 6·10번은 원본 초기 장면이 없어 실제 수를 확정하지 않았다. 수확 수는 레이저가 아니라 물리 과실 ID가 담긴 바구니 명세를 사용했다.

## 1. 예찰: 어디서 중복됐는가

실제 `Survey.ingest` 코드에 저장된 관측 결과를 순서대로 입력했다. 11행 모두 ID 순서·예상 수·window 구성원이 원본과 일치했다. 이는 검출 후 연계 로직의 재현이며, 신경망 검출 자체를 다시 실행한 것은 아니다.

| 행 | 동일 과실로 추정되는 GT | 분리된 track / 관측 | 첫 관측 좌표 차이 | 근거 |
|---|---|---|---:|---|
| 1 | Bed02/Pepper0036 yellow | F0010/G03, F0011/G04 | 13.56cm | G03 bbox 폭 2.7px, 오른쪽 절단 경계. G04에서는 폭 22.5px의 온전한 검출 |
| 2 | Bed04/Pepper0036 red | F0003/G02, F0007/G03 | 7.96cm | G03 bbox x=33.75~51.75, 왼쪽 절단 경계 근처 |
| 7·12 | Bed02/Pepper0016 red | F0008/G04, F0013/G05 | 8.49cm | 인접 관측에서 오른쪽→왼쪽 가장자리로 이동하며 새 ID 부여 |
| 7·12 | Bed02/Pepper0017 yellow | F0009/G04, F0012/G05 | 8.27cm | 위와 같은 구간 경계 중복 |

연계 문턱은 6.5cm다. 동일 과실 후보의 추정 좌표가 이보다 달라지면 별도 과실로 등록된다. 1번은 절단 검출의 위치가 실제 중심에서 약 12.5cm 떨어지고 다음 관측은 약 3cm여서, 가장자리 검출 품질 저하가 좌표 차이에 기여한다는 근거가 특히 강하다. 좌표 오차 전부를 특정 깊이 픽셀 하나의 문제로 확정하지는 않았다.

7·12번 W007은 예상 2개지만 수확 inventory가 0이고, 같은 물리 과실은 W008에서 수확됐다. 실제 11개가 모두 바구니에 있어 13→11을 수확 실패 2개로 세면 잘못이다.

**개선:** 가장자리 절단 bbox는 임시 후보로 두고 다음 온전한 관측에서 확정한다. 다중 관측·색·위치 불확실성을 함께 사용해 ID를 연계한다. 연계 거리를 일괄 확대하면 가까운 다른 과실을 합칠 수 있으므로, 현재 중복 사례와 인접한 서로 다른 과실 사례를 함께 회귀검증해야 한다.

## 2. 수확: 어느 과정에서 실패했는가

### 1번: 보였지만 작업영역 필터로 제외

- W003은 3초/60프레임 동안 `visible=1`, `targets=0`이었다.
- `continuous_near_mask`의 y 상한은 0.175m. 관측 y는 첫 기록 0.175684m, 마지막 0.175380m로 경계를 약 0.38~0.68mm 넘었다.
- `student_no_reachable_targets_arms_stowed`로 해당 window를 종료했다.
- Bed02/Pepper0028 yellow는 바구니에 없고 최종 위치도 초기에서 약 5.6mm만 달라, 베드에 남은 것으로 확인된다.
- **원인은 인식 실패가 아니라 도달 가능 영역 판정에서의 탈락이다.**

### 2번: 그리퍼 가림에 따른 대상 미선택

- W007 예상 2개 중 yellow 1개만 선택됐다. Bed04/Pepper0009 red는 베드에 남았다.
- 초기 GT 위치를 저장된 rear 카메라에 투영하면 원본 영상 좌표 (1114.7, 354.6)이다. 해당 지점은 저장 영상에서 오른쪽 그리퍼가 가리는 위치다.
- 유효한 베드 red 검출이 없으며, 다른 낮은 red 검출은 바구니/주변 대상으로 제외됐다.
- **영상·투영·선택 로그가 가림을 지지한다.** 전체 시간 동안의 가림 여부나 다른 시점에서의 검출 가능성까지 입증한 것은 아니다.

### 3번: 내부 집기 상태는 진행했지만 실제 과실은 분리되지 않음

- W001에서 Bed04/Pepper0031 red를 대상으로 명시적으로 연결했다.
- 두 번의 60초 시도가 `WAIT_BOX`에서 끝나고 `retry_timeout_exhausted`로 종료됐다.
- `captured_proxy=true`, `release_latched=true`가 기록됐지만 바구니에 없고 최종 위치는 초기에서 약 5.5mm만 달랐다.
- **내부 집기/해제 플래그가 실제 과실 확보를 보장하지 못한다.** 접촉·그립 힘의 연속 로그가 부족해 손가락 접촉 실패인지 부착 해제 실패인지까지는 확정하지 못했다.

### 6번: 실제 재사용 수확 세션에서 경계 제외와 대상 부족

- 예찰 세션과 수확 세션이 다르므로 `resume_manifest.source_session`을 따라 실제 수확 세션 `4efc9bf857ac41a3957285d7a45b8702`를 조사했다.
- W001: visible 1 / targets 0, 마지막 y=0.195315m. 상한보다 20.3mm 초과.
- W002: visible 1 / targets 0, 마지막 y=0.178058m. 상한보다 3.06mm 초과.
- W004: 예상 2개 중 red 1개만 검출·선택됐다.
- 초기 GT 장면이 없어 이를 실제 서로 다른 과실 3개 손실이라고 확정하거나 누락 과실 ID를 지정할 수 없다.

### 8번: 집기/분리 실패 1개와 낙하 1개

- W002 Bed04/Pepper0007 yellow: 두 번의 60초 `WAIT_BOX` 시간초과 후 종료. 최종 위치가 초기에서 약 5.5mm로 베드 잔류.
- W003 Bed04/Pepper0035 red: `target_dropped_below_box`가 기록되고 재관측되지 않았다. 최종 z=0.03658m, 초기에서 약 83cm 이동해 낙하가 확인된다.

**개선:** 작업창을 실제 도달영역 안쪽으로 배치하고, 경계 밖 대상은 제한된 재관측/자세 조정으로 재평가한다. 그리퍼가 관측 시야를 가리지 않는 관측 자세를 사용한다. 집기 성공은 상태 플래그 외에 실제 유지·분리 확인을 추가하고, 낙하와 바구니 유입을 분리 기록한다. 물리 도달범위 자체를 넓혀 통과시키는 방식은 피한다.

## 3. 선별: 투입 후 색 검사에서 놓침

손실 7행의 cargo ID는 모두 선별장 투입 성공 기록과 연결된다. 남은 ID와 실제 선별 집계 차이도 일치한다. 이 21개 차이는 운송 중 분실로 확인된 것이 아니다.

| 행 | 잔류 수 | 남은 과실 ID (해당 Bed) | 원래 폭 유지 Y 이동 시 검출 복구 |
|---|---:|---|---|
| 1 | 3 | Bed02: 0026Y, 0033R, 0036Y | +5px |
| 2 | 4 | Bed04: 0013R, 0025Y, 0027Y, 0036R | +5px |
| 3 | 1 | Bed04: 0032R | +20px |
| 4 | 3 | Bed06: 0018Y, 0029Y, 0036Y | +5px |
| 8 | 2 | Bed04: 0024Y, 0032R | +30px까지 미복구; 가로 ±10px 확대·Y+40px에서 yellow 검출 |
| 11 | 5 | Bed02: 0026Y, 0030Y, 0032R, 0033R, 0036Y | +5px |
| 12 | 3 | Bed02: 0017Y, 0027R, 0031Y | +15px |

R=red, Y=yellow. 표의 복구는 **잔류 영상에서 색 신호가 다시 나온다는 의미**이며, 모든 잔류 과실의 개별 검출이나 실제 집기 성공을 의미하지 않는다.

- 현재 ROI는 A=(185,148,24,10), B=(271,148,15,11), C=(349,147,18,11), D=(435,148,18,12)로 매우 얇다. 이전 +5px 조정이 반영된 설정에서도 재현된다.
- 실제 분류기(HSV S≥90/V≥60, 3×3 opening, 색 비율 8% 문턱)를 저장 영상에 적용하자 11행 모두 최종 `NO_COLOR`가 재현됐다. 손실 7행에도 과실은 남아 있었다.
- 예: 1번 A yellow 2.5%, 2번 C red 7.07%, 11번 B red 7.27%로 문턱 미달이다. 다른 ROI는 0%인 경우도 있어 문턱만 낮춰서는 해결되지 않는다.
- 8번은 더 아래에 남아 있어 단순 +5px로 해결되지 않는다. 확대 ROI를 Y+80px로 이동하면 red, +100px에서는 `MIXED`도 나온다.
- 공통 선별 감독자는 모든 구역 `NO_COLOR`가 3초 지속되면 `SUCCESS`로 끝낸다. 현재 코드에 새 관측을 4초 입력하는 별도 재현에서도 red=0/yellow=0의 `SUCCESS`가 나왔다.
- 즉 **색 미검출과 실제 빈 상태를 구분하지 않는 완료 판정**이 잔류를 성공 처리한다. 잔류 과실은 다음 집기 대상 선택까지 가지 못했으며, 해당 과실의 집기 실패로 기록된 것은 아니다.

**개선:** 투입면 전체의 잔류/점유 확인을 색 분류와 분리하고, 실제 집기 가능한 위치를 포괄하는 탐색 영역을 사용한다. `NO_COLOR`인데 점유가 있으면 제한된 재탐색·자세/위치 조정을 수행하고, 빈 상태 확인 후 완료한다. ROI 확대만 적용하면 혼색·다중 과실을 잘못 집을 수 있으므로 검출 위치와 집기 좌표를 함께 검증해야 한다.

| 선별 미검출 | 저장 영상에 현재 분류기 적용, 손실 7행 모두 재현 | 색 신호 복구 후 실제 집기까지 검증하지 않음 |
| 선별 조기 완료 | 현재 공통 감독자에서 NO_COLOR→SUCCESS 재현 | 역사적 전체 실행을 그대로 재생한 것은 아님 |

**해결·재발 없음으로 판정할 수 있는 상태가 아니다.** 이번 분석에서 운영 수정은 없고, 연계 및 선별 문제는 현재 코드로 재현된다. 이 데이터에는 재사용 실행, 전체 Action 실패, assisted grasp 및 가상 인계/투입 경로가 포함돼 있어 실물 로봇의 독립 E2E 성공률로 사용할 수 없다.

## 권장 개선 순서와 검증 조건

1. **선별 잔류 확인과 완료 판정 보완:** 현재 21개 차이에 직접 연결된다. 7개 잔류 영상과 4개 완료 영상을 모두 회귀 자료로 사용하고, 잔류 상태에서 성공 종료하지 않는지 검사한다. 이후 물리 선별 시험으로 잔류 0·오집기 여부를 검증한다.
2. **예찰 구간 경계 ID 중복 제거:** 현재 중복 후보 4쌍(7·12 재사용 제외)을 재생하며 같은 과실을 합치되 인접 과실은 분리하는지 검사한다. 전체 과실 정답 대응이 있어야 정확한 precision/recall을 낼 수 있다.
3. **수확 관측 자세·작업창 여유 개선:** 1·6번 경계 사례, 2번 가림 사례를 우선 짧게 재시험한다. 도달 불가 시 상태를 바꾼 제한 재시도를 적용한다.
4. **물리 집기 확인 계측:** 3·8번 대상으로 접촉·분리·유지·낙하·바구니 유입을 같은 시간축에 기록해 근본 원인을 분리한다. 센서 미통과와 실제 미수확을 별도 실적으로 유지한다.

공통/운영 수정은 별도 변경으로 진행해야 한다. 이번에는 분석 도구와 증거 문서만 추가했다.
