# 사이클 시험 적용 조건

2026-11-01 사용자 요청: 과거에 합의한 조건을 새 시험·재개 시험에도 반드시 확인한다.
단독시험 시작은 완료가 아니다. 액션 결과 및 전체 복귀 완료를 확인한다.

## 출발 순서 — 교통관제 미연결 시험

- TRANSPORT_CLEAR는 바구니 이격 완료다. 공유 통로가 비었다는 뜻이 아니다.
- 한 로봇을 정지시켜도 다른 로봇의 경로 위에 있으면 충돌한다.
- 모든 SEC/신규/재개/overlap 모드에서 같은 경로 점유 규칙을 적용한다. SEC 번호 분기 없음.
- 두 로봇의 최신 map 상태와 실행 프로필을 사용한다. 수확 복귀는 공통 전진/후진 선택기로,
  운송 선별장 접근은 해당 운송 그래프로 계산한다. 경로는 실행 제어기에 대신 주입하지 않는다.
- 수확이 운송 예정 경로를 점유하면 수확 선행, 아니면 운송 선행.
- 차체 footprint 외접반경+padding+도착 허용오차 합으로 보수적인 간격을 계산한다.
  인계 직후 여유 영역이 겹쳐도 경로 전체가 상대 쪽으로 더 접근하지 않는 이탈은 허용한다.
- 선행 로봇의 현재 위치가 후행 예정 경로에서 간격 이상 벗어나면 후행 출발.
  고정 실제시간 지연/스테이션 도착 필수 대기 없음. 위치 신선도는 ROS 시간1초 이내.
- 서로의 경로를 모두 막으면 임의로 어느 쪽도 출발시키지 않는다. 교통 재계획 필요 오류 기록.
- 구현: sim/tools/cycle_departure_gate.py, single_cycle_steps.py::after_handoff.
- 검사: sim/tests/test_resume_departure_order.py. 16개 좌표 배치 변형 및 가까운 이탈/상호 점유/신선도 검사.
- 모든 실제 SEC 주행 검증 완료는 아님. 동적 교통관제·Nav2 장애물 감지를 대체하지 않는다.
- 실제 실패 근거: sec02_restore_resume_20261101/attempt_001, sec02_departure_recovery_20261101/REPORT.md.

## 선별장 인계 후 운송 복귀

- 전체 사이클은 선별장 인계 액션 성공·기구 완료·이격 정지와 수확 스테이션 복귀 SUCCESS/docked를 모두 확인한 뒤 운송 복귀를 요청한다.
- 선별팔은 병행한다. 선별 완료를 운송 복귀 출발 조건으로 삼지 않는다.
- 수확 복귀 결과는 현재 시험 토큰으로 연결하고 다른 시도/다른 로봇/실패/미도착 결과는 거절한다.
- 운송 복귀와 선별 작업의 최종 성공은 각각 끝까지 확인한다.

## 실행·집계

- ROS_DOMAIN_ID=13 / ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET. CPU 물리.
- 운영 동작 제한시간은 시뮬 시계. 기존 코드에 실제시간 경로가 남은 부분은 완료로 주장하지 않는다.
- 성공한 예찰/수확 재사용 시 출처·세션·과실 실물 수·기존 집계를 보존한다.
- 수확 재사용 시 현재 세션의 윈도우 도착을 재확인하며 새 수확으로 집계하지 않는다.
- expected/harvested/sorted 수량 미달은 성능 지표. 액션 오류와 구분한다.
- 인계 태그 위치보정 금지. 시뮬 정답 위치를 실행 중 제어에 주입하지 않는다.
- 정렬 허용값을 임의 완화하지 않는다. 유효 정지 증거를 기다리거나 안전하게 재보정한다.
- 실패 로그와 원본 결과 보존. 자동 감독 유무·현재 PID·다음 SEC 전환 조건을 확인한다.

## 시작 전 확인

1. 본 문서와 최근 PROJECT_STATE/CHANGELOG를 읽고 해당 시험 분기의 실제 코드를 확인한다.
2. 출발 순서 회귀검사 실행. 수정 설치본/소스 일치 및 이전 프로세스 존재 확인.
3. 실행 조건은 selected_sim_sources.json에 본 문서 원문·해시와 함께 보존된다.
4. 실행 중인 시험은 시작 당시 코드를 사용한다. 파일 수정만으로 hot reload됐다고 말하지 않는다.

## 수확 정지 제동 — 2026-11-02

- 수확 시뮬 base.wheel_position_hold=true: 정지 시 바퀴 엔코더 위치 joint drive 유지, 주행 재개 시 원래 gain 복원. GT/차체 pose 고정 금지.
- 짧은 회전 정지 통과만으로 긴 운송 대기의 차체 밀림 해결을 주장하지 않는다. 위치 5cm 판정 유지, 실제 적재 재시험으로 확인한다.

## 인계 출발 전 준비 검사 — 2026-11-02

- 일반 RobotStatus.ready만으로 인계 준비 완료를 판단하지 않는다. 인계 controller_server/behavior_server ACTIVE, 새 costmap_raw/published_footprint, 배출/Spin 액션 및 장치 서비스 연결을 운송 출발 전과 인계 직전에 확인한다.
- Costmap 신선도는 공통 제어기와 동일하게 header.stamp 및 수신 시각으로 판정한다. metadata.update_time은 0일 수 있으므로 사용하지 않는다.
- 준비 실패는 출발 전에 기록하고 종료한다. lifecycle 구성 정체 자체가 해결됐다고 간주하지 않는다.

## 벽 정렬 전 제한 보정 — 2026-11-02 사용자 승인

- 공통 인계 planner/navigation/factory: 벽 접근 상한 초과 3cm 이내·벽 방향 0.05rad 이내만 기존 WindowCorrection 0.01m/s로 1회 접근. 정상 범위에서는 보정 생략. 경로 길이 최대4.1cm, 정상범위 안쪽1cm 확보 목표.
- 전체 경로 충돌 검사, 이동 중 횡오차5mm/방향0.035rad, 벽 거리 예측15mm/법선0.035rad 일치 검사 및 정지 후 재측정. 원래 벽 목표/20cm 접근 제한은 그대로. 보정 실패는 반복하지 않는다.
- source 및 install의 handoff_planning.py/handoff_navigation.py/handoff_factory.py 일치 확인. 실물에도 같은 코드가 적용되며 실제 하드웨어 검증은 미실시.
