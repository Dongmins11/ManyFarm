# 로봇팔 담당자 전달안 — 농장 조건의 Teacher 성능 확인

필수 실행 파일이 누락된 상태는 아니다. 전달받은 정책4개·run.json·코드·자산으로 시뮬 연결과 실제 관절 제어까지 구현했다. 아래는 현재 농장 조건에서 적재 성공을 확보하기 위한 검토 요청이며, 새 학습·물성 변경·입력 위조를 이미 승인받았다는 의미가 아니다. 이 문서는 전송하지 않았다.

---

전달 Teacher를 농장 Isaac World에 연결했습니다. 기존 Nav2 도착/정지 후 팔을 실행하고, 오른팔 기준 과실 pose 및 실제 관절·TCP·손가락 접촉·줄기 상태로82D 관측을 구성합니다. 정책20Hz/활동 물리480Hz,9g 물성 및 원본 명령 보정 설정을 유지했습니다. 대상은 현재 정차의 근거리 빨강/노랑 각1회이며, 실제 복귀 뒤 다음 대상을 처리합니다.

현재 서로 다른 농장 과실3개에서 적재0개를 확인했습니다.

- Bed02/Pepper0031 yellow: ENTRY20초 시간 초과. 정상 복귀, 성공0/실패1.
- Bed05/Pepper0030 red: 양쪽 손가락 접촉 후 `bad_detach`. 총변위42.945mm 분리, 낙하, 정상 복귀.
- Bed01/Pepper0027 red: `bad_detach`, 낙하, 정상 복귀. 최종 후보/관절 실행/수량/정지/프로세스 종료 검사는 통과했으나 적재는 실패했습니다.

현재의 큰 좌표 변환 오류 근거는 없습니다. 실제401샘플과 원본 ArmKinematics의 TCP 최대차0.2921mm/0.052412°, 400정책 입력 CPU 재생의 stage/status 차이0입니다. 정책·run SHA를 검사하고 공식 RSL-RL ActorCritic의 정규화를 그대로 복원했습니다.

원본 CurrentPairEnv는 과실 root quaternion을 identity로 초기화하지만, 첫 농장 과실은 identity 대비127.62° 회전/수직기울기17.47°입니다. 가장 가까운 전달18개 점과8.781mm 차이도 있습니다. 실제 과실 위치·회전·ID를 유지했으며 quaternion을 임의로identity로 입력하거나 실패 기준을 느슨하게 바꾸지 않았습니다.

검토 부탁드릴 사항은 다음입니다.

1. 현재 Teacher가 농장처럼 비정규 회전·기울기·연속 위치의 과실까지 지원하는지, 아니면 전달18개/identity 배치에 한정되는지 확인 부탁드립니다.
2. 지원 범위에 들어간다면, 첨부 관측/접촉/분리 trace와 원본 실행의 동일 입력·관절 명령을 비교해 필요한 관측 계약 차이를 알려주세요. source의 병합 wrist camera 접촉과 농장 분리 body 접촉 집계 차이도 있습니다. 농장에서는 카메라 접촉을 arm_forces에 기록하며 손가락 force에 합산하지 않습니다.
3. 현재 조건이 범위 밖이라면, 농장 과실 pose·간격·9g 조건에서 평가한 Teacher 체크포인트/평가 설정 또는 필요한 재학습 조건을 부탁드립니다. 현재 전달 묶음을 다시 모두 보낼 필요는 없습니다.

자료는 `sim/runs/robotarm/teacher_integration_20261006/`의 검사 결과와 각 결과의 `teacher_log_dir`에 있습니다. `trace.jsonl`은 관절·TCP·과실 pose·접촉·분리 순간 증거·정책 단계/명령을 포함합니다. `analysis_attempt02/audit_trace.py`와`result.json`에 원본FK/CPU 재생과 입력 해시가 있습니다. 단계별 실제 성과와 source strict 성공은 따로 기록했습니다.

전체 Nav2 도착→팔→관제 결과 E2E와 실제 다중 과실 적재는 아직 검증하지 않았습니다. 이번 요청은 그 이전의 실제 파지·안착 성능 차이를 확인하려는 목적입니다.
