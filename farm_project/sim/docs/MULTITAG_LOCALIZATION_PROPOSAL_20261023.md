# 복수 태그 관측 공통 개선 — 2026-10-23 승인·적용

## 문제와 근거

베드의 평행한 긴 벽면은 LiDAR가 베드 길이 방향 위치를 구분하는 정보가 약하다. 동일 실제 scan을 지도에 대조한5cm 이동의 점수 변화는 X약3.7%, Y약0.13%였다. 실제 AMCL에 동일 정지scan/encoder와 기록된 추정 초기분포를 재생해도 정지 강제 갱신/360빔/좁은 센서 모델만으로 길이 방향 잔차가 없어지지 않았다. 정답은 재생 입력으로 사용하지 않았다.

현재 공통 `farm_tag_localization/observer.py`는 같은 영상에서 여러 태그를 처리하더라도 최종적으로 하나의 태그 packet을 선택한다. 약50픽셀의 단일 태그는 코너 오차·평면 자세 모호성의 영향을 받는다. 같은 영상에 보이는 여러 태그의 알려진 간격을 함께 이용하는 방법을 평가했다.

## 실제 로그를 이용한 사전 검증

재현: `sim/runs/localization_motion_20261023/multitag.py`, `multitag_live.py`. 운영 노드를 변경하거나 정답 좌표를 보정 입력으로 쓰지 않았다. 입력은 같은 영상의 검출 코너/K/등록된 태그 좌표/카메라 장착값뿐이다. PnP 후보는 재투영 오차로 선택하고 정답은 사후 오차 계산에만 썼다.

마지막 보수적 비교에서는 **기존 observer가 usable 후보를 만든 태그만** 묶고 기존 Hamming0/margin80 조건을 유지했다. 복수 PnP의 재투영 RMS≤1px인 표본의 동일 프레임 단일/복수 평균 절대 오차:

| 데이터 | 단일 X/Y | 복수 X/Y | 단일/복수 yaw |
|---|---:|---:|---:|
| 기존 태그 ON 01 | 16.7/25.3mm | 15.5/16.0mm | 0.870/0.563° |
| 기존 태그 ON 04 | 17.9/23.3mm | 11.4/13.2mm | 1.012/0.647° |
| 기하 태그 ON 05 | 14.1/21.7mm | 7.1/12.6mm | 0.861/0.565° |

이 수치는 **복수 관측을 만들 수 있던 일부 표본**이며 전체 구간/실물 성능을 뜻하지 않는다. 실제 자세는 기존1벽시계초 주기의 물리 진단을 보간했으므로 이동 중 평가에는 시간 보간 오차가 남는다. 기존 태그 일부 조건에서는 X개선이 작아 전체 품질 게이트와 fallback이 필요하다. 느슨한 후보 입력의 탐색 수치보다 위 표의 보수적인 수치를 기준으로 삼는다.

높이/roll/pitch를 강제로 고정하는 평면 해법도 시험했으나 이동 중 차체 기울기를 설명하지 못해 길이 방향 오차가 커졌다. **이 제안에서는 6D 태그 PnP를 유지하고 마지막에 기존 XY/yaw로 투영한다.**

## 구체적인 변경안

권장: 기존 관측기를 유지하면서 **같은 프레임·같은 active section의 복수 태그 관측 packet**을 추가하고, 품질 조건을 통과했을 때만 기존 AMCL 보정 계약으로 전달한다.

1. `robot/ros_ws/src/farm_tag_localization/farm_tag_localization/observer.py`
   - 기존 중복ID/등록/코너/품질 검사를 재사용한다. 임의의 관측을 합치거나 서로 다른 시각·구간을 섞지 않는다.
   - 등록 위치가 같은 평면에 있는2개 이상의 충분히 떨어진 태그의 코너를 기준 태그 좌표계로 변환하고 일반 IPPE+LM으로 함께 추정한다.
   - 두 자세 후보·모호성·재투영·높이·roll/pitch·거리 검사를 유지한다. 단순 평균이나 AMCL 현재 위치로 후보를 임의 선택하지 않는다.
   - 복수 관측이 부족하거나 품질/불확실성 검증에 실패하면 현재 단일 태그 관측을 그대로 사용한다.
2. `farm_tag_localization/runtime.py`와 환경별 observation model
   - 복수 관측용 model ID/보수적인 불확실성 계약을 구분한다. 태그 수만큼 공분산을 무조건 줄이지 않는다.
   - 기존 AMCL 보정 gain/최대 이동량/TF 소유권/Action 판정/주행 설정은 유지한다.
3. `farm_tag_localization/node.py`
   - 복수 관측에 단일 태그의 pixel-bias 보정을 잘못 적용하지 않도록 구분한다. 현재 OFF인 보정을 켜는 변경은 하지 않는다.
   - 원본 태그 ID 목록·전체/태그별 재투영 오차·후보/거부/fallback 이유를 로그로 남긴다.
4. 공통 단위/계약 시험
   - 태그 순서/회전/다른 구간/반복ID/코너 손상/부분 검출/모호성/관측 부족/단일 fallback/기존 packet 소비를 검증한다.

## 실물·시뮬 영향과 검증

- 공통 알고리즘으로 구현하며 sim 전용 분기나 복사 관측기를 운영에 넣지 않는다. 현재 단일 관측의 성공·실패 계약을 유지한다.
- 실물은 독립 측량된 태그 간격·장착값이 정확해야 한다. 잘못 등록된 태그를 묶으면 오히려 편향이 커질 수 있어 재투영/일관성 거부가 필수다.
- 기존 uncertainty model을 근거 없이 “더 정확해졌다”고 축소하지 않는다. 실물 활성화 범위/모델은 별도 검증 후 확정해야 한다.
- 승인 후 먼저 저장된 실제 영상/원시 코너로 전후 재생 검증, 다음으로 SEC01/SEC02 실제 예찰, 마지막으로 여러SEC 반복에서 최종 과실/윈도우 대응과 TF/105를 확인한다. 정답은 끝까지 평가 전용이다.

## 현재 상태

사용자 “예찰은 거리가 머니까 복수태그 적용해도 괜찮을듯 반영해봐”로 승인 후 공통 관측기에 적용했다. 시뮬 예찰 model_ids.tag_multi만 명시해 활성화하며 실물/수확 설정은 유지한다. 별도 모델 ID로 기존 단일 태그의 6D 공분산 상한을 그대로 유지하며 태그 수에 따른 축소는 하지 않는다. 실제 성능 향상의 통계적 검증을 마친 모델이라는 의미는 아니다.

구현은 기존 usable 태그만 정렬해 사용하며 동일 평면(법선/법선방향 위치 차이 1e-6 이내), 중심 간격 최대값이 태그 최대 변 길이의 2배 이상인 그룹을 계산한다. 전체/각 태그 RMS가 기존 한계를 통과하고 모든 태그의 거리 범위·차체 높이/기울기가 유효해야 한다. 서로 다른 공분산 모델이면 결합하지 않는다. 두 해가 남으면 로그에 유지하고 단일 관측으로 fallback한다. 단일 태그 pixel-bias는 복수 관측에 적용하지 않는다. AMCL 보정량·주행·Action 판정은 유지한다.

검증 원본 `sim/runs/multitag_validation_20261023`, 최종 검증 결과는 `sim/docs/changes/MULTITAG_IMPLEMENTATION_20261023.md`를 따른다. 정답은 사후 평가에만 쓰며 이 변경이 모든 정합 문제를 해결했다는 뜻은 아니다.
