# 시뮬레이션 파트 작업 규칙

기준: 2026-10-02 사용자 요청. 프로젝트 루트 `AGENTS.md`와 함께 적용한다.

## 수정 범위

- 시뮬 전용 작업은 이 `sim/` 디렉터리 안에서 수행한다.
- 환경·로봇 USD, 물리·충돌·장착 정보: `assets/`.
- 지도·그래프·Nav2·장치·예찰·비전 프로파일: `ros_ws/src/farm_sim_config/`.
- 가상 센서·구동·ROS 연결: `ros_ws/src/farm_sim_devices/`.
- Isaac 실행과 시뮬 전용 launch: `ros_ws/src/farm_sim_runtime/`.
- 데이터 생성·평가·시험 도구: `tools/`. 새 시뮬 전용 시험: `tests/`.
- 변경 이력·검토·시험 보고: `docs/`. 새 실행 결과: `runs/`.

## 공통 코드와의 경계

- 공통 로봇 미션·FSM·메시지·주행·검출 계산을 복제하여 별도 구현하지 않는다.
- 공통 API, launch 인자, 환경 설정 경로를 통해 시뮬 장치와 데이터를 선택한다.
- 공통 코드에 시뮬 전용 분기나 경로를 추가해야 한다면, 이유·최소 변경안·실물 영향·검증 방법을 정리한 뒤 사용자 승인을 받는다.
- `sim/` 밖에 있는 기존 시뮬 설정은 읽어 참고할 수 있다. 새 시뮬 프로파일을 `sim/`에 두고 기존 경로 선택 기능으로 연결하는 방식을 우선 검토한다. 기존 파일 삭제와 외부 호출 경로 변경은 별도 승인 대상이다.
- 실제 업무 정책 변경을 설정 조정으로 위장하지 않는다. 과실 ID 정책·윈도우 확정 시점·실패 처리·피드백 의미 변경은 공통 동작 변경으로 검토한다.
- 기존 구동기/센서 어댑터 이외의 새 시험용 더미는 시험에 한정하고 운영 동작과 구분한다.

## 데이터와 검증

- 현재 농장 8개 베드·16개 관측 면을 기준으로 확장성을 유지한다. ID·좌표·촬영점은 설정 데이터에서 읽는다.
- 2026-10-02 사용자 요청으로 기존 연결 데이터(v0.8.5)를 복원했다. 원본은 `task.yaml`과 `scout_harvest.geojson`이다. 좌표와 통로를 임의로 추가하지 않는다. 역할별 그래프와 예찰 설정은 `sim/tools/rebuild_route_data.py`로 생성하고 `validate_route_data.py`로 검사한다. station 시작 배치와 AMCL 초기 pose는 같은 원본에서 생성한다. 현재 예찰 주행은 실물과 동일한 follow_path/RPP로 설정한다. 환경별 지도·TF·센서 값은 각 환경에 둔다. 루트 문서의 16개 분리 성분 설명은 복원 이전 상태다.
- 시뮬 정답 좌표는 평가·디버깅에만 사용하며 공통 비전/제어 입력에 주입하지 않는다.
- 실물과 비교할 때 지도 ID, 구역 ID, TF, 카메라 해상도·주기·장착값, 모델 버전, 주행 모드의 차이를 기록한다.
- 수정 범위를 확인하고 필요한 기존 검사만 실행한다. 미실행 시험과 실제 장치 없는 시험의 한계를 명시한다.

## 변경 기록과 전달

- 모든 변경은 `docs/CHANGELOG.md`에 남긴다. 승인 없는 공통 변경은 적용하지 않고 `승인 대기`로 기록한다.
- 기록에는 대상 파일, 변경 이유, 승인 근거, 전후 동작, 실물 영향, 검증, 복원 방법을 포함한다.
- 변경 파일만 들어 있는 패치를 제공하고, 사용자가 다운로드 후 프로젝트에 압축을 풀 수 있는 Bash 명령을 함께 제공한다.
