원격 `origin/main:farm_project/sim/docs/PRESENTATION_VIDEO_REVIEW_20261104.md`의 02 지시를 기준으로 준비했다. 기존 영상·설정과 원본 USD·공통 코드는 변경하지 않았다. 아래는 정적 자산 분석과 GUI 미리보기 결과다. A/B/C 9장과 D probe 3장 몽타주를 직접 확인했다. D refined의 후속 GUI 검수와 최종 영상 촬영·검수까지 마쳤으며 아래 최종 선택 절에 기록했다.

장착 원본: `sim/assets/robots/scout_robot/scout_mount_20261013.usda`. 연결 코드: `sim/ros_ws/src/farm_sim_runtime/farm_sim_runtime/scout_mount.py`.

`install_scout_mount()`는 기존 렌더 카메라 `base_link/scout_camera`를 위 광학 프레임에 연결하고 ROS/USD 축 변환을 적용한다. 화면에 보이는 회색 Cube와 실제 렌더 Camera prim은 별개다. 표시용 Cube는 직접 정의되어 있으며 렌즈 메시의 instance 표시를 켜서 복구할 구조가 아니다.

기존 02 구도는 센서보다 서쪽에 있어 센서의 뒷면·측면이 강조됐다. 광학 앞면을 보려면 촬영 카메라를 센서의 동쪽에 두어야 한다. 그쪽에는 실제 작물 베드도 있으므로, 센서 앞면 가시성과 작물의 전경 가림 사이의 절충을 GUI 이미지에서 비교해야 한다.

## 후보 3개

| 후보 | 시작 eye → target | 초점거리 | 의도와 주의점 |
|---|---|---:|---|
| [a · front](settings/candidates/02_scout_a.json) | `(-5.70,6.80,0.65) → (-6.20,9.10,0.35)` | 48mm | 동남쪽에서 센서 앞면을 본다. 센서는 왼쪽, 작물은 오른쪽에 놓인다. 가까운 전경 작물이 프레임 가장자리를 가릴 수 있다. |
| [b · side](settings/candidates/02_scout_b.json) | `(-7.85,8.40,0.65) → (-6.40,8.85,0.33)` | 27.5mm | 서남쪽 측면에서 로봇 뒤로 작물이 이어지게 한다. 하우징의 돌출과 작물 방향은 읽히지만 광학 앞면은 반대쪽이다. |
| [c · bedend](settings/candidates/02_scout_c.json) | `(-3.60,12.30,0.67) → (-6.20,9.10,0.39)` | 88mm | 북동쪽 베드 끝에서 앞면을 본다. 먼 위치와 긴 초점거리로 로봇·작물의 화면 간격을 줄인다. 베드 끝의 잎·과실이 센서를 가리는지 확인해야 한다. |

- 기존 route edge `30128`과 차체 자세를 유지한다. 로봇은 `(-6.655,9.044947)`에서 남쪽으로 0.4m 이동한다.
- 카메라 eye·target은 남쪽으로 **0.28m**, 즉 로봇 이동량의 **70%**만 따라간다. 로봇이 화면 안에서도 0.12m 상당 전진한다.
- 광학 중심 0.595m를 참고해 촬영 높이를 0.65~0.67m로 낮췄다. 기존 0.84m에서 바닥을 강하게 내려다보던 방향을 완화했다.
- 마스트·차체의 단순 기하 투영을 사용해 높이 약 60~70%와 하단 여유를 맞춘 시작값이다. 실제 메시 경계와 렌더 투영의 최종 검증은 별도다. 자막 영역에 핵심 센서·과실이 들어가지 않는지도 이미지로 확인한다.
- 5초·30fps, 동작 1~4초, `preview_frames=[0,75,149]`, `preview_warmup_frames=48`로 맞췄다. 세 후보를 촬영하면 시작·중간·끝 9장으로 비교할 수 있다.
- 센서·광학 프레임·렌더 카메라·마스트를 `inspect`에 넣어 GUI 촬영 시 실제 월드 변환도 남기도록 했다.

## 선택 기준과 남은 한계

초기 기하 분석의 우선순위 c → a → b는 아래 실제 미리보기 비교로 갱신했다. 후속 GUI 비교를 거쳐 D refined를 최종 채택했다.

현재 자산에는 렌즈가 없으므로 구도를 바꿔도 사진처럼 명확한 카메라 외형을 만들 수는 없다. 센서 하우징·마스트·작물의 배치를 가장 잘 읽히게 촬영하며, 없는 렌즈를 추가하거나 센서·베드를 옮기지 않는다. 이 후보 생성 과정에서는 GUI 실행, 촬영 요청, 실제 예찰 시험을 수행하지 않았다.


## GUI 미리보기 확인과 D 보정

[후보 9장](qa/02_scout-candidates.jpg), [D probe 3장](qa/02_scout-probe.jpg)을 직접 확인했다.

- A: 센서 앞면은 보이지만 빈 바닥·하늘 비중이 크고 작물이 오른쪽 끝에 몰린다.
- B: 작물 배경은 좋지만 흰 마스트 뒤로 센서가 가려져 앞면을 설명하기 어렵다.
- C: 작물과 센서 관계는 읽히지만 끝 프레임에서 전경 베드 벽이 바퀴·하부를 가린다.
- D probe: 로봇과 베드 사이 통로에서 촬영해 센서 앞면·전체 로봇·작물 줄기를 함께 보여준다. 시작·중간·끝 모두 하부 가림이 없다. 로봇이 오른쪽에 치우쳐 목표점을 보정했다.

[D refined 설정](settings/candidates/02_scout_d_refined.json)은 probe의 `eye=(-6.05,10.20,0.65)`, 25mm를 유지하고 `target`만 `(-6.25,9.05,0.40)`으로 옮겼다. 시작 대비 마지막 eye·target은 모두 남쪽으로 0.28m 이동한다. 원래 로봇 이동 0.4m와 바퀴 회전은 그대로다. 촬영점과 로봇 모두 베드 서쪽 벽 `x≈-5.475`보다 서쪽에 있어 카메라에서 로봇으로 향하는 시선이 벽을 가로지르지 않는다.

단순 차체·마스트 투영으로 예상한 로봇 영역(1920×1080):

| 시점 | 픽셀 경계 `(left,top,right,bottom)` | 화면 높이 비율 |
|---|---|---:|
| 시작 | `(1190,288,1570,1002)` | 66.1% |
| 중간 | `(1172,286,1531,967)` | 63.0% |
| 끝 | `(1156,285,1495,936)` | 60.2% |

이 경계는 실제 USD 전체 메시 경계가 아닌 보수적인 근사 투영이다. D refined의 센서 가시성·작물 배치·프레임 하단 여유는 아래 최종 GUI 검수에서 확인했다. 모든 후보는 기존 경로를 재현한 연출 촬영이며 실제 예찰 성능 시험 결과가 아니다.

## 최종 선택 및 촬영 검수

D refined의 시작·중간·끝과 시작1080p 이미지를 root가 직접 열어 확인한 뒤 채택했다. 최종 MP4 0/30/60/75/90/99/105/119/149프레임을 추출해 마스트·센서·바퀴가 동작 끝까지 보임을 확인했다. 작물은 센서 앞쪽인 화면 왼쪽에 배치되며, 로봇 뒤 전체를 작물로 채우는 구도와는 차이가 있다. 통로 바닥과 외곽 배경은 일부 남는다. 규격·전체 디코딩 검증은 README와validation.txt 참조.
