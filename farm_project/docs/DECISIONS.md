### D-017 — 전달 Teacher를 시뮬 전용으로 연결 (2026-10-06)

- **사용자 확정 범위:** “대부분의 로봇팔 구동 코드가 시뮬레이션 전용 … 공통코드에서 도착하자마자 result를 날리는 형태면, 그부분은 수정해서 sim 전용 로봇팔 동작 코드에 연결”. D-016의 넓은 공통 Window 실행기·신규 후보조회/PickFruit 제안은 채택하지 않는다.
- 공통 harvest_robot은 기존 Navigator의 도착/정지 확인 후 설정된 내부 HarvestTask Action을 요청하고, 누적 피드백·실제 결과·취소 정지를 전달한다. 외부 HarvestTask 필드, farm_interfaces, 실물 설정·주행·비전은 유지한다. legacy ARRIVAL_ONLY_NO_HARVEST도 명시적으로 유지한다.
- sim의 별도 `sim/harvest_arm` endpoint는 기존 형식을 재사용한다. 지역 과실 활성화, 현재 팔 TF 기준 정답 좌표, 실제 접촉 관측, 4개 Teacher 추론, 물리 복귀·성공 판정·대상 순서는 모두 sim에 둔다. 정답 사용은 이번 Teacher에만 허용한다.
- 현재 정차의 연속 근거리 조건을 만족하는 빨강/노랑을 각1회 시도한다. 녹색·추가 차체 이동·실패 재시도는 하지 않는다. 일반 실패는 실제 복귀/집게 열림 확인 후 계속하며 접촉·이웃 분리·정지 미확인은 작업을 중단한다. `SUCCESS`는 후보 전체 처리 완료이고 수량은 실제 안착/실패 수다. 예상 수량 달성 자체를 성공으로 꾸미지 않는다.
- 현재 과실의 실제 충돌 외곽·바구니 내부·저속·손가락 비접촉·0.6초 안착을 성과로 집계한다. Teacher 엄격 성공은 별도 진단이다. 앞서 안착한 과실이 탈출하면 `FAILED/PREVIOUS_DEPOSIT_LOST`; 이미 발행한 누적 수량은 역행시키지 않는다.
- 상세 구현·실행·직접 검증/미검증은 [시뮬 Teacher 실행 보고서](../sim/docs/TEACHER_HARVEST_RUNTIME_20261006.md)를 따른다. main/1666a23 이후 미커밋이며 이번 변경의 커밋·푸시는 요청받지 않았다.

- 성공 예찰의 전체 window 순서·ID·좌표·expected_count를 캐시에 저장하고 수확 실패 후 재사용한다. 전체 Isaac/ROS 재시작으로 과실도 초기화되므로 W001부터 해당 SEC의 모든 window를 다시 수확한다. 예찰이 실패했거나 성공 데이터가 없으면 예찰부터 실행한다.
- 수확 재시도는 예찰 Action/예찰 로봇 준비를 기다리지 않는다. 시뮬 스택 구성, 공통 Action·주행·수확 성공 판정은 유지한다. 캐시는 캠페인별로 분리하며 지도 변경 시험은 새 캠페인에서 시작한다.
- Domain13/SUBNET, 실패 원본 보존, SEC별 성공까지 재시도 후 SEC02~16 진행. 현재 SEC01 시도는 중단하지 않고 완료 후 같은 캠페인을 `--resume`으로 확장한다. 전체16SEC 성공 후 자동 종료하며 실제 완료 여부는 summary/result를 따른다.


### D-051 — 수확 실적 실패와 Action 실패 분리, 영상 재시도·성능 집계 (2026-10-21)

- 승인: 사용자 비대상 과실 이탈/시뮬 ID 연결을 Action 실패로 삼지 말고, 60초 실패 시 카메라 탐색부터1회 재시도 후 넘어가라는 지시. 예찰/수확 성능은 실제 시뮬 대상·예찰 expected·레이저 harvested를 분리한다. 이번 변경은 sim 안의 어댑터/시험 도구/환경 설정 및 전달 미션의 opt-in 복귀 기능에 한정한다.
- 영상 목표는 시뮬 ID 연결 여부와 무관하게 실행한다. 연결 불명/중복/모호/평가 조회 예외는 진단이다. 레이저 통과 계수에 실제 물체 ID를 요구하지 않는다. 알려진 비대상 과실 이탈·목표 낙하/이탈은 성능 사건으로 기록하며 즉시 Action을 실패시키지 않는다. ID 불명 중의 분리는 비대상임을 확정하지 않고 detachment_identity_unresolved로 구분한다.
- 과실별 수확 시작→박스 확인 제한은60시뮬초다. 시간초과 시 기존 측정 복귀 경로로 팔을 접고3시뮬초 새 카메라 관측을 한다. 영상 목표끼리 기존 카메라 추적 기준으로 재연결하고 최대1회 더 시도한다. 재관측에서 대응 대상이 없거나 모호하면 수확 실패로 기록하고 다음 대상으로 간다. 재시도도60초 초과면 해당 대상의 failed_count를1회 올리고 남은 대상으로 간다. 이미 성공한 대상/수량은 유지하며 남은 목록을 버리거나 재시도 횟수를 초기화하지 않는다.
- 실제 주행·통신/관절 피드백·복귀/정지 실패는 Action 실패로 유지한다. 팔 접촉 안전은 과실 ID별 힘 분리 대신 실제 팔/손가락 net force로 검사하여 평가 연결 여부가 정지 기준을 바꾸지 않게 한다. 목표별 실적 실패가 있어도 전체 복귀·정지 완료 후 SUCCESS다.
- 수확 전 scene snapshot 및 기존 작업면/높이/경로 범위의 red/yellow 정답을 성능 평가에만 사용한다. 개수 비율 expected/actual, harvested/expected, harvested/actual은 객체별 정밀도/재현율과 구분한다. 예찰의 정답 누락/중복/미대응·색 분류는 기존 오프라인 매칭 결과를 함께 기록한다. 실패 시도별 자료는 보존하되 SEC 최종 실적에 재시도 수확을 중복 합산하지 않는다.
- 시험 준비의 ROS 설정 복사20벽시계초 초과/명령 실패는 diagnostic_error로 기록하고 준비된 로봇의 시험은 계속한다. 느린 sim의 다중 대상 재시도가 기존30분 외부 제한에 잘리지 않도록 sim 팔 watchdog7200초, 상위 팔 대기7260초, 시험 window 대기7500초로 조정한다. 과실별60초와 통신 freshness/진행105 조건은 그대로다. 실물 설정/공통 메시지 변경은 없다.
