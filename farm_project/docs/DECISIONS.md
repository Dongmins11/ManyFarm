### D-017 — 전달 Teacher를 시뮬 전용으로 연결 (2026-10-06)

- **사용자 확정 범위:** “대부분의 로봇팔 구동 코드가 시뮬레이션 전용 … 공통코드에서 도착하자마자 result를 날리는 형태면, 그부분은 수정해서 sim 전용 로봇팔 동작 코드에 연결”. D-016의 넓은 공통 Window 실행기·신규 후보조회/PickFruit 제안은 채택하지 않는다.
- 공통 harvest_robot은 기존 Navigator의 도착/정지 확인 후 설정된 내부 HarvestTask Action을 요청하고, 누적 피드백·실제 결과·취소 정지를 전달한다. 외부 HarvestTask 필드, farm_interfaces, 실물 설정·주행·비전은 유지한다. legacy ARRIVAL_ONLY_NO_HARVEST도 명시적으로 유지한다.
- sim의 별도 `sim/harvest_arm` endpoint는 기존 형식을 재사용한다. 지역 과실 활성화, 현재 팔 TF 기준 정답 좌표, 실제 접촉 관측, 4개 Teacher 추론, 물리 복귀·성공 판정·대상 순서는 모두 sim에 둔다. 정답 사용은 이번 Teacher에만 허용한다.
- 현재 정차의 연속 근거리 조건을 만족하는 빨강/노랑을 각1회 시도한다. 녹색·추가 차체 이동·실패 재시도는 하지 않는다. 일반 실패는 실제 복귀/집게 열림 확인 후 계속하며 접촉·이웃 분리·정지 미확인은 작업을 중단한다. `SUCCESS`는 후보 전체 처리 완료이고 수량은 실제 안착/실패 수다. 예상 수량 달성 자체를 성공으로 꾸미지 않는다.
- 현재 과실의 실제 충돌 외곽·바구니 내부·저속·손가락 비접촉·0.6초 안착을 성과로 집계한다. Teacher 엄격 성공은 별도 진단이다. 앞서 안착한 과실이 탈출하면 `FAILED/PREVIOUS_DEPOSIT_LOST`; 이미 발행한 누적 수량은 역행시키지 않는다.
- 상세 구현·실행·직접 검증/미검증은 [시뮬 Teacher 실행 보고서](../sim/docs/TEACHER_HARVEST_RUNTIME_20261006.md)를 따른다. main/1666a23 이후 미커밋이며 이번 변경의 커밋·푸시는 요청받지 않았다.

### D-032 — 공통 구현 한 벌과 변경 가능한 환경 데이터 (2026-10-14)

- 사용자 “같은 코드를 쓰는 것”, “동일한 파일을 읽어오는 형태”, “설정값은 … 데이터는 바꿀 수 있어야” 및 “sim 디렉토리는 … sim 전용 파일만” 지시가 기준이다. 공통 구현을 복사해 동기화하거나 설정값의 변경을 일괄 금지하는 방식으로 해석하지 않는다.
- 주행·시작/완료/실패 판정·작업 단계·태그 관측/보정 구현은 `robot/ros_ws/src/`의 공통 패키지가 소유한다. 두 환경은 같은 Python 모듈과 Nav2 구현을 실행한다. `sim/`은 Isaac/가상 센서/구동/시계 연결, 시뮬 자산·환경 데이터·실행 조합·검증만 소유한다. 실물 장치 연결은 `farm_real_devices` 및 해당 장치 도구가 소유한다.
- 기본 주행 데이터는 `robot/config/navigation/`을 한 원본으로 참조한다. Nav2 환경 파일은 `shared_nav2` + 장치 `bindings` + 선택적 `overrides`, 상위 환경은 `navigation_policy` + `navigation`, 수확 작업은 `task_navigation_policy` + 로컬 설정을 읽는다. 공통 병합기는 중첩 객체를 병합하고 리스트·스칼라는 교체하며 원본을 바꾸지 않는다. 속도·허용치·시간 등은 코드 수정 없이 바꿀 수 있다. 알고리즘 변경은 환경별 코드 복사/분기 대신 공통 구현에 적용한다.
- 태그 ROS 검출 연결/Journal 기록/검출 메시지 변환은 `farm_tag_localization` 한 벌을 재사용한다. 관측모델도 공통 원본을 읽고 센서별 수치는 `shared_model_file` + `overrides`로 지정한다. 기존 sim import와 BT/모델 경로는 호출 wrapper 또는 심볼릭 링크로 호환하며 구현 원본을 복제하지 않는다.
- 현재 수확 기본값은 전달 `bf10fcd`의 RPP/SimpleGoalChecker 및 진입·작업 끝점 추종 설정을 기준으로 정렬했다. 이전 실험 Settling/Stopped 플러그인은 소스/호환 시험을 보존하지만 운영 기본값에서 선택하지 않는다. D-029 종료 잔차 비차단과 D-030 예찰 현재 위치 기준 RPP 판단은 공통 구현/설정으로 유지한다. 이는 기존 실패 전부의 해결이나 실물 재검증 완료를 뜻하지 않는다.
- 실물 PiCam 교정·태그 등록과 실제 모터 드라이버/펌웨어 소스·응답 검증은 미확보다. 시뮬의 교정값이나 휠 PI를 실물 검증값으로 취급하지 않는다. 구현 파일 공유와 장치 응답의 일치는 별도로 검증한다. 실제 확인 범위는 PROJECT_STATE §52와 실행 기록을 따른다.
