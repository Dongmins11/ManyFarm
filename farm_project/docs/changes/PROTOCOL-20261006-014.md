# 관제 통신규약 반영 — 2026-10-06

사용자 승인: “관제쪽에서 통신규약이 수정됐어 반영해줘”.
기준: 사용자가 첨부한 `farm_interfaces.zip` 전체. 공통 코드 변경 범위는 아래와 같다.

## 변경 내용

| 항목 | 반영 |
|---|---|
| ScoutArea Goal | `section_ids[]` → `section_id`. 한 Goal당 한 Section |
| ScoutArea Result | `section_id`, `harvest_tasks[]` 추가. `completed_section_ids` 제거 |
| ScoutArea Feedback | `completed_section_count` 제거. 진행만 통지 |
| SECTION_COMPLETE | 빈 작업 배열, 빈 segment_id, segment_expected_count=0 |
| HarvestTask 메시지 | task_id / window_id / goal_pose / expected_count 네 필드 |
| HarvestTask 서버 | 삭제된 Section/Segment/sequence 참조 제거. Window ID는 비어 있지 않은 식별자로 취급 |
| 수확 완료 | 도착 후 SUCCESS, harvested_count=0, failed_count=0 유지. 받은 window_id 그대로 반환 |
| 여러 Section 테스트 | `control/scripts/send_scout_area.py --section SEC01 SEC02`가 단일 Goal을 순차 전송 |

예찰은 각 Segment의 관측 결과를 저장한 후 해당 시점의 Window 목록을 확정한다. 정상 완료 Result는 최종 배열을, 실패/취소 Result는 마지막 저장 성공 시점의 부분 배열을 담는다. 배열 순서를 유지하며 task 수와 expected 합계를 실제 전송 배열에서 계산한다. SECTION_COMPLETE 피드백으로 수확 작업을 등록하면 안 된다. 최종 Result 실패·취소 시 부분 목록은 관제에서 보관하되 자동 수확 전송은 보류한다.

내부 survey.json에는 분석용 Section/Segment/sequence 정보를 유지할 수 있지만 ROS HarvestTask에는 보내지 않는다. 기존 세션 접두사가 붙은 Window ID도 그대로 송수신하므로 수동으로 SEC01_G01_W001로 바꾸는 절차가 필요 없다.

## 수정 위치

- `robot/ros_ws/src/farm_interfaces/`: 첨부 패키지와 동일한 정의·예제.
- `robot/ros_ws/src/scout_robot/scout_new/`: 현행 상태 기반 예찰 서버.
- `robot/ros_ws/src/scout_robot/scout_robot/task_messages.py`: 내부 Window → 공통 Task 변환.
- `robot/ros_ws/src/scout_robot/scout_robot/survey_server.py`: 이전 직접 실행 서버의 동일 규약 호환.
- `robot/ros_ws/src/harvest_robot/harvest_robot/contract.py`: 수확 입력 검사.
- `control/scripts/send_scout_area.py`: 프로젝트에 포함된 임시 예찰 클라이언트.
- `sim/tools/harvest_smoke_goal.py`, `sim/tests/test_harvest_motion.py`: 시뮬 전용 Goal/검사.

실물·시뮬 공통 서버에 함께 적용된다. 장치 연결부, 경로 계산/FollowPath 설정, 모델 경로, 지도, station, Isaac 런타임, 마찰 수정 USD는 이 패치에 포함하지 않는다.

## 인터페이스 포함과 실행 기능의 구분

- RobotStatus.msg의 boot_id/sequence를 포함하여 첨부 파일 그대로 추가했다. 현재 확보한 예찰·수확 서버에는 RobotStatus 발행기가 없으므로, 메시지 정의 추가만으로 상태 토픽이 발행되지는 않는다. 관제가 Status 필수 모드라면 상태 발행 구현이 별도로 필요하다.
- GetHarvestTasks.srv는 첨부본대로 보존한다. 이번 Result 기반 흐름은 서비스를 생성/호출하지 않는다.
- 외부 관제 프로그램 소스는 제공받지 않았다. 해당 프로그램은 관제 측에서 동일 인터페이스로 재빌드해야 한다. 프로젝트 안의 임시 예찰 클라이언트만 함께 수정했다.
- 첨부 VALIDATION.md에 적힌 관제 측 시험 횟수는 전달받은 기록이며, 아래 로컬 검증 결과와 구분한다.

## 적용 — 백업, 압축 해제, 빌드

실행 중인 Isaac, 로봇 bringup, 관제 노드를 종료한다. 패치 ZIP을 `~/Downloads`에 다운로드하고 실행한다.

```bash
cd ~/main/farm_project &&
mkdir -p backups &&
tar -czf "backups/protocol_before_$(date +%Y%m%d_%H%M%S).tar.gz" \
  robot/ros_ws/src/farm_interfaces \
  robot/ros_ws/src/scout_robot \
  robot/ros_ws/src/harvest_robot \
  control/scripts sim/tools sim/tests &&
unzip -o "$HOME/Downloads/farm_protocol_update_20261006.zip" -d "$PWD" &&
date -Is >> docs/changes/PROTOCOL-20261006-014-applied.log &&
sha256sum "$HOME/Downloads/farm_protocol_update_20261006.zip" >> docs/changes/PROTOCOL-20261006-014-applied.log &&
source /opt/ros/jazzy/setup.bash &&
bash scripts/build.sh sim &&
source scripts/env.sh sim &&
python robot/ros_ws/src/farm_interfaces/examples/verify_interfaces.py
```

이 ZIP은 변경 파일만 포함한다. 현재 로컬에서 동일 Python 파일을 추가 수정했다면 백업본과 비교해 병합해야 한다. 실물 로봇에서는 동일 공통 패치를 적용하고 `bash scripts/build.sh real`, `source scripts/env.sh real`을 사용한다.

검증 스크립트가 PASS를 출력한 뒤 재실행한다. 기존 서버 프로세스와 관제 터미널도 종료·재시작하고 각각 새 install을 source해야 한다. 이전 메시지 타입을 쓰는 프로세스와 혼용하지 않는다.

```bash
ros2 launch farm_sim_runtime all.launch.py \
  project_root:="$PWD" \
  isaac_python:="$HOME/isaac/env_isaaclab/bin/python" \
  device:=0
```

다른 robot_venv 터미널에서 예찰 실행:

```bash
cd ~/main/farm_project
source scripts/env.sh sim
python control/scripts/send_scout_area.py --section SEC01
```

새 수확 Goal 예시(팔 작업 없이 이동 확인, 성공 수량 0):

```bash
ros2 action send_goal /harvest_01/harvest_task farm_interfaces/action/HarvestTask \
"{robot_id: harvest_01, map_id: farm_map_v1, harvest_task: {task_id: HARVEST_PROTOCOL_TEST_01, window_id: c1167c0c9631_SEC01_W001, goal_pose: {frame_id: map, position: {x: -5.95, y: 8.322783439653392, z: 0.0}, yaw: -1.5707963267948966}, expected_count: 1}, timestamp: '$(date -Iseconds)'}" \
--feedback
```

이 예시는 기존 첫 window 좌표를 사용하는 수동 시험이다. 실제 연동은 이번 예찰 Result의 Task를 변경 없이 전달한다. 성공한 task_id를 재사용하면 서버의 중복 작업 검사로 거절되므로 다른 task_id를 사용한다.

## 검증

- 새 정의에서 필드 목록을 읽어 생성한 slots 기반 ROS 대역으로 예찰 결과·목록 순서·합계·실패/취소 부분 결과·저장 실패·피드백·수확 Goal 검사 6개 통과.
- 기존 수확 계약/상태/취소 및 sim audit 독립성 회귀 검사 9개 통과.
- 변경 Python 파일 문법 검사 통과.
- 기존 시험 모듈의 전체 로딩에는 확보하지 못한 `tests/test_launch_composition.py`가 필요하여, 해당 launch 검사와 무관한 ContractTests/AuditTests만 분리 실행했다.
- ROS 2/Isaac 런타임이 없어 실제 colcon 빌드, 생성 메시지 CDR 왕복, ROS 네트워크 연동은 여기서 미실행. 위 적용 명령에 첨부 원본의 생성 타입/CDR 검사 스크립트를 포함했다.

수확 이동/마찰 보정은 사용자가 이번 메시지에서 정상 이동을 확인했다. 이번 프로토콜 패치는 해당 USD를 수정하지 않는다.

## 롤백

실행 중인 노드를 종료하고 적용 전에 만든 백업을 프로젝트 루트에 복원한 뒤 다시 빌드한다.

```bash

tar -xzf backups/protocol_before_<백업시각>.tar.gz -C "$PWD"
bash scripts/build.sh sim
source scripts/env.sh sim
```

새로 추가된 보조 파일은 기존 소스에서 참조하지 않으므로 남아 있어도 구버전 실행에는 영향을 주지 않는다. 새로 생성된 인터페이스 산출물까지 완전히 제거해야 한다면 별도의 깨끗한 워크스페이스에서 구버전을 빌드한다.
