# 정지 후 도착·도킹 진입 오차의 공통 복구 — 2026-10-30

## 승인·범위

사용자 “공통코드에서 재발하지않게 조치한다음 커밋” 승인. 기준 main3993790 및 진행 중 시뮬/기존 미커밋 변경 보존. 대상은 논의한②벽 정렬과④주행→도킹 진입 전 거리 불일치다. 기존 실물/시뮬 허용값, 도킹 목표, 충돌 검사와 속도 제한을 변경하지 않는다. 공통 로봇 패키지에서 양 환경에 적용한다.

정지 후 재검사는 유지한다. 이전 시점의 통과 결과를 재사용하거나 범위 밖을 성공으로 바꾸지 않는다. 복구 가능한 두 상황만 최초 시도 후 최대2회 재시도하며, 영구적인 물리·센서 오차까지 성공을 보장하지 않는다.

## ② 벽 정렬

- `farm_navigation/arrival.py`, `navigator.py`: Nav2 종료와 정지 확인 이후 별도 도착 판정기가 accepted=false를 반환한 경우만 `ArrivalValidationError`로 구분한다. 측정값·정지 표본 시각을 보존한다. 기존 RuntimeError 하위형으로 기존 실패 처리와 호환된다.
- `harvest_robot/handoff_navigation.py`: wall 단계에서만 이 오류를 처리한다. 출력 차단/자신의 Goal 종료/정지를 확인하고, 원래 reference로 현재 벽·odom을 다시 읽어 새 계획·충돌 검사를 수행한다. 기존 원호 출발/복귀 전체를 재실행하지 않는다.
- 최초+재시도2회 모두 실패하면 실패 유지. 취소, 충돌, TF/센서 오류, 제어권·정지 확인 실패, 다른 단계 실패는 이 복구로 삼키지 않는다.
- 원래 측정은 navigation log에 `STOPPED_ARRIVAL_REJECTED`(attempt, retry, measurement, stamp_ns), 재시도는 `WALL_REALIGN_RETRY`로 남긴다.

## ④ 도킹 진입

- `farm_docking/staged_dock.py`: 기존 distance_corridor의 거리 거절에 관측 stamp/거리/기존한도를 저장한다. 새 업데이트에서 이전 거절을 초기화해 미검출·다른 마커·다른 실패에 재사용하지 않는다.
- `precision_server.py`: route_handoff 선택 프로필의 ACQUIRE 상태에서 현재 액션 시작 뒤 신선한 관측이 거리 한도를 초과하고, 정지 상태이며 초기 탐색/진입 이동을 시작하지 않았을 때만 재접근을 요청한다. 거리가 먼데 후진 탐색을 시작하지 않는다. 임의 전진 명령도 만들지 않는다.
- 정밀 액션은 기존 정지 절차와 lease 해제를 마친 뒤 ABORTED로 종료한다. 정지·해제 성공, 취소 아님, 정리 오류 없음이 모두 확인된 경우에만 내부 결과의 `APPROACH_REENTRY_REQUIRED: ` 식별자를 전달한다. 외부 관제 action/message 필드는 변경하지 않는다.
- `clients.py`는 이 식별자와 ABORTED/stopped를 함께 검사하고 자신의 종료 참조를 정리한 뒤 `ApproachReentryRequired`를 전달한다. 정리 실패는 일반 실패로 바뀌어 Nav2 재출발을 차단한다. 결과 도착 시점의 취소도 우선 확인한다.
- `transport_robot/states/transfer_states.py`, `transport_state_controller.py`: 초기 수령 접근 단계에만 복구를 연결한다. 접근 전 정지 증거가 있는 경우 접촉 저널을 해제하고 원래 `NAVIGATION_MOVE` 상태로 전환한다. 기존 그래프/목표로 다시 계획하고 충돌검사를 거쳐 이동한다. 재접근은 작업당 최대2회이며 새 작업에서만 초기화한다. 최종 도킹/인계/선별 실패를 통째로 재실행하지 않는다.
- 재접근 거절 이유/시도 번호는 업무 저널 `APPROACH_REENTRY_REQUIRED`에 남긴다. 실제 정밀 접근 성공 후에만 WAIT_DOCK_READY로 넘어간다. 한도 소진/다른 오류는 기존 실패 처리한다.

## 커밋 범위·후속

이번 커밋은 이 공통 복구와 회귀검사·기록만 묶는다. 앞서 작업한 실물 설정 정합/TF 대기/스테이션 복귀/촬영/시험 순서 등의 다른 미커밋 변경과 사용자 Frontend/Robotarm_update는 보존한다. 원격 push는 이번 요청 범위에 없다.
