## Costmap 및 태그 시각 문제

inflation_radius=0.7 / cost_scaling_factor=3.0, footprint x±0.35/y±0.30m와 padding0.01m를 변경하지 않았다. 넓은 색칠 영역 전체가 통행 금지는 아니다. 실제 장애물 셀의 근접과 회전의 관계를 먼저 검증한다. 차체 실측/장착 TF 오류가 확인되면 그 근거로 설정을 정정하며 통과를 위해 실제보다 작은 footprint를 사용하지 않는다.
태그 수신11회 및 AMCL 미래 TF 조회 경고가 있었으나 제공 자료에는 adapter events.jsonl이 없다. bag initialpose/TF를 분석할 수 있지만 태그별 기하 계산의 상세 진단은 해당 세션 이벤트가 필요하다.
주행 중 보정 TF 시간 정합성, 보정 전후 방향 명령 변화, 실제 벽 간격을 별도로 검사한다. 현재 단계에서 AMCL/드라이버/보정 계산은 변경하지 않았다. 최종 시각을 임의로 바꾸지 않는다.

## 현장 검증 순서와 종료 조건

1. PC 검사→로봇 해당 파일 동기화→harvest_robot 빌드→check_runtime --ros→launch 재시작. HarvestWork 등록/True/.4/True 확인.
2. 녹화 후 이전과 유사한 출발 자세에서 목표14 한 번. 진입/작업 제어기, 마지막 반대 회전, 도착위치·방향 및 정지, 충돌 상태를 확인한다.
3. 단일 목표가 확인된 후 실제 사용 구간 안의 연속 작업 좌표를 보내 모든 목표에서 정지·완료와 다음 목표 선택을 확인한다. 실패 중 다음 Goal 자동 전송 금지.
4. 태그 보정 효과는 실제 간격과 주행 중 횡방향/방향 오차를 함께 평가한다. AMCL 추정오차를 실측 정확도로 표기하지 않는다.
실물 ARRIVAL_ONLY_NO_HARVEST는 팔 작업 검증을 포함하지 않는다. 이번 패치로 벽 간격 보장·TF 경고 해결·카메라 종료 오류 해결을 주장하지 않는다.
