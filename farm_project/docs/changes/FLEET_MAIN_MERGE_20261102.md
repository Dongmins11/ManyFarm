## 발견해서 수정한 병합 문제

1. **중복 함수가 main 처리를 덮어씀**: Nav2Client의 경로 제한시간·정지 함수가 중복되는 충돌을 제거. 수확 인계 전용 pause clock을 선택하면 원래 단계 제한시간을 유지한다.
2. **예찰 기동 변경이 수확에 전파됨**: 공용 `scout_navigation.launch.py`는 수확도 사용한다. 초기 TF 후 Nav2 활성화는 `wait_for_localization` 명시 인자로 분리하고, 실물 예찰 launch만 켠다. 공통 기본 기동 및 시뮬은 유지한다.
3. **route_preview 기본 변경의 전파**: 실물 예찰 launch만 끄고, 공용 launch의 기존 기본 표시 동작은 유지한다.
4. **공통 복귀 API 충돌**: main의 client_factory, _run_mission/_cleanup_mission/_mission_docked 경계와 수확 subclass 호출 계약을 보존했다. 예찰 전략은 config 선택으로 조립한다.
5. **새 lifecycle 조회 client 정리 누락**: Nav2Client.close에서 생성한 lifecycle clients도 해제하도록 보완했다.
6. **시험이 잘못된 지도를 참조**: 예찰 복귀 시험은 `many_farm` 대신 실제 `scout_real` 그래프를 읽도록 수정. 지도 자체는 변경하지 않았다.
7. **구형 시험의 시계·RPC 대역**: 운송 회귀시험의 대역을 main의 motion_time/operation_time API에 맞췄다. 성공·실패·정지 확인 기대값은 그대로 유지했다.
8. **시험 실행 환경 누락**: 운송 프로토콜 시험 시작 전에 빌드 overlay를 로드하도록 수정. 소스 검사를 설치 복사본 검사로 대체하지 않았다.

## 반드시 구분할 연동 조건: 지도 좌표계

**코드가 함께 빌드되는 것과 세 로봇이 같은 지도에서 바로 협업하는 것은 다르다.**

| 선택 | map_id | 그래프 예시: 11번 / 14번(m) |
|---|---|---|
| main 수확 기본 | many_farm_v1 | (1.188,-1.020) / (1.188,-4.020) |
| 현재 실물 예찰 | farm_map_v1 | (1.046,-0.035) / (3.576,-0.035) |
| 현재 실물 운송 | farm_map_v1 | (1.046,-0.035) / (3.576,-0.035) |

예찰·운송도12번과20번 등의 역할별 노드가 다르다. 역할별 그래프 사용은 보존했지만, 관제 노드 번호·경로 계약까지 모두 같다고 해석하면 안 된다.

main 수확에 예찰의 목표 좌표를 그대로 넘기는 전체 통합 운전은 아직 확정할 수 없다. 다음 중 기준을 먼저 정해야 한다.

- 현재 현장 지도에 맞춘 **수확 전용 환경 프로파일**을 별도로 준비하고, 태그 지도·초기위치·작업 자세·station·관제 map_id까지 함께 맞춘다.
- 또는 main 수확 지도를 전체 기준으로 선택하고, 예찰·운송 설정과 실측 티칭/벽 기준을 다시 검증한다.

이번에는 검증 없이 지도 이름만 같게 바꾸거나 좌표를 임의 회전/이동시키지 않았다. 기존 실물 동작을 보존하라는 범위에 맞춰 원본 설정을 남겼다. 이 선택은 3로봇 통합 운전 전 해결할 항목이다.

## 재현과 전달

저장소 루트에서:

```bash
bash scripts/build.sh
bash scripts/verify.sh
```

빌드는 공백 없는 `/tmp/fleet_main_integration_20261102_build`를 기본 사용한다. 로봇 소스 폴더를 덮어쓰지 않는다. 재부팅 등으로 /tmp가 비면 다시 빌드해야 한다. 오프라인 nlohmann 의존성은 `deps/`에 있다.

향후 로봇 배포를 별도 승인한 다음 해당 로봇에서 선택할 명령은 기존과 같은 `scripts/bringup.sh scout current`, `scripts/bringup.sh transport current`이다. **이번에 이 명령은 실행하지 않았다.** 현재 로봇 alias는 이 새 폴더를 가리키지 않는다.

로컬 진단은 `reports/build.log`, `verification.log`, `isolated_final/`, `main_baseline_final/`, `failure_comparison.json`, `file_decisions.json`에 있다. 보고서/빌드 출력은 Git 제외, 재현 테스트와 지도 기준 해시는 `tests/`에 유지한다. 불필요한 옛 시험용 운전 도구는 이번 추가 대상에서 제외했다.

이 저장소는 main의 대용량 시뮬 자산·발표자료를 제외한 부분 체크아웃이다. 제외 파일은 Git에 그대로 존재하며 삭제한 것이 아니다. 시뮬 전체 실행이나 전체 자료 전달에는 해당 자산을 추가 체크아웃해야 한다.
