# 윈도우 복귀 기반 구현 — 2026-10-21 KST

기준 원격: `8df5f8eab87d450c675587b0be38ed85e3866a2e`.
승인: 기존 곡선 제어기 확장, 윈도우 위치 2cm·저장 방향 1°를 초기 기준으로 진행. 사용자가 진행하며 실물 확인하기로 승인했다.

## 이번 변경

- farm_arc_controller: 기존 플러그인에서 양의 원호는 후진 좌회전, 음의 원호는 전진 우회전. 별도 제어기 클래스를 만들지 않았다. 시작/끝뿐 아니라 모든 경로 자세의 유한성·기하·순서를 동일 함수로 검증한다.
- 기존 속도 상한 0.01m/s·0.15rad/s, 경로 이탈 0.01m, 반경 0.05~0.30m, 90도 이하 제한, 취소 시 0 출력과 실행 중 Nav2 footprint 충돌 검사를 유지한다.
- harvest_robot.transfer_restore: 윈도우 map 좌표, 정렬 전 map 방향벡터, 같은 정지 시각의 odom 시작 자세, 당시 ArcSpec과 지도/윈도우/odom 세션 식별자를 함께 보관한다. restart 전 odom 기준을 재사용하지 않도록 호출자가 현재 세션을 제공한다.
- 역원호는 기존 arc_path와 RoutePlan을 재사용하며 차체 방향에 pi를 더하지 않는다.
- 재진입은 원호 끝 위치 기준 ArcSpec.endpoint_tolerance(기본 8mm)와 1°를 검사한다. 이 함수는 위치나 방향을 자동으로 고치지 않는다. 최종 윈도우 위치 2cm와 다른 구간 기준이다.
- 기존 arrival.measure_arrival과 Navigator.arrival_validator를 사용한다. 정지 시각의 map TF로 윈도우 위치 2cm·저장 방향 1°를 모두 확인하며, 실패는 Navigator에서 INTERRUPTED가 된다. 부호 있는 방향 오차는 내적/외적의 atan2로 계산한다.

## 변경하지 않은 것

벽 제어/0.02m/s/각도 보정/0.5° 허용오차, 기존 후진 시험 프로필·속도 감시·정확한 셀 충돌검사, Navigator와 공통 위치·정지 모듈, 기존 Spin 어댑터와 인계 FSM. 프로필 수치·footprint를 완화하지 않았다.

## 직접 실행 검증

- Python 172개 통과: 기존 회귀 152개와 복귀 기준 15개, 실제 Navigator에 새 validator를 연결한 대역 검사 5개.
- 기존 후진 제어 명령 4,545조건에서 이전 코드와 차이 1e-15 이내.
- C++ 양방향 60개 정수 RPM 이상 모델 궤적 통과. 위치 8mm·방향 1° 이내 수렴. 28,215 assertion 통과.
- 기존 C++ 곡선 검사 및 벽 861 assertion 통과.
- 역경로에서 기존 footprint를 그대로 사용해 장애물/unknown 셀을 거절하는 검사 포함.
- 프레임·시각·지도·윈도우·odom 세션 불일치, TF 실패, 정지 실패, 위치/방향 오차 초과를 성공으로 처리하지 않는 검사 포함.

## 아직 연결하지 않은 부분

이번 산출물은 복귀의 계산·검증 기반이며 벽에서 윈도우까지 자동 복귀하는 완성본이 아니다.
새 RestoreReference의 런타임 capture/persistence, 벽 이탈 경로 실행과 원호 재진입 보정, 복귀 전용 프로필/전진 감시 설정, 운영 FSM 호출은 아직 미연결이다. 현재 arc_trial은 기존 후진 시험을 그대로 실행한다. return_arc만 실행하면 벽 이탈이나 윈도우 도착을 대신하지 않는다.
곡선 재진입 위치/방향이 허용 범위를 벗어나면 현재는 거절하며, 자동 제자리 회전을 추가하지 않았다.
최종 검사에서 윈도우 오차가 크면 실패한다. 실제 출발 위치와 윈도우 좌표 차이를 없애는 경로는 아직 구현하지 않았다.

## ROS 및 실물 검증

작성 환경에는 ROS가 없어 Nav2 플러그인 전체 빌드/동적 로딩/실물 복귀는 수행하지 못했다. C++ 순수 계산 헤더만 직접 컴파일했다.
전달 run_pc.bash가 PC에서 독립 ROS 빌드·CTest를 수행한다. 결과가 나오기 전 해당 검증을 통과했다고 간주하지 않는다. 이 스크립트는 로봇 접속·Goal·설치본 변경을 하지 않는다.
실물과 시뮬에 공통인 제어기 코드 변경이며, 양쪽 런치 및 운영 설정은 불변이다.
