# 실행 구조 변경 및 실물·시뮬 실행 절차

2026-10-02 사용자 승인: 로봇별 bringup, Isaac 환경, RViz, 관제를 독립 실행 단위로 분리하고 시뮬 전용 전체 실행 launch를 제공한다.

## 1. 실물 담당자가 먼저 확인할 변경

**실물 로봇은 여전히 launch 한 번으로 장치·Nav2·예찰 서버를 실행한다. RViz만 별도 실행으로 분리됐다.** 실물 지도·장치 설정·로봇 업무 코드·ROS 메시지는 이번 분리에서 변경하지 않았다.

| 항목 | 이전 | 변경 후 |
|---|---|---|
| `farm_bringup scout.launch.py` | 장치 실행, 인자로 Nav2/예찰/RViz/Isaac 포함 | 자기 로봇의 장치·Nav2·예찰 서버만 실행 |
| `survey` 기본값 | false | true |
| `navigation` 기본값 | false | true |
| `rviz` 기본값 | true | false. true 명시 시 별도 실행 안내 오류 |
| `start_isaac` 기본값 | true | false. true 명시 시 별도 실행 안내 오류 |
| 실물에서 `survey:=true`로 쓰던 명령 | 장치·주행·예찰 포함 | 같은 역할 유지. `rviz:=true`가 있었다면 제거 |
| `scout_navigation.launch.py` | RViz 기본 포함 | RViz 기본 제외. 기존 저수준 launch의 명시적 rviz=true는 호환용으로 남음 |
| 시뮬 한 번에 실행 | `farm_sim_runtime scout.launch.py` | `farm_sim_runtime all.launch.py` |

`assets_root`와 `isaac_python`은 공통 scout launch에서 호환 인자로만 남으며 실행에 사용하지 않는다. 새 Isaac/all launch로 전달한다. `headless`는 로봇 launch에서는 비전 화면 옵션이다.

공통 변경 파일: `farm_bringup/launch/scout.launch.py`, `scout_navigation.launch.py`, 새 `rviz.launch.py`. 조합 검사는 `tests/test_launch_composition.py`다. 공통 미션·주행 라이브러리·실물 설정은 수정하지 않았다. 이번 승인은 실행 구조 분리 범위이며 이후 공통 업무 코드 변경은 별도 확인 대상이다.

## 2. 실행 단위와 현재 구현 범위

| 단위 | 명령 진입점 | 역할 |
|---|---|---|
| 예찰 실물 | `farm_bringup scout.launch.py mode:=real` | 실물 장치 + AMCL/Nav2 + 공통 예찰 서버 |
| 예찰 시뮬 | `farm_sim_runtime scout.launch.py` | 가상 장치 ROS 어댑터 + AMCL/Nav2 + 같은 예찰 서버 |
| Isaac 환경 | `farm_sim_runtime isaac.launch.py` | Isaac 시작, 농장 USD, 예찰 station 배치, 물리/가상 센서/구동 |
| RViz | `farm_bringup rviz.launch.py` | 모니터링만 실행 |
| 시뮬 전체 | `farm_sim_runtime all.launch.py` | 위 Isaac + 예찰 시뮬 + RViz를 조합 |
| 관제 | 별도 프로그램 | 현재 저장소에는 정식 관제 서버/GUI 없이 시험 요청 클라이언트만 존재 |

수확·운송의 기존 launch는 명시적으로 미구현 오류를 내는 상태를 유지한다. 없는 서버를 성공한 것처럼 실행하지 않는다. 새 전체 launch의 `all`은 현재 구현된 시뮬 구성 전체를 의미하며 3대 로봇 전체 구현을 의미하지 않는다. 현재 Isaac 런타임도 예찰 한 대를 구동한다.

기존 `farm_bringup all.launch.py`는 여전히 미구현이다. 시뮬 전체 실행에는 반드시 **farm_sim_runtime** 패키지를 사용한다.

## 3. 빌드

패치를 프로젝트 루트에 적용한다. 실행 중인 기존 통합 launch를 먼저 종료하고 수정 전 파일은 백업한다.

실물 라즈베리파이:

```bash
cd ~/main/farm_project
bash scripts/build.sh real
source scripts/env.sh real
```

시뮬 PC:

```bash
cd ~/main/farm_project
bash scripts/build.sh sim
source scripts/env.sh sim
```

새 터미널에서는 해당 프로젝트의 `source scripts/env.sh real` 또는 `sim`을 실행한다. 아래 `/실제/.../bin/python`은 각 장비에 설치된 Python 경로로 바꾼다. `vision_python`은 예찰 추론 의존성을 갖춘 환경이어야 한다. 라즈베리파이에서 추론 성능과 패키지 설치까지 검증된 것은 아니다.

## 4. 실물 예찰로봇: 로봇에서 한 번 실행

예찰 라즈베리파이에서:

```bash
cd ~/main/farm_project
source scripts/env.sh real
ros2 launch farm_bringup scout.launch.py \
  mode:=real project_root:="$PWD" \
  vision_python:=/실제/비전환경/bin/python device:=cpu
```

이 명령은 장치·위치추정·주행·예찰 서버를 함께 켠다. 서버가 준비돼도 관제 Goal을 받기 전에는 예찰 미션을 시작하지 않는다. 실물 환경 선택은 `robot/config/environments/scout_real.yaml`이며 `follow_path/RPP`를 사용한다.

주행만 시험하려면 `survey:=false navigation:=true`, 장치만 시험하려면 `survey:=false navigation:=false`를 추가한다. `survey:=true`는 예찰에 필요한 주행 실행도 포함한다.

모니터링 PC에서 별도 실행:

```bash
cd ~/main/farm_project
source scripts/env.sh real
ros2 launch farm_bringup rviz.launch.py \
  mode:=real project_root:="$PWD" \
  environment_config:=robot/config/environments/scout_real.yaml
```

PC에는 프로젝트와 RViz 실행에 필요한 패키지가 있어야 한다. 이 명령은 PC의 하드웨어 드라이버나 예찰 서버를 켜지 않는다. 실물 TF는 해당 robot_id의 네임스페이스 토픽을 구독한다.

## 5. 시뮬 PC: 한 번에 실행

```bash
cd ~/main/farm_project
source scripts/env.sh sim
ros2 launch farm_sim_runtime all.launch.py \
  project_root:="$PWD" \
  isaac_python:=/실제/env_isaaclab/bin/python \
  vision_python:=/실제/비전환경/bin/python device:=0
```

Isaac 한 개, 예찰 장치 어댑터 한 개, 예찰 서버 한 개, Nav2 구성 한 세트, RViz 한 개를 시작한다. station 배치와 실물과 맞춘 FollowPath/RPP 설정을 사용한다. 관제나 예찰 Goal은 자동으로 실행하지 않는다.

구성 요소 선택:

- `rviz:=false`: RViz 제외.
- `isaac:=false`: 별도 터미널에서 이미 실행 중인 Isaac 환경에 연결.
- `scout:=false`: 로봇 bringup 제외.
- `survey:=false navigation:=true`: 예찰 서버 없이 주행 구성만 실행.
- `headless:=true rviz:=false`: Isaac/비전 화면과 RViz 없이 실행.

전체 실행과 별도 실행을 동시에 중복으로 켜지 않는다. all에서 제외한 요소만 별도로 실행한다. 시작 요청은 함께 전달되며 모든 준비가 완료됐다는 뜻은 아니다. Isaac의 station 검증·센서 로그, Nav2 활성 상태, 예찰 서버 준비 상태를 확인한 뒤 관제 요청을 보낸다. 고정 시간 지연으로 준비 완료를 가정하지 않는다.

## 6. 시뮬 PC: 세 터미널 독립 실행

각 터미널에서 프로젝트 루트로 이동하고 `source scripts/env.sh sim`을 실행한다.

터미널 1 — Isaac 환경만:

```bash
ros2 launch farm_sim_runtime isaac.launch.py \
  project_root:="$PWD" isaac_python:=/실제/env_isaaclab/bin/python
```

터미널 2 — 예찰로봇만:

```bash
ros2 launch farm_sim_runtime scout.launch.py \
  project_root:="$PWD" \
  vision_python:=/실제/비전환경/bin/python device:=0
```

터미널 3 — RViz만:

```bash
ros2 launch farm_bringup rviz.launch.py \
  mode:=sim project_root:="$PWD" \
  environment_config:=sim/ros_ws/src/farm_sim_config/config/scout_runtime.yaml
```

대체 환경을 지정할 때는 **세 명령 모두 같은 environment_config**를 사용한다. RViz도 `rviz_config`로 별도 화면 설정을 선택할 수 있다. 시뮬 환경/화면 설정은 sim 내부 파일이어야 한다.

Isaac에는 ROS 장치 어댑터가 포함되지 않는다. 어댑터는 터미널 2에서 실행한다. 가상 센서·물리 구동은 터미널 1, 그 데이터를 ROS 토픽/명령에 연결하는 어댑터는 터미널 2의 책임이다. 현재 연결은 같은 PC의 로컬 통신이며 시뮬 어댑터를 다른 PC에서 실행하는 구조까지 구현한 것은 아니다.

## 7. 관제/시험 요청

정식 관제 프로그램은 별도 장비/터미널에서 실행한다. 현재 코드에 정식 관제 시작 명령이 없으므로 전체 launch에 가상의 관제 프로세스를 추가하지 않았다.

현재 시뮬 예찰만 시험할 때는 모든 구성 준비 후 네 번째 터미널에서 기존 시험 클라이언트를 사용한다.

```bash
cd ~/main/farm_project
source scripts/env.sh sim
python control/scripts/send_scout_area.py \
  --survey-config sim/ros_ws/src/farm_sim_config/config/scout_survey.json \
  --section SEC01
```

이는 실제 예찰 작업을 요청하는 명령이다. GUI 관제나 수확 연계 관제가 아니다. 구역을 생략하면 구형 기본 이름 BED_01이 선택되므로 현재 시뮬에서는 반드시 `--section SEC01` 등의 구역을 지정한다. 기존 클라이언트 로그 위치는 `runs/control/`이며 이번 launch 분리에서는 변경하지 않았다.

## 8. 종료·재시작과 향후 다중 로봇

- 독립 실행에서 RViz를 닫아도 로봇·Isaac은 유지된다.
- 독립 실행에서 로봇 bringup을 닫아도 Isaac 프로세스는 유지된다. 현재 가상 구동기의 명령 timeout이 적용된다.
- Isaac을 재시작하면 로봇이 station으로 재배치되고 시뮬 시간이 초기화된다. Nav2·예찰도 재시작해 시간/위치 상태를 맞춘다.
- all.launch.py를 Ctrl+C로 종료하면 그 launch가 시작한 자식 프로세스를 함께 종료한다. Isaac 종료 또는 장치 어댑터 종료도 조합 실행 전체의 종료로 연결된다. RViz를 닫는 것만으로는 전체를 종료하지 않는다.
- 독립 실행의 한 프로세스 종료가 별도 터미널의 프로세스를 자동 종료시키지는 않는다. 작업 중 통신 단절/복구 정책을 완성했다는 뜻은 아니다.

향후 수확·운송은 각 장비에서 자기 launch만 실행한다. 시뮬에서는 Isaac 환경 실행을 하나로 유지하고 각 로봇 bringup을 상위 all에 추가한다. 먼저 다중 로봇 Isaac 실행부, 로봇별 네임스페이스·TF·가상 연결 포트·카메라 공유 메모리·주행/업무 서버를 구현해야 한다.

현재 RViz는 한 예찰로봇용이다. 여러 실물 로봇은 동일 이름의 map/odom TF를 각자 네임스페이스에서 쓸 수 있으므로 다중 표시에는 공통 지도 등록/프레임 식별과 화면 설정이 추가로 필요하다. 현재 표시 항목은 지도·LiDAR·TF·footprint·그래프 프리뷰·Nav2 plan이다. FollowPath 전달 경로와 실제 누적 이동 궤적을 각각 표시하는 기능은 이번 launch 분리 범위에 포함하지 않았다. 저장된 지도+AMCL을 사용하며 온라인 SLAM 실행은 아니다.

## 9. 검증과 원복

`python tests/test_launch_composition.py`: ROS 실행 객체를 기록 객체로 대체한 9개 구성 시험. 전체 실행의 단일 Isaac/어댑터/서버/RViz, 분리 실행, 실물 하드웨어 포함 경계, 옵션, 잘못된 구형 옵션/환경 거절을 확인했다. 실제 ROS 프로세스 실행은 아니다.

기존 station 시험 6개와 경로 371개 검사는 앞선 패치에서 통과했으며 해당 런타임/데이터는 이번에 변경하지 않았다. 이번 변경의 실제 ROS·Isaac·라즈베리파이 실행 및 colcon 빌드는 수행하지 못했다.

원복은 적용 전 공통/시뮬 launch 백업을 함께 복원한다. 새 isaac/all/rviz launch와 구성 시험 파일도 함께 정리한다. 공통·시뮬 일부만 되돌리면 중복 실행이나 인자 불일치가 생길 수 있다. 변경 이력은 `sim/docs/CHANGELOG.md`의 LAUNCH-SPLIT-20261002-006에 기록했다.
