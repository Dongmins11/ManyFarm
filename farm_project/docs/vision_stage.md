# v0.4.2 — B 관측 영역 크롭·패딩 + YOLO 분할

## 이번 단계

Isaac 카메라 → 기존 RGB-D 공유메모리 → B 관측 범위 계산 → 크롭 → 비율 유지 리사이즈/패딩(640×640) → YOLO → 화면 표시.

추론 코드는 `robot/ros_ws/src/farm_vision`에 둡니다. 실물 카메라도 같은 공유메모리 형식으로 제공하면 같은 코드를 사용합니다.
Isaac/ROS와 별도 Python 프로세스이며, 이번 단계는 수동으로 추론 프로그램을 실행합니다.
노이즈·블러·깊이 랜덤오차·깊이 양자화를 추가하지 않습니다.

## 1. 적용

압축 안 `farm_project` 내용물을 기존 `~/robotarm/farm_project`에 병합합니다.
기존 bringup·Nav2·장치 연결 파일은 덮어쓰지 않습니다.
제공한 모델도 아래 위치에 포함했습니다.

```text
robot/models/scout/model_yolo11_seg_ver1.0.pt
```

이번 실행 스크립트는 소스 폴더를 직접 읽으므로 **colcon 재빌드는 필요 없습니다.**

## 2. 카메라 공급

기존 Isaac Sim bringup을 켜둡니다. 로봇을 베드가 보이는 위치에 정지시키고 주행 액션은 취소합니다.
카메라가 베드를 정면으로 보도록 로봇 방향을 맞추세요. 이동/회전 중의 화면도 표시할 수 있으나 B 정지 관측의 기하 조건을 만족한다고 간주하지 않습니다.

기존 주행 bringup이 켜져 있으면 추가로 실행하지 않습니다. 꺼져 있다면 robot_venv에서:

```bash
cd ~/robotarm/farm_project
source scripts/env.sh sim
ros2 launch farm_bringup scout.launch.py mode:=sim \
  isaac_python:=/home/ysy/isaac/env_isaaclab/bin/python \
  assets_root:="$PWD/sim/assets"
```

위 명령은 장치만 실행합니다. Nav2가 필요하면 기존 `navigation:=true rviz:=true` 명령을 사용하세요.

## 3. 추론 환경

별도 터미널에서 기존 **pytorch 등 YOLO를 실행하던 가상환경**을 활성화합니다.
가상환경의 실제 설치 경로는 사용자 PC 설정을 사용하세요. 이 추론 터미널에는 ROS 환경을 source할 필요가 없습니다.

```bash
cd ~/robotarm/farm_project
python -c 'import torch, ultralytics, cv2; print("Ultralytics", ultralytics.__version__, "CUDA", torch.cuda.is_available())'
```

모듈이 없거나 모델 로딩 시 버전 오류가 생기면 이 추론 환경에서만 설치/업데이트합니다.

```bash
python -m pip install -r robot/requirements-vision.txt
```

모델 체크포인트에 기록된 Ultralytics 버전은 **8.4.156**, 입력 크기는 **640**, 클래스는 **0: Red / 1: Yellow**입니다.
Green 클래스는 포함돼 있지 않습니다. GPU 실행에는 CUDA를 사용할 수 있는 PyTorch가 필요합니다.

## 4. 먼저 크롭 화면 확인

```bash
python scripts/run_scout_vision.py --preview-only
```

- 왼쪽: 원본 영상과 하늘색 B 관측 영역.
- 오른쪽: 그 영역을 잘라 비율을 유지하고 640×640으로 패딩한 영상.
- Q 또는 ESC: 종료.

오른쪽 제목에 `YOLO OFF`가 표시됩니다. 이 단계는 모델을 로드하지 않습니다. OpenCV와 NumPy만 필요합니다.
높이 범위가 화면 밖이면 `ROI ERROR`를 표시하고 추론하지 않습니다. 임의로 잘라서 정상인 것처럼 진행하지 않습니다.

## 5. YOLO 실행

크롭 화면이 맞으면 미리보기 프로그램을 종료하고 다음을 실행합니다.

```bash
python scripts/run_scout_vision.py --device 0
```

오른쪽에 Red/Yellow 마스크와 점수, 처리 FPS, 추론 시간, 공유메모리 기록 이후 결과까지의 시간이 표시됩니다.
FPS 15는 처리 상한 목표입니다. 실제 속도 보장은 아니며 새 프레임만 처리하고 대기 프레임을 쌓지 않습니다.
GPU를 사용할 수 없을 때 기능만 느리게 확인하려면 `--device cpu`를 사용합니다.
창 없는 실행은 `--headless`, 일정 프레임 후 종료는 `--max-frames 30`입니다.

Q/ESC 또는 Ctrl+C로 추론만 종료합니다. 로봇 이동 명령은 보내지 않습니다.
카메라가 멈추거나 오래된 결과라면 WAITING/STALE을 표시합니다.

## B를 어떻게 적용했는가

제공된 B 코드 `bsim/viewpoint_optimization.py`와 기획 문서는 다음을 사용합니다.

1. 영상 좌우 각 5%를 제외합니다.
2. 관측할 높이의 위·아래 경계에서 시선과 베드 기준 평면의 교점을 계산합니다.
3. 두 높이 모두 확보되는 공통 가로 범위를 사용합니다.

이 규칙을 현재 Isaac 카메라의 **프레임별 K와 광학 좌표계 자세**로 계산합니다.
B의 PyBullet 좌표축 및 424×240 카메라 보정값을 그대로 가져오지 않습니다.
기존 B는 모의 검출 마스크를 사용했으므로, 실제 영상의 크롭·640 패딩·YOLO 연결은 이번에 새로 작성했습니다.
카메라 기울기로 사각형이 사다리꼴이 되면 공통 영역 밖 픽셀도 패딩 색으로 가립니다.
YOLO 결과 마스크에서 패딩 영역을 제외하며, 검출 위치를 원본 픽셀로 역변환할 수 있도록 변환값을 함께 보존합니다.

### 현재 가정 — 반드시 화면으로 확인

설정: `robot/config/vision/scout.json`

```json
"preprocess": {
  "edge_fraction": 0.05,
  "camera_to_bed_plane_m": 1.14,
  "height_band_m": [0.603, 1.053],
  "vertical_margin_fraction": 0.10,
  "input_size": 640,
  "pad_value": 114
}
```

- `height_band_m`: 제공된 수확로봇 모델의 `top_deck` 기준 높이 0.703m에 −0.10/+0.35m를 적용한 **0.603~1.053m**입니다. 상판 prim의 기준 위치이며, 팔 base_link 높이 0.713m와 구분합니다. 농장 배치에 추가 Z 이동/스케일이 없고 지면 원점이 같다는 조건입니다. 이 높이 구간만으로 팔의 실제 도달 가능성이 보장되지는 않습니다.
- `camera_to_bed_plane_m`: 사용자 제공 카메라~베드 엣지 거리 1.14m를 설계 평면 거리로 사용합니다. 실제 열매 깊이가 전부 같은 평면에 있다는 뜻은 아닙니다.
- 설계 평면은 카메라의 수평 시선에 수직인 수직면입니다. 정지하여 베드를 정면으로 보는 경우를 가정합니다. map상의 베드 평면이나 현재 로봇과 베드의 거리를 실시간 추정한 값이 아닙니다.
- `T_odom_camera_optical`의 높이 기준은 기존 sim 연결부와 같은 지면 기준입니다. 다른 바닥 높이의 실물 환경에서는 원점/높이를 맞춰야 합니다.
- 크롭은 한 번의 관측에서 보는 공통 영역입니다. 수확로봇 한 번의 작업 윈도우 폭으로 쪼개는 과정은 다음 단계입니다.

화면에 열매가 있는데 오른쪽에 없다면 먼저 왼쪽 크롭 영역과 높이 범위를 확인하세요.
크롭 설정 변경 후 추론 프로그램만 다시 실행하면 됩니다.

## S 키: 현재 프레임 저장

`captures/scout_vision`에 같은 시각의 파일들을 저장합니다.

- `_rgb.png`: 원본 RGB.
- `_input.png`: 실제 YOLO 입력 640×640.
- `_result.png`: 입력 위 검출 결과.
- `_depth.npy`: 원본과 정렬된 광학축 깊이(m), 유효하지 않은 값은 NaN.
- `_masks.npz`: 각 검출의 원본 영상 크기 마스크.
- `.json`: 촬영 시각·K·카메라 자세·크롭/패딩 변환·클래스/점수·시간 정보.

저장은 S 키를 눌렀을 때만 합니다. 미리보기 전용에서는 검출 목록이 비어 있습니다.
표시한 마스크 번호는 영속 과실 ID가 아닙니다. 프레임 간 중복 제거는 아직 하지 않습니다.

## 이후 연결할 부분

정차 관측점 계산/이동 → 안정화 후 새 프레임 검출 → 마스크 내부의 유효 깊이로 표면 좌표 계산 → 촬영 시각의 map 변환 → 중복 과실 연결 → 수확 윈도우 구성 → ScoutArea feedback/result.
현재는 검출/전처리 검증 단계이며, 관제 액션·지도상 열매 좌표·예찰 성공 결과를 발행하지 않습니다.

## 검증 범위

현재 환경에서 크롭 기하, 높이 범위 오류 처리, RGB/BGR 변환, 패딩/역변환, 마스크 복원,
화면 구성 및 저장, 별도 프로세스 간 실제 공유메모리 읽기와 전처리까지 점검했습니다.
모델의 메타데이터에서 분할 모델/클래스/입력 크기를 확인했습니다.
여기에는 PyTorch·Ultralytics·GPU·Isaac 실행 환경이 없어 **첨부 모델의 실제 추론과 농장 영상 검출 정확도, GPU FPS는 실행 검증하지 못했습니다.**

Ultralytics 입력/마스크 규격 참고: https://docs.ultralytics.com/modes/predict/

## v0.4.1 보정 범위

높이 설정과 미리보기 제목을 수정했습니다. 카메라 높이/거리 설정, 물리 시뮬레이션, 영상 흔들림은 수정하지 않았습니다.
이 크롭은 지정한 거리의 평면에 높이 범위를 투영합니다. 실제 깊이가 다른 열매의 높이는 깊이값과 카메라 자세로 별도 판정해야 합니다.

## v0.4.2 — 크롭 상하 여유

`vertical_margin_fraction: 0.10`으로 원래 투영된 크롭 높이의 10%만큼 위와 아래에 각각 원본 영상 영역을 추가합니다. 예를 들어 기존 높이가 140px이면 위 14px, 아래 14px를 추가합니다. 원본 화면을 벗어나는 부분은 화면 경계까지만 포함합니다.
추가 영역은 YOLO의 유효 마스크에도 포함하며, 왼쪽 하늘색 선은 확장된 실제 크롭 영역입니다. 기존 물리 높이 기준 0.603~1.053m는 유지합니다. 검출 여유 영역이 팔의 작업 범위를 확장하는 것은 아닙니다.
회색 640×640 패딩과 별개이며, 0.0이면 기존 크롭입니다. 설정 변경 후 추론 프로그램만 재시작합니다. colcon 빌드는 필요 없습니다.
