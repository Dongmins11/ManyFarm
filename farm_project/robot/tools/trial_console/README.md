1. 상태 새로 조회: 실행 프로세스·로봇 상태·odom 정지·더미·관제 차단 상태를 확인한다.
2. 재시작 시 수확 프로세스 종료 → 잔존 없음 확인 → 실제 스테이션 재배치 → 상태 조회 → 스테이션 확인 체크 → 복구 기록. 원본과 이전 결과는 백업한다.
3. 사용자 터미널에서 PC 더미/브리지와 로봇 laun을 켠다. IDLE·정지 및 실제 스테이션 위치 확인 후 vinit, 이어 zen/dzen.
4. 더미 준비 확인. 복구 필요 상태에서만 더미 복구 후 다시 준비 확인한다. 개수 변경은 유휴 시 가능하며 실제 팔의 수량을 뜻하지 않는다.
5. 웹 작업 직전에 마지막 수확 1회 반복 허용. 300초·1회·같은 요청 내용만 허용하며 실행 중 중복은 차단한다. 허용권은 더미 재시작 시 사라진다.
6. 관제 미확정 인계/대기열 정리는 기존 관제에서 사용자가 수행한다. 주행·인계 버튼도 기존 관제를 사용한다.

표시된 정지는 표본 구간의 결과이며 위치 정합 검증을 대신하지 않는다. 오류 응답을 성공으로 처리하거나 자동 재시도하지 않는다.

## 실제 Jetson 팔 통신 시험 — 2026-10-27

웹 상단의 **이동 없는 팔 시험**을 사용한다. 기존 더미/복구 기능은 아래에 그대로 있다.
코드 갱신 뒤에는 기존 PC 미니관제 터미널만 사용자가 종료하고 위 app.py 명령으로 다시 실행한다.
8091의 서버를 중복 기동하지 않는다. 브라우저도 새로고침한다.

1. 로봇의 새 laun/zen/dzen을 사용자 터미널에서 실행한 상태에서 **팔 시험 연결**을 누른다.
   PC→SSH→Pinky 시험 클라이언트→기존 팔 전용 Zenoh→Jetson 경로다. Jetson SSH는 사용하지 않는다.
   연결은 RuntimeStatus/ControlState/RobotStatus/AMCL 구독과 Action/Service 클라이언트만 생성한다.
2. RuntimeStatus의 마지막 수신·sequence·ready/phase/error, ControlState 원문, 서버 발견 상태를 확인한다.
   서버 발견, 콘솔 접수, ROS 요청 송신, Jetson Goal 수락, Feedback, terminal Result는 서로 다르게 표시한다.
3. 수확은 원본 HarvestTask Goal JSON을 붙여넣거나 **관측 자세로 수확 요청 초안**을 만든 뒤 내용을 확인하여 전송한다.
   초안은 관측한 AMCL 자세/RobotStatus robot/map 값과 사용자가 입력한 expected_count를 사용한다.
   시험 task/window ID는 새 UUID이며 초안 작성만으로 전송하지 않는다. 오래된 관측은 현재 자세로 가정하지 않는다.
4. 수확 요청은 /harvest_01/arm/harvest_task에 직접 보낸다. 기존 차체 미션·관제 대기열을 실행하지 않는다.
   이 시험의 결과를 Pinky의 운영 적재량에 자동 반영하지 않으므로 실제 수량은 별도로 대조한다.
5. 실행 중에도 **내 Goal 취소 요청**, **stop 정지 요청**을 보낼 수 있다. 취소 접수만으로 완료라고 표시하지 않는다.
   이 콘솔이 소유한 Goal만 Action 취소한다. stop은 Jetson 서비스 요청이며 실제 정지 응답을 확인해야 한다.
6. prepare, Discharge, GetOperation, Recover도 지원한다. 현재 Jetson 회신상 Discharge는 거절 상태다.
   Recover에는 실제 장치/수량 대조 확인과 DEVICE_AND_LOAD_RECONCILED를 사용한다. 저널 삭제·재실행 없음.
7. 유휴 연결 종료는 미완료 요청이 있으면 거절한다. **시험 클라이언트 정리**는 자신이 생성한 SSH/ROS 관찰 연결을 닫는다.
   이것은 팔 정지가 아니다. 끊긴 요청의 종료 여부는 GetOperation으로 대조하며 같은 Goal을 자동 재전송하지 않는다.

회신의 수확 준비 기준(depth_v11/ready/TTL2.5초 및 boot/sequence)은 기존 jetson_state를 재사용한다.
설정의 준비10초/응답5초/실행1260초/취소20초와 서비스 응답20초를 사용한다.
실행 중 ready=false는 정상 진행을 차단하지 않는다. 박스·팔 자세에 추가 준비 조건을 붙이지 않는다.
팔 시험 영역은 차체 이동/초기위치/ControlState를 발행하지 않는다. 별도 스테이션 복귀 영역은 ReturnToStation Action만 요청한다. V3에서는 비상정지 필드가 삭제되었다.
PC와 로봇 격리 설치본의 V3 재빌드 완료. 사용자 기동·실제 Jetson 왕복 검증은 남았다.

### 구성·기록·검증

- app.py: HTTP 세션/CSRF 및 기존 작업 큐. 팔 통신은 별도 /api/arm 경로라 긴 요청 중 취소/상태 조회가 가능하다.

초안용 AMCL은 transient-local로 마지막 보존 표본도 수신한다. 초안 안내의 원본 측정 시각과 실제 자세를 확인한다.

진행 수량은 해당 요청 Feedback, 최종 수량은 Result 기준이다. ready=true만으로 완료를 표시하지 않는다.
연결이 끊기면 현재 상태 미확인으로 바뀌며 마지막 결과는 남는다.

## 스테이션 복귀 버튼 — 2026-10-29

PC 미니관제 서버를 사용자 터미널에서 재시작하고 브라우저를 새로고침한다. 로봇 laun 재빌드는 필요 없다.
상단 스테이션 복귀 영역에서 로봇 시험 연결 → 후진 이동 확인 → **18번으로 복귀** 순서로 요청한다.
기존 팔 시험과 동일 SSH 클라이언트를 재사용하므로 팔 연결이 이미 있으면 새로 중복 연결하지 않는다.
팔 ready/RuntimeStatus 수신은 복귀 송신 조건이 아니다. 로봇의 팔 검사 생략 여부는 로봇 프로필을 따른다.

목표는 config.json의 station_return_config가 가리키는 YAML에서 읽으며, 현재 STATION_HARVEST_01/노드18이다.
map_id는 station_return_map_id=farm_map_v1, 새 task_id와 timestamp는 서버에서 생성한다.
브라우저로 좌표나 목표를 덮어쓰지 않는다. 요청은 /harvest_01/return_to_station으로 보내고 서버가 현재 위치에서 경로를 계산한다.
14번은 시험 출발점이지 버튼이 보내는 초기위치가 아니다. dinit·프로세스 기동은 자동으로 수행하지 않는다.
콘솔 접수/Goal 수락/Feedback/Result를 구분하며 SUCCESS+docked=false를 도착 성공으로 표시한다.
**내 복귀 요청 취소**는 이 연결이 보낸 활성 복귀 Goal만 취소한다. 취소 접수는 정지 완료를 뜻하지 않는다.
연결 단절·결과 미확인에서는 자동 재전송하지 않는다. 일반 팔 stop은 차체 정지 버튼이 아니다.

검증: PC 단위10개+domain231/loopback 가짜 서버 ROS7개=17개 통과.
팔 ready=false에서 복귀 송신·Feedback·SUCCESS/docked=false, 취소·거절을 확인했다.
JS 문법·기존 팔 요약·복귀 요약/초안 UI 검사 통과. 실물 웹 버튼 왕복은 미시험.

### 팔 없이 시험 위치로 이동 (PC 구현, 로봇 적용 별도)

`팔 없이 시험 위치로 이동`의 목표는 기존 `robot/tools/terminal/dinit.json`과 실물 그래프에서 읽는다(현재14번, 12번을 등지는 방향). 초기위치를 덮어쓰지 않는다. `로봇 시험 연결` 후 실제 팔 접힘·정지/주행 공간 확인란을 체크하고 이동 버튼을 누른다. 요청 수락과 최종 완료는 별도 표시하며 `내 이동 요청 취소`는 이 연결의 이동 Goal만 취소한다.
실물 시험 프로필의 `/harvest_01/trial/navigate_to_pose`는 기존 진입/작업선 주행을 실행하고 팔 수확은 호출하지 않는다. 표준 Action 형식만 NavigateToPose이며 내부 경로는 기존 RouteToPose/FollowPath다. 기존 시험 프로필의 팔 상태 수신 생략 정책을 사용한다. 이전 팔 오류나 blocked를 강제 해제하는 IDLE 버튼은 아니다.
새 로봇 코드·시험 프로필을 별도로 배포/빌드하고 사용자가 재기동해야 서버가 발견된다. PC 미니관제도 사용자가 재시작/새로고침한다. 이번 구현 작업에서는 운영 프로세스를 변경하지 않았다.
