2026-10-08 · 수확로봇 Vic Pinky / A벽 · 실제 출력 원본 패턴 기반

**tag36h11 / 실물 ID 100~106 · 8m 확장 ID 107~114 / 검은 태그 50mm / 중심 높이 264mm / 종이 사이 빈 공간 500mm**

**첫 번째 태그는 화단 시작점에 부착한다.**

ID100의 **D쪽 종이 끝 = 화단 시작점 s=0mm**. 따라서 검은 태그 중심은 시작점에서 32mm, 검은 테두리의 시작쪽 끝은 7mm 들어간 위치다. 검은 중심을 시작점에 놓는 배치가 아니다. 이후 ID101 중심은 596mm, ID102 중심은 1160mm…가 된다.

## 1. 배치 규격

- 종이 크기 64 × 69mm. 검은 정사각형 50 × 50mm. 좌우·위쪽 흰 여백 7mm, 아래쪽 12mm에는 ID 표기가 들어간다.

- 태그 중심 높이는 바닥에서 264mm. 검은 사각형 하단 239mm, 상단 289mm. 종이 하단 227mm, 상단 296mm.

- 종이 사이 **빈 공간 500mm**이므로 중심 간격은 **564mm**. 중심 간격 500mm로 배치하면 실제 설치와 달라진다.

- ID100의 D쪽 종이 끝을 화단 시작점 s=0에 맞춘다. 번호가 증가하는 방향을 s 양의 방향으로 정의한다. ID 표기를 아래로 두고, 태그 정면은 통로·카메라 쪽을 향한다.

- 화단 길이 약 3500mm 기준, 마지막 종이 끝은 3448mm. 남는 길이 52mm. 이는 설치 기준값이며 각 태그를 독립 측량한 값은 아니다.

## 3. 시뮬레이터에 이미지 적용

각 PNG는 **1280 × 1380px**이며 전체 이미지를 **폭 0.064m × 높이 0.069m** 평면에 적용한다. 검은 영역은 1000 × 1000px, 실제 길이 0.050m다. 평면 중심의 높이는 **0.2615m**여야 검은 태그 중심이 0.264m가 된다. 종이 중심과 태그 중심을 혼동하지 않는다. PNG의 DPI보다 시뮬레이터의 물리 평면 크기 설정이 중요하다.

원본 PDF의 셀 패턴과 회전 방향을 그대로 추출했다. 재단선·정렬 삼각형은 텍스처에서 제외했다. 좌우 반전, 임의 회전, 늘이기를 하지 않는다. 검출기 tag size는 종이 폭이 아닌 **0.050m**로 지정한다.

## 4. 전달받은 farm_map.yaml 확인

| 항목 | 값 |
| --- | --- |
| 지도 이미지 | farm_map.png (아직 미전달) |
| 해상도 | 0.05 m/cell |
| 원점 x, y, yaw | -8.0750003815, 15.0250001907, 0 |
| negate / occupied / free | 0 / 0.65 / 0.196 |

지도 해상도는 장애물 지도 셀 크기다. 태그 텍스처는 별도 3D 물체로 넣으며 5cm 셀 하나로 태그 이미지를 표현하는 방식이 아니다. 이 YAML만으로는 이미지 크기, A벽 위치, 실제 월드와 map의 관계를 알 수 없다. 기존 실물 지도 태그 좌표는 그대로 이식하지 않았다.

**이번 전달 범위**

실물 설치 규격 및 그 규격을 8m로 연장한 배치안만 제공한다. URDF·지도·기존 주행 설정은 변경하지 않는다. 실물과 URDF를 맞추는 작업은 담당 측에서 진행한다. 전달받은 YAML은 참고용 그대로 포함한다. 지도 좌표를 새로 확정하거나 기존 실물 map 좌표를 이식하지 않았다.

태그가 붙는 직선 구간의 유효 길이가 실제로 8000mm이고 시작 종이 끝을 그 구간 시작에 맞출 수 있다면 15개 배치가 성립한다. 끝단 여유가 40mm뿐이므로 문·기둥 등 설치 불가 구간이 있으면 최종 부착 전에 간섭 여부만 확인하면 된다.

## 5. Vic Pinky 카메라 장착 기준

**왼쪽 차체 옆면에 거의 맞닿게 고정하고, 왼쪽 화단 벽을 바라보도록 설치했다.** 카메라는 PCWEB400 USB 웹캠이다. 아래 x/y/z는 로봇 전방/왼쪽/위쪽이며, 기존 계산은 구동바퀴 축 중간점의 바닥 투영점을 base_footprint 기준으로 가정했다. URDF 파일의 실제 원점·링크 정의와 일치하는지는 본 자료에서 검증하지 않았다.

| 구분 | 수치 | 의미·근거 |
| --- | --- | --- |
| 기준면까지 횡방향 거리 | 260mm | 구동바퀴 축 중간 기준 → 측면 측정 기준면, 사용자 실측 |
| 앞/뒤 기준면→벽 | 각 172mm | 거리계 뒤끝 기준 실측. 두 측정 지점 간격 530mm |
| 104 중심 높이 | 264mm | 바닥 기준 실측. 카메라 광학 중심의 직접 정밀 실측값과는 구분 |
| 104 전후 정렬 | 축 위치와 약 0mm | 사용자 추정 오차 약 1~2mm |
| 카메라 광학 중심 x | −4.338mm | 기준 원점보다 약 4.3mm 뒤쪽 — 추정값 |
| 카메라 광학 중심 y | +250.465mm | 기준 원점보다 약 250.5mm 왼쪽 — 추정값 |
| 카메라 광학 중심 z | +261.423mm | 바닥에서 약 261.4mm — 추정값 |

광학 중심 수치는 정지 상태의 ID104 관측과 위 실측값을 결합한 장착 추정 결과다. 소수점 자릿수가 실제 장착 정확도를 의미하지 않는다. 벽 수직·태그 직립·로봇 수평 가정이 포함된다. 단순 배치 설명으로는 **축 중심 근처, 왼쪽 약 250mm, 높이 약 261mm, 왼쪽 벽을 향함**이다.

기존 추정 **base_footprint → apriltag_camera_optical_frame** 회전 쿼터니언(x,y,z,w)은 `[-0.69205081, 0.00823666, 0.00411433, 0.72179007]`. 광학축 +Z가 보는 방향이며 base 기준 약 `[0.006196, 0.999099, 0.041996]`로, 거의 왼쪽을 향한다. 이는 카메라 본체 링크가 아닌 **optical frame** 변환이므로 URDF에 광학축 회전이 이미 있으면 중복 적용하면 안 된다. 수치 제공만 하며 URDF는 변경하지 않았다.

렌즈에서 벽까지 거리는 로봇 배치에 따라 달라진다. 이 정지 실측 자세에서는 `260 + 172 − 250.465 ≈ 181.5mm`이고, 기존 주행 경로 설계의 목표 약 204.5mm와는 다른 값이다.

### 카메라 영상 조건

1280×720, MJPG, 카메라 요청 30fps. ROS 영상 발행 상한 10Hz(관측 약 8~9Hz), 비교 주행 노출 manual 2ms. 보정 내부 파라미터는 fx=1049.6865, fy=1049.6045, cx=631.4065, cy=371.5007px. 전체 K/D 및 장착 4×4 행렬을 camera_mount_reference.json에 포함했다. 이 수치는 재현용 참고이며 시뮬레이션 설정에 자동 적용하지 않았다.

## 6. 실측·시험 조건을 혼동하지 않기

- 앞·뒤 172mm, 두 측정 지점 사이 530mm는 정지한 로봇의 기준면과 벽을 측정한 값이다. 태그 간격이나 목표 주행 간격이 아니다.

- 기존 route 설계의 렌즈~벽 목표 거리는 약 204.5mm였으며 설계·장착 모델 기반이다. 최초 논의한 250mm를 최종 주행값으로 사용하지 않는다. 새 시뮬레이션 경로에 자동 적용되는 값도 아니다.

- 실물 보정 시험 구간은 Route 10→13, 태그 평가 구간은 11→13이었다. 7개 설치가 7개 모두 통과·검출을 의미하지 않는다.

- 시야 ROI는 배치 치수가 아니며 60%는 초기 임시값이었다. 담당자는 배치 검증 뒤 평가 조건을 따로 맞춘다.
